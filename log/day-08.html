Day08 · 通用执行内核与 native 评测

本页目录

2026-11-11 至 11-12，Hearth 把 native 从精简编码循环升级为通用执行内核，并用独立评测仓库对 30 个离线 case 做了第一轮完整测量。11-11 的 16 个计划项涉及 81 个文件（+7,156/−850）；11-12 在基线 4617419 之后又完成 91 个提交（19 个文件，+2,358/−17），主要用于评测结果归一化和最终修复。最终修复提交为 eb32ad5，文档随后补齐。

通用执行内核 ​

方向结果
文件与命令新增 glob/grep、文档读取、XLSX/CSV/DOCX 生成；edit_file 可预览差异，补丁先校验全部目标再原子写入，支持 move 和真实删除；Shell 完整输出写入任务内 .hearth/shell 日志，只回填尾部，超时会杀死整个进程树
上下文与稳定性模型窗口默认 128K、最大输出默认 8K；按窗口预留 max(16K, 15%) 并保留约 20K 近期 Token，只在完整回合边界压缩，绝不拆散工具调用与结果；压缩后写检查点；纯文本不再算完成，连续未调用 finish_task 会失败；429/5xx/网络错误最多重试两次，相同工具参数循环会被提示并停止重复执行
技能与委派提示词只注入技能索引，load_skill 校验内容哈希、任务权限和审计后返回正文，read_skill_resource 限制在技能包内；delegate_task 使用新上下文，只允许只读或隔离写，单层串行、每父任务最多两个、禁止 MCP 和自动合并，子代理用量计入父任务
项目与 Worktree新增本地 Git 项目注册、路径与 Git 根校验、分支校验和设置页项目列表；项目任务使用 hearth/<task-id> 独立 Worktree，恢复时复用，成功或失败都保留，只有用户手动清理且工作区干净时才删除；GitHub 任务继续走 Codex
本地 MCP仅支持 stdio，服务器命令、参数和加密环境值由设置页管理；启动探测、工具发现、超时和崩溃隔离形成闭环；工具统一命名为 mcp__<serverId>__<toolName>，调用前用 ajv 校验 JSON Schema，结果限长，输出、错误和 stderr 均脱敏，并检测跨服务器及内置工具名称冲突
搜索与审批搜索默认关闭，仅支持 Tavily 与 SearXNG；公共网络能力仍受 DNS、重定向和私网地址拦截，每次抓取仍审批；每次 MCP 调用进入现有逐次工具审批，绑定服务器、工具名和参数摘要，只有完全权限模式自动放行并记录审计

这一轮的边界同样明确：没有远程 MCP、OAuth、浏览器自动化搜索、图片/扫描件视觉理解、PPTX、LSP、格式化器、Shell 后台会话或自动 cherry-pick。工具数量增加不等于执行质量已经经过真实用户验收。

Native 30 题评测 ​

评测使用 hearthproject/hearth-eval 的 30 个离线 case（8 个任务族均匀分布），仅运行 native 执行器，重复 1 次，自动评分和自动重试开启，并发 4。

阶段结果
初始基线 EXP-20261111051349-b71b800/30 通过；评测桥接的任务带有空 permissions.tools，工具全部被过滤
第一次完整 30 题 EXP-20261111141538-01150615/30 通过（50%），平均分 81.33
最好完整 30 题 EXP-20261111145332-7a95ea18/30 通过（60%），平均分 88.89
最近完整 30 题 EXP-20261112003215-b1172b12/30 通过（40%），平均分 73.33
累计定向确认19/30 个 case 曾达到 100 分

最近完整实验受到 provider 慢响应、评分 JSON 截断和任务超时影响，而且早于最后四个归一化修复，因此不能直接等同于最终代码能力。累计 19/30 来自不同轮次和定向重跑，不是一次连续实验。最终提交 eb32ad5 还没有做不中断的完整 30 题复测；这是一条必须保留的验证边界。

修复集中在三类：评测桥接与运行时（恢复默认工具白名单、任务级审批模式、禁止评测任务移交、代码任务 Shell 权限、瞬态重试、机器可读 facts 门禁）；结果契约与归一化（阻塞计数、冲突标记、备用时间槽、下一页查询、扁平 metadata、必填字段、桌面移动/删除计数等）；Prompt 契约（合同测试、直接交付、恢复最终状态、回滚章节、回归检查等）。

验证 ​

2026-11-12 在当前分支运行：

bash
npm test              # 100 个测试文件、725 个测试全部通过

npm run build         # Web 控制面

vitest.config.ts 将单个测试超时提高到 20 秒，避免 Windows 上 Git、Worktree 和 MCP 探测测试被默认 5 秒超时误判。独立评测仓库当前有 11 个测试文件、42 个测试；npm run typecheck:scenarios 已补上 turndown-plugin-gfm 的模块声明并通过。
