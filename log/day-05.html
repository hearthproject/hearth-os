Day05 · 首次运行、入口与邮件闭环

本页目录

2026-11-08 是 Hearth 把已有能力收敛成入口的一天。当天 40 次提交涉及 91 个文件（+9,076/−329）：凌晨先修掉模型档案、路由、会话启动和执行器就绪中的断点，再用可重复的浏览器 E2E 固定行为；随后把方法推进到 schema 11 的可审计应用，把首次运行、主动提醒、记忆召回、飞书长连接和 SMTP/IMAP 邮件依次接到真实界面。测试从 Day04 的 54 个文件、296 个测试增长到 61 个文件、381 个测试。

今天的主线不是再加一个页面，而是让已有闭环能被新用户走通、能被手机上的审批接住、能被真实邮件账户验证。每一步仍然保留同一条边界：通知只负责让人看到，批准仍走同一个审批与效果账本；没有真实账户时，不伪造送达或回执。

方向结果
模型档案与密钥删除档案前清空聊天档案指针；更新时把空 API Key 写成空密文，旧密钥不再复活；模型注册表校验失败返回 4xx，而不是 500
就绪判定native、Codex、DeepSeek Harness 的就绪状态统一从执行时使用的模型绑定推导，界面、路由和调度器共享同一健康结果

设置保存空命令或路径按未配置处理，保存不再失败或清掉旧值；保存前加载审批与路由设置，避免把默认值写回；侧栏健康状态和执行器标签与运行时对齐

四步向导/welcome 把服务商选择、连接测试、执行器检查、记忆与主动偏好、进入聊天串成一条路径；保存模型时一次完成建档、设为聊天模型并自动绑定原生执行器
导航与提醒主导航直接暴露“需要你”“记忆”“技能”“邮件”；新增通知中心，把待审批和主动建议转成可读提醒，页面打开时可用应用内 toast 和可选的浏览器桌面通知

飞书与真实邮件 ​

方向结果
飞书长连接自建应用长连接网关，包含租户令牌缓存、事件解析、图片/文件下载、自动重连、open_id 白名单和连接状态；不需要公网回调地址
任务与审批任务状态和一次性审批摘要发送到已映射会话；/approve、/reject 只接受白名单 open_id，并按当前会话关联任务的前缀匹配审批；拒绝不产生外部副作用
飞书设置设置页新增 App ID/Secret（加密保存）、白名单、飞书/飞书国际版域名、启停和连接状态
邮件账户SMTP/IMAP 主机、端口、TLS、账户和口令保存到本机；口令经 AES-256-GCM 加密，编辑时留空保留原口令；支持连接测试、更新和删除
SMTP 发送发件箱草稿选择 SMTP 账户后生成 email.smtp-send 一次性审批：预览发件人、收件人、抄送/密送、主题、正文和不可撤回影响，TTL 为 10 分钟；批准后由效果账本发送并保存 receipt.json
幂等与不确定发送复用审批参数哈希、效果幂等键、确定性 Message-ID 和本地回执；目录先用 sending.json 占位，已有目录但没有回执时进入不确定状态，不盲目重发
IMAP 同步只读打开 INBOX，读取最近 20–50 封，不标记已读；按 Message-ID 去重写入来源，正文进入来源内容目录；默认每 15 分钟同步，账户可关闭
邮件工作台账户、收件箱和写信三个视图；收件箱读取同步后的来源条目，写信只创建草稿，批准卡片显示邮件预览；本版没有附件选择 UI

边界与下一步 ​

  • 邮件默认仍写本机发件箱；配置 SMTP 后才可提交真实发送审批。真实账户、退信、垃圾邮件语义、OAuth2 和附件选择 UI 尚未人工验收；IMAP 只读最近 20–50 封且不标记已读。
  • 飞书长连接提供文本消息和一次性审批命令，但不是手机 PWA、系统推送或完整远程接管；真实租户、限频、重连和卡片按钮方案仍未验收，页面关闭后不会推送。
  • 方法自动学习与 2+2 证据已进入调度和审计，但仍缺长期生产对照、错误方法演练和候选质量数据；不能把“能生成候选”当作“方法已经变好”。
  • 首次运行只检查模型、执行器、记忆和主动服务，没有覆盖备份、安全和数据迁移；向导查询失败或非根路由不会强制拦截，属于有意保留的恢复路径。
  • 主动扫描每 5 分钟运行并响应领域事件，但页面关闭后没有系统级推送；通知只是提醒，批准仍走同一条一次性审批链。
  • 首次运行 API 测试对启动时延较敏感，并行负载下曾出现一次 5 秒超时；重跑通过，但测试超时余量仍需调整。
  • 阶段二至六的真实验收状态没有变化：真实邮件/日历、飞书租户、手机入口、桌面高风险动作、记忆生产对照、双设备切换和数周连续运行仍然留空。
  • 下一阶段继续按交付路线补真实证据，不新增只证明“页面存在”的入口。
