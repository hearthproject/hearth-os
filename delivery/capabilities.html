阶段二至六能力状态 ​

本文只记录当前代码和真实运行能证明的事实。状态分为“已实现代码闭环”“部分完成”和“未完成”，三者不能互相替代。

核对基线：2026-11-07。当前 npm test 通过 40 个测试文件、199 个测试；npm run typecheck、npm run build 和 npm run docs:build 通过。

Agent 运行时闭环 ​

  • 已实现： 原生执行器 native 与工程执行器 codex 并列，执行器身份写入运行记录和产物清单；普通任务默认走原生执行器，明确的代码/工程任务走 Codex，失败后不静默切换。
  • 已实现： 四协议模型接入（OpenAI Chat、OpenAI Responses、Anthropic Messages、Gemini），统一流式文本与工具调用；服务商可在设置中选择或自定义。
  • 已实现： @hearth/agent-runtime 单 Agent 工具循环，包含读取、搜索、写入、编辑、补丁、命令、联网、询问用户和完成工具；任务级读写目录、网络域名和工具白名单。
  • 已实现： 轮次、工具次数、Token 和时长预算；每个模型回合与工具步骤写检查点；等待用户补充时可带着回答恢复；缺失产物时带上一轮 Agent 上下文补交，最多两轮。
  • 已实现： 需要联网或工程工作区权限的任务先在聊天中生成提案，用户确认后才创建任务；普通通用任务直接派出。
  • 界面结果： 任务页显示执行器、阶段、Token、耗时和结果；详情页默认只展示用户需要的总结与声明产物，中间 JSON、命令日志和检查点收进折叠区域。

以上是代码与自动测试能证明的闭环，不代表已在真实用户环境中完成长期运行验收。

小阶段当前状态已实现明确留空
3.1 连接并查看桌面设备部分完成六位配对码、设备令牌、配对审批与能力审批分离；观察、控制、界面自动化逐项授权；应用白名单；在线状态和撤销设备尚未实现托盘或全局常驻的“自动控制中”提示；仅 Windows 同机助手
3.2 观察桌面与人工接管部分完成截图绑定当前会话；暂停、继续、接管、交还、终止；接管会取消待执行输入并推进控制代次；用户输入空闲检查；截图 2 分钟过期敏感区域遮罩、长期录像、完整桌面快照未实现
3.3 分级完成桌面操作部分完成目标应用绑定与执行前聚焦复核；点击、短文本、Enter/Tab/Escape/Ctrl+S；UIA invoke/setvalue 白名单；UWP 宿主窗口通过 UIA 子进程映射到批准应用；命令状态和结果记录；不支持动作结构化拒绝高风险动作预览与二次确认、隔离桌面、快照、补偿、真实 UIA setvalue 验收未完成
3.4 桌面操作验收未完成已在隔离端口完成配对、能力审批、观察、暂停、继续、接管、交还和专业版展开验证尚未用至少 5 个真实桌面任务完成成功率、接管次数和失败演练验收

Windows 助手目前采用“先聚焦服务端批准的目标应用，再截图或输入”的方式，不适合后台无焦点操作。对于由 ApplicationFrameHost 承载窗口的 UWP 应用，助手会读取窗口的 UIA 子树，只有解析出与批准应用对应的子进程时才允许聚焦和观察；例如 CalculatorApp 会映射为批准名 calculator。无法唯一归属或无法读取 UWP 子进程时直接拒绝，不把整个宿主窗口静默当成目标。真实 UIA invoke 已在计算器中验证：调用“二”返回 InvokePattern，读数由 7 变为 72。同一条链路也已在隔离配对设备上完成“观察 → UIA 动作 → 自动观察”，命令结果和截图回传均成功。

阶段四能力 ​

小阶段当前状态已实现明确留空
4.1 触发条件与主动建议已实现代码闭环六类触发器：任务进入 24 小时截止窗口、任务失败或可恢复、外部动作结果不确定、审批等待超过 2 小时、来源在 24 小时内出现新条目、队列积压或任务长时间运行；建议包含来源、为什么现在重要、建议动作、预计影响、预计成本、风险、是否需要审批和优先级；同一事件按键去重并累计出现次数邮件和日历触发器只有禁用占位，没有账户读取；主动模式只生成建议，不直接执行高风险动作
4.2 主动收件箱已实现代码闭环独立收件箱按优先级展示建议；支持接受、忽略、稍后提醒和转成普通任务；接受与转任务分离，接受只记录决定，转任务只创建排队任务，不批准审批、不重放外部动作；忽略后同一事件不换说法继续推送没有多设备或手机收件箱；没有通知渠道分发，只在本机 Web 收件箱呈现
4.3 手机查看、审批与接管未实现无没有手机 PWA、手机配对、推送、移动端审批或远程接管；当前入口仅为同机 Web 控制面
4.4 注意力预算与主动服务验收部分完成每日上限 0–50、安静时段、冷却时间、聚合窗口、临时暂停和恢复；预算快照显示今日已用、限额、是否安静/暂停及下次允许时间；最近 7 天记录送达、接受、忽略、转任务和完成任务数；“需要你”页面集中显示待处理审批尚未用 5–10 个真实主动任务验收“平均每个任务打断不超过一次”；没有推送送达统计，也没有长期用户感受记录

阶段四的关键边界是“建议不等于执行”。accept 只改变建议状态；只有 convert 会创建一个新的排队任务，之后仍按普通任务的执行器、审批和效果账本规则运行。高风险动作不会因为来自主动建议而绕过审批。

阶段五能力 ​

小阶段当前状态已实现明确留空
5.1 可查看的记忆已实现代码闭环记忆先进入候选，确认后才参与召回；记录类型、主题键、范围、标签、来源、置信度、敏感度、有效期和版本；召回按任务匹配度评分并记录原因与使用审计；注入上下文带 trusted="false" 和“不能扩大权限”的边界；支持召回条数与字符预算自动捕获默认关闭，且只支持从终态任务捕获“经历”记忆；没有从邮件、网页或任意文档自动抽取用户事实
5.2 纠正、遗忘与导出已实现代码闭环纠正生成新版本并保留历史；同主题冲突不会静默覆盖，必须选择左侧、右侧或合并；遗忘会把当前记录改为墓碑，并脱敏历史版本、相关事件和召回审计中的匹配词；导出不包含已遗忘正文；敏感记忆默认不召回，secret 记忆永不召回跨设备遗忘只通过同步过滤和本地副本边界保证；没有对已导出到外部文件的旧副本进行远程擦除
5.3 总结并评估可复用方法已实现代码闭环从终态任务轨迹生成候选；权限取来源任务能力交集，候选不得扩大权限；基线/试跑记录成功率、耗时、token 和审批次数；评估区分 improved、flat、regressed、insufficient；只有有改进证据且完成试跑样本的候选才能晋升；支持拒绝、回退并保留原因和审计“试跑”只读取已有终态轨迹作为证据，不会为评估自动再执行一次任务，因此不是实时 Shadow 执行器；没有真实生产方法的长期采用对照
5.4 记忆与进化验收未完成已有 API、服务层和页面闭环测试，覆盖创建、确认、召回、纠正、冲突、遗忘、导出、试跑、晋升和回退尚未完成真实用户的错误记忆演练、错误方法演练、采用前后成功率/人工时间/成本对照，以及完整“提出—评估—试用—采用—退回”生产验收

记忆与方法的共同边界是“先候选、后确认；先证据、后晋升”。候选方法不会自动上线，记忆内容也不能作为指令直接扩大工具、网络或审批能力。

阶段六能力 ​

小阶段当前状态已实现明确留空
6.1 多设备同步与切换部分完成每个实例有独立 instanceId；同步对端令牌只显示一次，服务端保存哈希和加密副本；按事件序号增量拉取并去重；导入事件可重建投影；任务、记忆和方法的较新本地状态不会被远端静默覆盖，冲突保留双方记录并由用户选择 local/remote；同步 UI 展示对端、游标、错误和冲突只同步经过过滤的事件投影；审批、来源、发件箱、设备、桌面、安全、同步事件以及敏感/机密记忆不会复制；产物正文、工作区和本地绝对路径不会同步；尚未用两台真实设备完成切换和断网恢复验收
6.2 设备撤销与安全迁移部分完成任务租约带 TTL、owner、epoch；过期后其他实例可接管并推进 epoch，旧 owner 的提交和结果会被拒绝；设备能力可撤销、设备令牌可轮换、设备可重新配对；同步对端可轮换令牌或撤销；全局 kill switch 会阻止审批和调度器重启，并记录安全审计；安全页展示状态与审计没有专门的跨设备产物/工作区迁移流程；没有真实设备丢失演练来证明旧设备在撤销后无法审批、接管或读取；解除全局停止后不会自动恢复执行器，需要用户显式重启
6.3 备份、恢复与升级部分完成生成 *.hearth-backup 加密归档；口令经 scrypt（N=32768、r=8、p=1）派生，AES-256-GCM 加密，口令至少 12 字符；归档包含 SQLite 快照、必要设置/审计/事件元数据和加密后的本机 master.key；恢复先写临时 SQLite，检查 user_version、schema 和 integrity_check，重建投影，再事务复制，失败回滚；保留当前实例 instanceId、createdAt 和全局停止状态，清除旧租约、配对和桌面会话临时记录；旧 /api/backup 返回 410 并要求使用加密备份不包含产物正文、任务工作区、来源正文、发件箱附件、截图/桌面临时文件和外部服务数据，因此不是完整可迁移备份；没有应用版本升级流水线或升级失败回退发布流程；schema 不兼容会拒绝恢复，但没有真实跨版本 fixture 演练
6.4 长期运行与 v1.0 验收部分完成健康快照包含运行时长、内存、磁盘、schema、任务计数、调度器、审批、kill switch 和最近一次维护；维护会清理过期审批、恢复中断任务、删除过期租约/桌面命令/截图/配对和临时文件，不删除任务、记忆或产物；服务启动后每 6 小时自动维护，也可手动触发；维护失败会记录失败并把健康状态标为 degraded；诊断导出包含健康、维护、计数和事件类型，不含路径、密钥或环境秘密；运维页展示健康、维护和备份边界没有数周连续运行测试、资源漂移数据、真实 v1.0 安装/升级/迁移/退出验收，也没有完整的全任务类型回归矩阵

阶段六的备份边界需要在界面上继续显示：数据库可恢复不等于产物文件可迁移。恢复完成后，任务可能重新出现，但产物正文、任务工作区或外部附件仍需要单独备份和核对。

当前界面边界 ​

当前聊天优先主导航只暴露 聊天、任务、设备、设置 四个入口。记忆、方法、主动收件箱、同步、安全和运维已经有服务端 API、投影和页面组件，但尚未全部接回主导航。阅读本文时，应把“能力存在”区分为：

  • 界面可直接使用： 聊天、任务、任务详情、设备、设置。
  • API 与页面组件已存在： 记忆、方法、主动收件箱、同步、安全、运维、发件箱、来源。
  • 尚未实现： 手机 PWA、推送、远程接管、真实邮件/日历账户。

借鉴与取舍 ​

  • OpenClaw： 配对与能力审批分离；命令按设备声明并逐项授权；观察帧是动作的唯一依据；用户接管会取消待执行输入、推进控制代次；不支持的动作直接拒绝。Hearth 已采用这些边界。
  • Hermes： 强调显式能力清单、执行前目标复核和会话隔离。Hearth 已采用应用白名单、目标应用复核和控制代次；尚未采用后台无焦点输入，因为当前 Windows 执行层无法可靠证明输入仍落在批准窗口内。
  • OpenClaw 的主动服务思路： 建议与执行分离、建议动作仍回到普通审批链。Hearth 已采用；没有把主动建议做成自动执行器。
  • Hermes 的健康检查思路： 把驱动、权限、运行状态和最近维护结果显式暴露。Hearth 已用健康快照、维护记录和脱敏诊断采用该边界。
  • DeerFlow： 任务拆解、方法候选和评估分层只作为设计参考。Hearth 没有集成 DeerFlow，也没有引入其多 Agent 运行时。
  • LoopX： 只借鉴小闭环提交、状态证据和验收边界作为交付方法；没有把 LoopX 作为运行依赖。

尚未完成的真实验收 ​

  1. 邮件与日历账户的只读接入、真实测试账户和真实发送回执。
  2. 10–15 个日常内容任务，以及至少 5 个桌面任务的完整验收记录。
  3. 敏感区域遮罩、隔离桌面、快照、补偿和高风险操作。
  4. 真实应用中的 UIA setvalue 验收，以及窗口丢失、权限变化和用户接管的失败演练。
  5. 阶段四手机入口（PWA、配对、推送、远程审批和接管），以及 5–10 个真实主动任务的打扰验收。
  6. 阶段五错误记忆/错误方法演练、完整导出核对，以及候选方法采用前后的真实生产对照。
  7. 阶段六真实双设备同步、断网恢复、设备丢失撤销、令牌轮换、备份恢复和迁移核对。
  8. 至少数周连续运行、资源与状态漂移检查、版本升级回退流水线和 v1.0 整体验收。

这些缺口已经留空，不用模拟数据或“看起来完成”的界面替代。
