工程交付与仓库结构 ​

工程原则、推荐技术栈、仓库布局、进程模型、数据目录、CLI、Event Log、测试、可观测性与发布迁移。

工程架构与仓库结构 ​

工程原则 ​

  • 模块化单体优先：早期不引入微服务；
  • 纵向切片优先：每个里程碑都必须同时包含 UI、持久状态、执行、验证和恢复；
  • 界面即验收面：用户不能在浏览器中完成的能力，不进入阶段出口；
  • 单写者：同一 State Root 只有一个写权威；
  • 事件溯源：事实写 Event Log，UI/索引是投影；
  • Schema 优先：输入、输出、Effect、Approval 都有版本化 schema；
  • 适配器隔离：Codex、Connector、Browser、GUI、Sandbox 都通过接口接入；
  • 本地优先：默认数据本地，云资源可替换；
  • 可回滚：数据库、技能、配置和发布都有回滚路径；
  • 可观测：每个任务有 correlation id、trace 和成本归因。

推荐技术栈 ​

以下为默认建议，不是不可替换的宗教：

层建议
语言TypeScript / Node.js 22+
包管理pnpm
单体仓库Turborepo 或等价工具
常驻服务Node + Fastify/Hono
数据库SQLite WAL + migration
SchemaZod / JSON Schema
WebReact + Vite + PWA
实时更新SSE 优先，必要时 WebSocket
浏览器Playwright
文档/数据Python sidecar + 成熟解析库
沙箱Docker 起步，微虚拟机用于不受信任任务
可观测OpenTelemetry + 本地日志/指标
测试Vitest/Playwright/契约测试/故障注入
打包npm CLI + Docker Compose

选择 TypeScript 的理由是前后端共享类型、事件协议和 schema，适合快速构建本地 Web 与 CLI；文档/数据密集处理通过 Python sidecar 补足生态，不把整个系统拆成多语言微服务。

进程模型 ​

text
hearth CLI / Web / Mobile
          │
          ▼
       hearthd
  ├─ Gateway
  ├─ Control Plane
  ├─ Durable Harness
  ├─ Token Governor / Context Compiler
  ├─ Executor Supervisor
  ├─ Event Log / projections
  ├─ Sandbox Provider client
  ├─ Credential Broker
  └─ Effect Dispatcher
          │
          ├─ Codex adapter
          ├─ Browser worker
          ├─ Connector workers
          ├─ Document/Data sidecar
          └─ Device agentd（后续）

所有执行器通过统一协议连接，不直接写主数据库。SQLite 由 hearthd 单进程写入；执行器通过 RPC/任务队列得到工作。

数据目录 ​

text
~/.hearth/
  state.db                # Event Log + projections
  artifacts/              # 内容寻址产物
  workspaces/             # 临时和项目工作区
  config/
    policy.yaml
    connections.yaml
  secrets/                # 加密凭据或 Broker 指针
  logs/
  backups/
  devices/

敏感目录权限最小化；备份加密；设备同步只传输必要的投影和产物引用。

CLI 输出支持人类可读和 JSON 两种模式，方便脚本和自动化测试。

Event Log 与投影 ​

  • Event 只追加，不原地更新；
  • 每个 Event 有 schemaVersion、correlationId、causationId；
  • 任务状态、收件箱、产物和成本都是投影；
  • 投影可重建；
  • 事件 hash 链或等价完整性校验；
  • 大内容存 Artifact，Event 只存引用；
  • migration 必须兼容旧事件；
  • 事件重放不能产生外部副作用。

任务与 lease ​

  • 每个 Ticket 同一时刻最多一个有效 Assignment；
  • lease 带 fencing token；
  • 执行器写入前校验 fencing token；
  • 设备离线后 lease 过期，任务可重新分配；
  • 重新分配不能重复外部 Effect；
  • 任务状态迁移有显式事件和条件；
  • 子任务继承父任务预算和权限交集。

可观测性 ​

  • 每个 Task/Run 有 trace id；
  • 每次模型调用记录模型、Token、成本和延迟；
  • 每次工具调用记录参数哈希、结果状态和资源；
  • 每次外部副作用记录幂等键与 Receipt；
  • UI 只展示用户需要的事件；
  • 详细信息保留在本地审计视图；
  • 日志自动脱敏；
  • 指标用于路由和评估，不用于操纵用户。

发布与迁移 ​

  • 版本化 schema 和 API；
  • 数据库 migration 向前兼容；
  • 执行器版本锁定；
  • 技能版本化；
  • 发布前跑评测和故障注入；
  • 支持回滚到上一个稳定版本；
  • 升级不破坏历史事件和产物；
  • 用户可导出和迁移。
  • 每个增量保留可回退版本，不允许只能靠重新搭建环境恢复。
