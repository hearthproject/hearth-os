交付路线总览 ​

产品路线图定义范围、顺序和阶段门槛；“从 0 到 100”把总纲拆成七个可以独立施工和验收的模块；工程保障负责仓库、风险与关键决策。

阅读顺序只有一条： 先读产品路线图，确认当前阶段做什么、不做什么；再进入对应的 Stage 模块；最后查阅工程保障与来源覆盖。

第一层：产品路线图是总纲 ​

产品路线图回答四个问题：

  1. 为什么现在做这个阶段？ 用能力依赖而不是日历排期来决定顺序。
  2. 这一阶段交付什么？ 明确用户可见的产品形态、核心能力和主要风险。
  3. 什么时候算完成？ 每个 Stage 都有退出条件和学习门槛。
  4. 什么暂时不做？ 把高风险、低价值或会拖垮地基的范围明确推迟。

阶段是能力门槛，不是日期承诺。每个阶段都可以停留、试用和回退，但不能跳过恢复、界面、验证或安全边界。

第二层：七个开发模块 ​

《从 0 到 100 开发计划》不是一张笼统的大清单，而是七个连续模块。每个模块都按“前置条件 → 开发步骤 → 增量拆分 → 退出验收 → 本模块不做”组织，开发者可以直接从当前模块开始施工。

S04 个增量定义与原型锁定用户、任务楔子、端到端原型、协议契约与评测基线。→S16 个增量持久内核与 MVP走路骨架、第一个 Codex 切片、MVP-1、副作用安全与恢复。→S26 个增量Personal Operator连接器、文档与数据、网页研究，以及需要审批的写入。→S34 个增量Computer Operator桌面 agentd、GUI 观察、人工接管和分级桌面动作。→S45 个增量主动个人 AgentTrigger、主动收件箱、手机 PWA 与注意力预算。→S54 个增量记忆与进化Memory Core、遗忘与导出、技能候选、评估与回滚。→S66 个增量多设备与长期运行事件同步、离线队列、设备撤销、备份迁移与长期运维。→

阶段推进顺序 ​

阶段开发模块阶段出口不能跳过的证据
Stage 0定义与原型可点击原型与稳定契约12 个真实任务、完整状态流、评测与审批基线
Stage 1持久内核与 MVP本地可每天使用的 MVP持久状态、真实 Codex 执行、审批、产物与恢复
Stage 2Personal Operator日常内容工作可委托连接器闭环、引用来源、审批写入与回执
Stage 3Computer Operator桌面任务可接管执行GUI 观察、接管、隔离、桌面验证与高风险审批
Stage 4主动个人 Agent有限授权下主动工作Trigger、注意力预算、手机审批与随时暂停
Stage 5记忆与进化可解释、可回滚地积累记忆纠正/遗忘/导出，技能评估、晋升与回滚
Stage 6多设备与长期运行可迁移的个人 Agent OS同步、离线恢复、设备撤销、备份迁移与长期审计

MVP 的位置： MVP-1 是 Stage 1 的早期出口，位于 D1.3，不是 Stage 6 的产物。它必须包含真实执行、持久任务、Web 任务卡、产物、审批演练和失败恢复。

开发者应该怎么开始 ​

  1. 第一次接触项目：读认识 Hearth和产品定义。
  2. 准备实现：读系统设计总览与持久执行。
  3. 开始动手：打开Stage 0，按步骤和增量逐项完成。
  4. 准备合并：检查风险与 Kill Criteria与默认清单。
