D1.5 · 第二任务族与内核加固 ​

证明内核不是为一个演示任务量身定制的：再加入一个真实任务族，并用故障注入检验恢复能力。

STAGE 1 · D1.5 · 1 个纵向切片 · 4 个工作包

用户可见结果除研究/文档外，第二个任务族也能通过同一任务卡模型完成；失败任务更容易恢复。
完成门槛两个任务族都能端到端完成；恢复率达到阶段门槛；重复外部副作用为 0；任务状态与事实源一致；失败不需要人工重建状态。

这一步要交付什么 ​

除研究/文档外，第二个任务族也能通过同一任务卡模型完成；失败任务更容易恢复。

Stage 1 的顺序是先有真实短闭环，再有安全副作用，最后扩大任务族和恢复覆盖；不能在空内核上先堆模块。

开始前 ​

  • Stage 0 的 12 个任务、原型、协议、评测与安全基线已经评审通过。
  • 默认任务楔子是研究/文档整理；如果首位用户更依赖代码任务，可以替换楔子，但纵向结构不能改变。
  • 本地开发环境、SQLite、可隔离 workspace 和 Web 构建链路可用。
  • D1.4 的交付物已经验收；未通过时不进入本增量。

四个实施工作包 ​

每个工作包都要产生可运行的代码、可复现的验证或明确的界面结果；只写接口或只做页面都不算完成。

01 · 第二任务族选择 ​

选择一个与首个任务族不同、但仍可本地验证的窄任务，例如文档转换或 Issue 到 PR 草稿。复用同一 Ticket、Run、Artifact 和审批路径，不复制一套旁路系统。

02 · 能力路由与模板 ​

为执行器声明 capability，按任务需求路由；任务模板固定输入、输出和验收。路由失败显示缺失能力，不默默降级到不适用的执行器。

03 · 恢复、预算与故障注入 ​

补齐 checkpoint、暂停、恢复、预算耗尽和人工接管；运行故障注入和重放，验证不同任务族共享同一恢复语义。

04 · 内核加固与审计导出 ​

补 schema migration、事件完整性、产物校验、诊断导出和用户可见审计。移除只在开发机可用的隐藏配置和永久 mock。

工程落点 ​

主要目录与模块 ​

  • apps/hearthd — 单进程常驻、Gateway、Control、Harness 与 SSE
  • packages/eventlog — SQLite WAL、事件、投影、migration 与 replay
  • packages/harness — Ticket、Run、lease、outbox、恢复与死信
  • packages/executors/codex — Codex adapter、workspace 与结构化输出
  • packages/policy — Policy、Mandate、Approval 与风险等级
  • packages/artifacts — 内容寻址产物、哈希、版本与验证器
  • apps/web — 任务卡、详情/时间线、审批、产物与恢复

关键接口 ​

接口必须保持的契约
RunrunId、ticketId、state、checkpoint、budget、terminalReason；一次执行尝试只能有一个终态。
Ticket / Leaseowner、scope、expiresAt、fencingToken；同一 Ticket 同时最多一个有效写者。
TaskPackobjective、inputs、constraints、outputSchema、acceptance、budget、permissions；执行器只在该包内工作。
Effect / ReceipteffectIntent、approvalId、idempotencyKey、receipt、reconciliation；不确定结果先对账，不盲目重试。

验收演练 ​

  1. 从干净的数据目录启动 hearthd，打开 D1.5 页面，确认当前页面没有依赖浏览器缓存或手工种子数据。
  2. 按顺序完成四个工作包：第二任务族选择、能力路由与模板、恢复、预算与故障注入、内核加固与审计导出。每完成一个工作包，保存对应测试输出、截图或产物版本。
  3. 复现失败案例“进程崩溃或重启”。页面必须显示“任务详情显示最后已知状态、未完成步骤和“继续/取消/重试”。”，然后按“从 Event Log 重放并重新领取 lease，禁止静默丢弃任务。”恢复；不得出现重复副作用或未登记状态。
  4. 重启服务并重新打开任务，确认运行状态、审批、产物和恢复入口都来自持久投影，而不是只存在于当前页面。
  5. 运行上方的共享验证命令并导出证据。完成门槛是：两个任务族都能端到端完成；恢复率达到阶段门槛；重复外部副作用为 0；任务状态与事实源一致；失败不需要人工重建状态。

完成判定 ​

  • [ ] 两个任务族都能端到端完成；恢复率达到阶段门槛；重复外部副作用为 0；任务状态与事实源一致；失败不需要人工重建状态。
  • [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
  • [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
  • [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

失败与恢复 ​

情况用户看到恢复动作
进程崩溃或重启任务详情显示最后已知状态、未完成步骤和“继续/取消/重试”。从 Event Log 重放并重新领取 lease，禁止静默丢弃任务。
外部动作重复系统显示“正在对账”，不生成第二个成功回执。按幂等键查询 sink，确认已完成后补写 Receipt 或走补偿。
副作用结果不确定任务进入“等待确认”，隐藏自动重试按钮。先查询外部系统或人工核对，再决定重试、补偿或关闭。

本增量不包含 ​

  • 不允许只靠 CLI、日志或数据库证明 MVP 可用。
  • 不在恢复与审批未稳定前扩大任务族。
  • 不把永久 mock 结果当成真实执行。
