D3.2 · GUI 观察与人工接管 ​

先让用户看得见、接得住，再让系统动手；观察和接管是任何自动 GUI 动作的前置条件。

STAGE 3 · D3.2 · 1 个纵向切片 · 4 个工作包

用户可见结果用户能在 Hearth 中看到目标窗口，暂停自动流程，自己操作，然后交还或终止。
完成门槛接管可用且不会与自动输入争抢；交还后任务状态明确；窗口范围正确；用户能看到需要自己完成什么；没有自动执行高风险动作。

这一步要交付什么 ​

用户能在 Hearth 中看到目标窗口，暂停自动流程，自己操作，然后交还或终止。

Stage 3 的顺序是观察、接管、低风险动作、高风险动作；无法观察和接管的桌面自动化不具备产品资格。

开始前 ​

  • Stage 1–2 的恢复、审批、幂等、回执和网页隔离已经稳定。
  • 有一台可配对的专用桌面设备，明确哪些窗口、应用和文件范围允许操作。
  • GUI 任务可以在隔离桌面中运行，且用户能随时暂停和接管。
  • D3.1 的交付物已经验收；未通过时不进入本增量。

四个实施工作包 ​

每个工作包都要产生可运行的代码、可复现的验证或明确的界面结果；只写接口或只做页面都不算完成。

01 · 最小观察采集 ​

采集目标窗口边界、可见截图、可访问性树和必要的焦点信息，不抓取全屏隐私区域。截图按任务范围裁剪，密码框、通知和敏感标题自动脱敏；观察帧带时间、窗口 ID 和范围，避免把旧画面当成当前状态。

02 · 只观察模式与输入锁定 ​

提供只观察模式，明确保证不发送任何键鼠输入。执行器处于观察状态时，控制通道只允许读取观察帧和取消；任何输入请求都因策略拒绝并记录，防止“看一下”演变成未授权操作。

03 · 实时接管与争抢处理 ​

用户点击接管后立即暂停自动输入、撤销待发送动作并把焦点交给用户。接管界面显示窗口、任务目标、当前步骤和已完成动作；用户操作期间系统只观察和记录，不得后台继续点击或抢占焦点。

04 · 交还、脱敏与超时 ​

交还前记录当前焦点、窗口、URL、已完成步骤和下一步；交还后重新采集状态并确认前置条件。接管超时、连接中断或窗口关闭时转入等待人工处理，保留截图和审计；验收要覆盖争抢、断线、敏感区域脱敏和任务终止。

工程落点 ​

主要目录与模块 ​

  • apps/agentd — 设备配对、能力声明、健康检查与撤销
  • packages/devices — 设备身份、会话、能力目录与在线状态
  • packages/desktop-observation — 窗口边界、截图、可访问性树与脱敏
  • packages/desktop-control — 白名单、定位器、输入动作与前后条件
  • packages/desktop-verification — 截图比较、焦点检查、半完成检测
  • packages/approval — 桌面 Effect Preview、二次确认与补偿说明
  • apps/web — 设备页、观察视图、实时接管和恢复界面

关键接口 ​

接口必须保持的契约
DeviceManifestdeviceId、publicKey、agentdVersion、capabilities、allowedRoots、expiresAt、revocationState；未声明的能力不可调用。
ObservationFramecaptureId、windowBounds、screenshotRef、accessibilityTree、capturedAt、redactions；只采集完成任务所需的最小范围。
DesktopActionactionType、targetWindow、locator、preconditions、expectedPostconditions、riskLevel、timeout；执行前必须通过策略检查。
DesktopReceiptactionId、beforeRef、afterRef、verification、partialState、compensation、approvalId；失败时保留可恢复证据。

共享验证命令 ​

bash
pnpm test:device：配对、能力越权、离线、撤销和会话失效
pnpm test:desktop：观察、接管、焦点变化、半完成和补偿
pnpm test:desktop-fault：窗口漂移、元素消失、输入争抢和崩溃
pnpm eval:computer：至少 8 个真实桌面任务及失败样本

验收演练 ​

  1. 从干净的数据目录启动 hearthd，打开 D3.2 页面，确认当前页面没有依赖浏览器缓存或手工种子数据。
  2. 按顺序完成四个工作包：最小观察采集、只观察模式与输入锁定、实时接管与争抢处理、交还、脱敏与超时。每完成一个工作包，保存对应测试输出、截图或产物版本。
  3. 复现失败案例“窗口或元素不匹配”。页面必须显示“任务暂停并显示当前窗口截图和需要确认的元素。”，然后按“重新定位、请求接管或调整白名单，不盲目点击坐标。”恢复；不得出现重复副作用或未登记状态。
  4. 重启服务并重新打开任务，确认运行状态、审批、产物和恢复入口都来自持久投影，而不是只存在于当前页面。
  5. 运行上方的共享验证命令并导出证据。完成门槛是：接管可用且不会与自动输入争抢；交还后任务状态明确；窗口范围正确；用户能看到需要自己完成什么；没有自动执行高风险动作。

交付物 ​

  • 观察视图与窗口范围
  • 实时接管/交还演示
  • 截图脱敏
  • 接管审计事件

完成判定 ​

  • [ ] 接管可用且不会与自动输入争抢；交还后任务状态明确；窗口范围正确；用户能看到需要自己完成什么；没有自动执行高风险动作。
  • [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
  • [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
  • [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

失败与恢复 ​

情况用户看到恢复动作
窗口或元素不匹配任务暂停并显示当前窗口截图和需要确认的元素。重新定位、请求接管或调整白名单，不盲目点击坐标。
自动输入与用户争抢自动输入立即暂停，控制权交给用户。等待用户交还并确认焦点、窗口和下一步。
高风险动作半完成任务显示“需要检查”，隐藏继续按钮并保留快照。按补偿脚本或人工接管恢复，记录未完成影响。

本增量不包含 ​

  • 不在无法观察、无法验证或无法接管时开放自动操作。
  • 不读取密码库，不修改系统安全设置，不操作未授权窗口。
  • 不把一次成功的坐标点击当成通用 GUI 能力。
