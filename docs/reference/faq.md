# 常见问题

<p class="lead">这里回答第一次接触 Hearth 时最常见的问题。产品边界和设计取舍见[总体设计](/design/)，阶段顺序见[交付路线](/delivery/)。</p>

**Hearth 是另一个 Coding Agent 吗？** 不是。Codex 是 Hearth 的重要执行器之一，但 Hearth 的产品中心是任务控制、持久执行、审批、回执、记忆和验证。它要处理邮件、日程、文档、网页、桌面和数据等更广泛的个人数字工作。

**它是 Codex 套壳吗？** 不是。Hearth 不让 Codex 持有长期凭据、成为记忆中心或自行扩大权限。Codex 接收最小上下文，在隔离工作区完成工作，返回产物和结构化结果；外部动作仍由 Hearth 审批、执行和对账。

**必须联网吗？** 默认本地优先。任务、产物、记忆和凭据先保存在用户控制的环境；模型、远程执行环境和同步服务都是可选能力。使用云端能力时，系统会说明哪些数据离开设备、保留多久以及如何删除。

**现在能做什么？** 0.3.4 已经能聊天、执行带工具的真实任务、在审批后执行外部动作、操作浏览器和桌面、跑定时任务、用资料库管理文件/记忆/技能、从 Context 生成接手摘要，并用 SQLite 事件日志和操作账本做崩溃恢复。任务列表、任务详情和“需要你”收件箱已下线，执行轨迹改为对话内联运行卡；外部账户、真实模型首跑、自动更新签名和干净机安装/卸载仍未验收。逐项见[当前交付状态](/delivery/status)。

**为什么找不到任务列表或“需要你”收件箱？** 0.3.4 把任务表面收进了聊天：对话里的运行卡显示执行轨迹、审批、产物和恢复入口。主导航只保留聊天、资料库、Context；定时任务和连接收在“更多”。这是产品收缩，不是页面故障。

**Windows 沙箱是强隔离吗？** 不是。它用 AppContainer、ACL、Job Object 和父进程 watchdog 限制文件、进程与网络，但不是虚拟机或容器级隔离；网络只有 `deny | open`，`approvalMode=full` 会显式切到 `danger-full-access` 并跳过沙箱。助手缺失或策略不支持时 fail-closed，不会静默降级。

**为什么不直接做一个万能 Agent？** 因为“万能”通常意味着权限、上下文和失败边界都不可控。Hearth 使用多个专长执行器，根据能力、风险、可逆性和成本选择路径；每个执行器都有明确边界、验证方式和人工接管入口。

**外部操作如何防止重复？** 所有外部动作先生成可预览参数，经过一次性授权后写入操作账本，再用同一身份执行并保存回执。审批绑定参数指纹：文件变化、页面 DOM 变化或参数被篡改时授权失效。重试不会创建第二封邮件或第二条记录；外部系统返回不确定结果时先对账，无法确认就停下来交给用户。

**Hearth 会自动修改自己吗？** 不会自动修改核心权限、审批门槛或执行边界。自修改需要单独设计和验收，不能由模型在运行时绕过审批或扩大沙箱范围。

**支持多用户、企业和手机吗？** Hearth 是单用户、自托管产品，不把企业多租户、组织审计和计费作为第一版目标。手机是受控入口，重点覆盖查看、审批、接管、简单发起和通知，不复制桌面端的全部管理功能。当前已有 PWA 壳、移动底部导航和飞书文本审批，但手机配对、系统级推送、远程接管和真机安装仍未验收。
