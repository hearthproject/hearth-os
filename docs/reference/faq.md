# 常见问题

<p class="lead">这里回答第一次接触 Hearth 时最常见的问题。产品边界和设计取舍见[总体设计](/design/)，阶段顺序见[交付路线](/delivery/)。</p>

**Hearth 是另一个 Coding Agent 吗？** 不是。Codex 是 Hearth 的重要执行器之一，但 Hearth 的产品中心是任务控制、持久执行、审批、回执、记忆和验证。它要处理邮件、日程、文档、网页、桌面和数据等更广泛的个人数字工作。

**它是 Codex 套壳吗？** 不是。Hearth 不让 Codex 持有长期凭据、成为记忆中心或自行扩大权限。Codex 接收最小上下文，在隔离工作区完成工作，返回产物和结构化结果；外部动作仍由 Hearth 审批、执行和对账。

**必须联网吗？** 默认本地优先。任务、产物、记忆和凭据先保存在用户控制的环境；模型、远程执行环境和同步服务都是可选能力。使用云端能力时，系统会说明哪些数据离开设备、保留多久以及如何删除。

**第一阶段能做什么？** 第一阶段交付最小完整 MVP：只服务一个窄任务族，但在真实浏览器里走完“创建任务、执行、审批、查看产物、失败恢复”的完整路径。它不包含邮件、日历、桌面操作、主动循环、完整记忆或多设备。

**为什么不直接做一个万能 Agent？** 因为“万能”通常意味着权限、上下文和失败边界都不可控。Hearth 使用多个专长执行器，根据能力、风险、可逆性和成本选择路径；每个执行器都有明确边界、验证方式和人工接管入口。

**外部操作如何防止重复？** 所有外部动作先留下待执行意图，经过预览和授权，再用同一身份执行并保存回执。重试不会创建第二封邮件或第二条记录；外部系统返回不确定结果时先对账，无法确认就停下来交给用户。

**Hearth 会自动修改自己吗？** 不会无界自修改。系统可以根据真实轨迹提出新方法，但候选方法必须经过权限检查、回放、无副作用试运行、小范围真实使用和回退验证。授权规则、审批门槛和核心安全边界不能由模型自己修改。

**支持多用户、企业和手机吗？** Hearth 是单用户、自托管产品，不把企业多租户、组织审计和计费作为第一版目标。手机是受控入口，重点覆盖查看、审批、接管、简单发起和通知，不复制桌面端的全部管理功能。第一阶段只保证本地 Web 的最小完整路径。
