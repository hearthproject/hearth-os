# 常见问题

<p class="lead">这里回答第一次接触 Hearth 时最容易出现的疑问。更完整的定义与边界见[项目设计与取舍](/design/)，架构细节见[总体架构](/architecture/overview)。</p>

## Hearth 是另一个 Coding Agent 吗？

不是。Codex 是 Hearth 的重要并列执行器，但 Hearth 的产品中心是任务控制、持久执行、记忆、验证、审批和回执。它要处理的是邮件、文档、日程、网页、桌面和数据等更广泛的个人数字劳动。

## 它是 Codex 套壳吗？

不是。Hearth 不把 Codex 当作唯一执行大脑，也不让 Codex 持有长期凭据、成为记忆中心或自行扩大权限。Codex 通过 Task Pack 接收最小上下文，通过结构化输出返回产物、验证和失败分类。

## 必须联网吗？

默认是本地优先。状态、事件、记忆和凭据优先保存在本地；模型 API、远程 Sandbox 或云端同步都是可选能力。具体部署形态见[总体架构](/architecture/overview)。

## Stage 1 能做什么？

Stage 1 早期会出现 Hearth MVP-1：可恢复内核、Codex 切片、Web 任务卡、审批演练、产物和失败恢复。它不包含邮件、日历、GUI、主动循环、完整记忆和多设备。

## 为什么不直接做一个万能 Agent？

因为“万能”通常意味着权限、上下文和失败边界都不可控。Hearth 选择多个并列执行器，按能力、风险和 Token 成本路由；每个执行器有明确边界、验证器和接管路径。

## 外部副作用如何防止重复？

所有外部动作经过 outbox、幂等键、审批/授权检查和 Receipt。先落盘再执行；重试复用同一幂等键；无法幂等的外部动作必须审批并转人工；不确定结果先对账。

## Hearth 会自动修改自己吗？

不会无界自修改。Evolution OS 只能产生候选技能或候选策略，必须经过评估、canary、晋升和回滚。核心 Runtime 的修改仍需要人工 PR。

## 支持多用户或企业吗？

不是第一版目标。Hearth 是单用户、自托管产品；企业 IAM、多租户、组织审计和计费明确不承诺。

## 手机能用吗？

移动端是 Stage 4 的重点：查看、审批、接管、发起和通知。手机不是复制完整 Agent，而是受控入口。

## 文档为什么有中英文两套？

中文是当前路线图的原始语言，英文用于更广泛的开发者阅读。两套页面保持相同路径和结构，右上角可一键切换。发现翻译或结构问题，请阅读[贡献与文档维护](/reference/contributing)。
