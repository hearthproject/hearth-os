# 风险与 Kill Criteria

<p class="lead">什么情况下暂停、回退或停止项目，比“继续做”更难也更重要的决策。</p>

## 风险与 Kill Criteria

### 主要风险

| 风险 | 早期信号 | 缓解 |
|---|---|---|
| 范围膨胀 | 每阶段都在新增执行器，核心闭环未稳定 | 以任务集和阶段门槛控制范围 |
| 可靠性不足 | 崩溃后任务丢失、重复发送 | 单写者、outbox、lease、故障注入 |
| 安全事件 | 越权、秘密泄露、提示词注入成功 | 沙箱、Broker、审批、红队 |
| Token 成本失控 | 单任务成本高且人工分钟未下降 | Context Compiler、路由、缓存、硬预算 |
| 外部 Agent 依赖 | 版本变化导致大量任务失败 | 适配器、版本锁定、降级到 Native/人工 |
| 维护负担 | 每周大量时间修依赖和渠道 | 不自研底层、减少连接器、自动升级测试 |
| 通知疲劳 | 用户关闭通知或忽略审批 | 注意力预算、聚合、静默、默认动作 |
| 记忆错误 | 反复引用过期或错误事实 | 来源、置信度、冲突、遗忘、用户纠正 |
| 自进化漂移 | 技能越用越复杂、权限变多 | 评估、shadow、canary、权限交集、回滚 |
| 多设备复杂 | 同步冲突、重复执行 | 单写者、lease、fencing、离线队列 |
| 产品像套壳 | 去掉 Codex 后没有独立价值 | 控制面、记忆、审批、恢复、评测 |
| 平台限制 | 浏览器登录、验证码、API 变更 | 人工接管、官方 API 优先、降级 |
| 用户信任下降 | 用户不理解为什么这样做或无法撤销 | 可解释状态、产物、回执、kill switch |
| 时间投入不可持续 | 维护超过可支配时间 | 缩小范围、延迟非核心能力、自动化测试 |

### 全局暂停条件

出现以下情况时，暂停新增功能，优先修复：

- 高风险动作发生越权；
- 发生秘密或敏感数据泄露；
- 故障注入出现重复外部副作用；
- 崩溃恢复率低于 95%；
- 用户无法撤销设备、连接或技能；
- 关键记忆无法遗忘；
- 任务状态与事实源不一致；
- 外部副作用无法对账。

### 阶段 Kill Criteria

**第一阶段：**

- 无法定义 10 个可验收的真实任务；
- 无法说明 Hearth 与直接使用现有工具的区别；
- 没有威胁模型和基本安全边界；
- 原型无法让用户在不看说明的情况下完成主路径；
- 达到 MVP 门槛后仍无法完成 8 个真实任务；
- 重复外部操作无法消除；
- 恢复依赖人工重建状态；
- 任务状态只能靠聊天记录推断；
- 后端可用但浏览器无法完成创建、查看、审批、恢复和取回产物。

**第二阶段：**

- 邮件或日历闭环需要用户频繁重建背景信息；
- 来源权限无法最小化；
- 文档、表格或网页结果无法验证；
- 常见任务人工时间没有下降；
- 不同账户或项目数据串扰；
- 外部写入可能重复执行或无法核对。

**第三阶段：**

- 桌面任务成功率低且无法接管；
- 无法证明操作没有越权；
- 桌面状态无法恢复；
- 每次桌面任务都需要大量人工介入；
- 失败后容易留下半完成的高风险状态。

**第四阶段：**

- 主动任务制造通知疲劳；
- 用户无法预测何时会被打扰；
- 手机审批可被重复使用或越权；
- 后台任务无法停止或预算失控；
- 高风险动作因为主动性而绕过审批。

**第五阶段：**

- 记忆错误导致持续返工；
- 遗忘无法传播到摘要、索引和关联内容；
- 方法评估可被挑选样本操纵；
- 新方法扩大权限或造成安全回归；
- 旧版本无法恢复。

**第六阶段：**

- 多设备重复执行或状态分裂；
- 设备丢失无法及时撤销；
- 迁移后任务、记忆或产物不一致；
- 长期运行维护成本超过产品收益；
- 用户无法独立备份、恢复或退出。

### 项目级 Kill Criteria

在以下情况下，应考虑缩小产品，而不是继续加功能：

- 完成第二阶段后仍没有稳定的 10 个真实日常任务；
- 人工分钟没有实质下降，用户只是在“看 Agent 工作”；
- 维护成本持续超过可支配时间且没有下降趋势；
- 仅靠换模型就能替代 Hearth 的绝大部分价值；
- 安全边界无法达到可接受水平；
- 用户不愿意把真实邮件、文件或日程交给它；
- 自进化持续产生不可解释的漂移；
- 多设备复杂度吞掉单设备体验。

### 不应被 Kill 的东西

- Event Log 和可恢复性；
- 审批、幂等和 Receipt；
- 评测与失败样本；
- 记忆遗忘和用户纠正；
- 任务卡与低打扰体验；
- 手动接管；
- 安全边界和 kill switch。

这些是产品的地基，不是可以在“赶进度”时删除的功能。
