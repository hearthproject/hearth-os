# 术语表

<p class="lead">同一个词在文档、界面和代码里应当表达同一件事。这里解释 Hearth 最常用的概念，优先使用用户能理解的说法。</p>

| 术语 | 含义 |
|---|---|
| Hearth | 单用户、自托管、长期运行的个人 Agent OS |
| 任务 | 用户希望完成、可以验收和恢复的工作项 |
| 运行 | 任务的一次真实执行尝试；同一任务可以有多次运行 |
| 完成判定 | 按验收条件逐项检查证据并给出通过、失败、需要人工或受阻结论的过程 |
| 工作单元 | 任务中被授权、可单独执行和验证的一小段工作 |
| 事实记录 | 只追加的系统记录；界面、统计和通知都从它重建 |
| 单一事件日志 | SQLite `events` 表；消息、工具结算、检查点和 run 边界的唯一事实源 |
| 检查点 | 长任务中途保存的可恢复状态；服务端是事件的物化视图，损坏时按 `event_seq` 重建 |
| 操作账本 | 工具调用的 `prepare → dispatch → settle` 记录；未结算操作在下一进程拒绝自动重放 |
| HostKernel | 管理数据目录租约、阶段化恢复、就绪门和关闭顺序的宿主内核 |
| run-evidence | 终态 run 输出的证据文件，含检查点引用、恢复决策、operations/cleanup、产物与 run 链 |
| 快照 | 某一时刻的工作区或数据副本，用于恢复和比较 |
| 执行器 | 完成某类工作的受控能力，例如 native、Codex、DeepSeek Harness |
| 连接器 | 通过官方接口连接邮件、日历、云盘等外部系统 |
| 委派 | 父任务把一块边界清楚的子工作交给另一个执行路径，并继承父任务的约束和剩余预算 |
| 交接包 | 继续执行所需的诊断、已完成事项、证据、未解决问题、剩余预算和 generation |
| 沙箱 | 对路径、进程、网络和凭据范围执行的策略边界；Windows 使用 AppContainer + Job Object，不是强隔离容器或虚拟机 |
| 授权范围 | 用户允许某类动作在什么对象、时间和风险范围内发生 |
| 审批 | 用户针对一次具体外部动作作出的确认；绑定参数指纹，参数变化即失效 |
| 外部副作用 | 发送、写入、删除、发布、付款、设备操作等真实世界影响 |
| 回执 | 外部动作发生后的可核对结果 |
| 对账 | 在结果不确定时查询外部状态，确认动作是否真的发生 |
| 个人本体 | 带来源、可信度、敏感度和有效期的实体、别名、关系、状态、决定和承诺 |
| Context Pack | 按范围、预算和通道组装给执行器的上下文，区分必须知道、相关、可展开和明确省略 |
| Context 交接 | 从活跃记忆生成接手摘要、原记录和导出包，交给下一个执行者或账号 |
| 离线 outbox | 设备断网时保存待发动作的队列；重连后按幂等标识提交，不盲目重放外部副作用 |
| 产物 | 任务交付的文件、报告、表格、链接或其他结果 |
| 记忆 | 带来源、适用范围和敏感度的长期或中期背景 |
| 资料库 | 文件、记忆、资料和技能的统一树；支持检索、预览、回收站和遗忘传播 |
| 评估 | 用真实任务、基线、验证器和成本指标判断能力；评测控制台已拆到独立仓库 |
| 停止开关 | 在异常时暂停任务、设备或全部外部动作的入口 |
| 验证通过 | 有产物、证据和必要回执支持的真实完成 |
