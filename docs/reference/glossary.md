# 术语表

<p class="lead">同一个词在文档、界面和代码里应当表达同一件事。这里解释 Hearth 最常用的概念，优先使用用户能理解的说法。</p>

| 术语 | 含义 |
|---|---|
| Hearth | 单用户、自托管、长期运行的个人 Agent OS |
| 任务 | 用户希望完成、可以验收和恢复的工作项 |
| 工作单元 | 任务中被授权、可单独执行和验证的一小段工作 |
| 执行记录 | 某一次真实执行留下的输入、结果、产物和失败原因 |
| 事实记录 | 只追加的系统记录；界面、统计和通知都从它重建 |
| 检查点 | 长任务中途保存的可恢复状态 |
| 快照 | 某一时刻的工作区或数据副本，用于恢复和比较 |
| 执行器 | 完成某类工作的受控能力，例如通用推理、Codex、浏览器或桌面操作 |
| 连接器 | 通过官方接口连接邮件、日历、云盘等外部系统 |
| 授权范围 | 用户允许某类动作在什么对象、时间和风险范围内发生 |
| 审批 | 用户针对一次具体外部动作作出的确认 |
| 外部副作用 | 发送、写入、删除、发布、付款、设备操作等真实世界影响 |
| 回执 | 外部动作发生后的可核对结果 |
| 对账 | 在结果不确定时查询外部状态，确认动作是否真的发生 |
| 产物 | 任务交付的文件、报告、表格、链接或其他结果 |
| 记忆 | 带来源、适用范围和敏感度的长期或中期背景 |
| 方法 | 经过验证、可以重复使用的工作流程或工具配方 |
| 评估 | 用真实任务、基线、验证器和成本指标判断能力 |
| 灰度 | 让新方法先在小范围真实使用，再决定是否扩大 |
| 停止开关 | 在异常时暂停任务、设备或全部外部动作的入口 |
| 验证通过 | 有产物、证据和必要回执支持的真实完成 |
