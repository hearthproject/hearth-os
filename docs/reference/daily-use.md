# 日常使用与自用报告

Hearth 现在把“日常操作”和“工程诊断”分开：日常只需要聊天、资料库和 Context；任务状态、审批和失败恢复都出现在对话里的运行卡和右侧产物面板，不再有独立的任务列表或收件箱。

## 聊天工作台

- 左侧是对话列表；项目会话按文件夹分组，可直接新建任务或继续普通对话。
- 输入框只保留一个执行器选择器：对话级选择覆盖全局默认；不可用或未绑定时自动回退。
- 任务以运行卡内联在时间线里：展开后看到叙述、工具调用、命令、文件与结算状态；任务失败或等待审批时，卡片会给出继续、重试或补充输入入口。
- 右侧“对话产物”按需展开：产物、后台任务和附件都在这里，文本、Markdown、代码、JSON/CSV、图片和 PDF 可直接预览。

审批出现在运行卡内，不需要另开页面。工作区内可逆写入自动执行；shell、删除、邮件、桌面、陌生域名和提交/上传/下载类动作仍需要一次性授权，参数指纹绑定当次动作。

## 资料库

左侧导航的 **资料库**（`/library`）把文件、记忆、资料和技能放在同一棵树里：

- 顶部搜索框跨树检索；选中节点后右侧显示摘要、标签和内容预览。
- 记忆按“已记住 / 待确认”分区；点开一条记忆可以查看来源、可信度、版本和纠正记录。
- 回收站支持恢复或彻底删除；删除记忆会走遗忘传播，其他节点仍引用的内容不会被误删。
- 技能页可以查看使用次数、版本和最近一次调用，不是静态说明页。

## Context 交接

左侧导航的 **Context**（`/context`）用于把当前工作交给下一个执行者或账号：

- 顶部选择范围（全部记忆或单个账号），显示活跃记忆、最近决定、目标和下一步。
- “接手摘要”从记忆生成，原文按条目列出；可以下载原记录和完整 zip。
- 共享视图会列出全部记忆和交接范围，便于核对是否漏项。
- 导出文件可能包含个人信息，分享前请检查。

## 邮件与定时任务

- **邮件**（`/mail`）：SMTP 发送复用审批与效果账本；IMAP 只读同步最近邮件到来源，不标记已读。默认写本机发件箱，配置账户后可以提交真实发送审批。
- **定时任务**（`/schedules`）：支持 Cron、有界补跑、失败冷却和直接使用自定义输入；执行结果仍以任务形式进入对话或资料库。
- **连接**（`/connections`）：飞书长连接、浏览器、桌面助手和 MCP 的接入状态都在这里；入站消息带幂等记录，不需要公网回调。

## 自用报告（dogfood）

`npm run dogfood:report` 从本地事件账本读最近 7 天：

```bash
npm run dogfood:report
npm run dogfood:report -- --days 30 --project hearth-os --out reports/dogfood.md
```

报告包含：

- 新建任务数、完成/失败/进行中数量；
- 成功率（完成 ÷ 已完成和失败）与一次通过率（第一次尝试就完成）；
- 尝试次数、轮次、工具调用、输入/输出 token；
- 审批次数、通过和拒绝数量；
- 最常见的失败原因，以及需要多次尝试的任务。

指标只描述本机真实使用，不是公开基准。公开评测已迁到独立仓库 `hearth-eval`，主仓库不再保留评测控制台。报告默认写到 `reports/`，这个目录用于本机记录，不进入版本库。

## 边界

- 聊天时间线只显示用户需要看的摘要和证据；完整轨迹留在本地事件日志与 `run-evidence.json`，不在界面上倾倒内部 JSON。
- 自用报告不推断因果，不把失败归因于模型或用户；失败原因按任务记录原文聚合。
- 数据不出本机；报告文件里可能包含任务标题，分享前请自行检查。
