# 日常使用与自用报告

Hearth 把"需要人处理的事"和"系统自己在做什么"分开。日常使用时，你只要看两处。

## "需要你"收件箱

左侧导航的 **需要你**（`/inbox`）只放四类信号：

- 任务运行超过 30 分钟；
- 审批等待超过 10 分钟；
- 任务停在预算上限；
- 任务失败或可恢复失败。

每条通知都可以标为已读、稍后提醒（默认 4 小时）或不再提醒。相同的任务和类型在 6 小时内不会重复出现；22:00–08:00 不生成新通知，避免半夜打断。

通知不是聊天气泡，也不会自动发到飞书或邮件。它只写在本地 `data/supervision.json`，由网页读取。

## 昨日回顾

每天 08:00 之后第一次打开收件箱或调用 `GET /api/supervision` 时，会生成一份昨日回顾：完成、失败、等审批、未结束的数量，以及最多三条建议。回顾按本地日期计算，不会回填历史日期。

## 自用报告（dogfood）

`npm run dogfood:report` 从本地事件账本读最近 7 天：

```bash
npm run dogfood:report
npm run dogfood:report -- --days 30 --project hearth-os --out reports/dogfood.md
```

报告包含：

- 新建任务数、完成/失败/进行中数量；
- 成功率（完成 ÷ 已完成和失败）与一次通过率（第一次尝试就完成）；
- 尝试次数、轮次、工具调用、输入/输出 token；
- 审批次数、通过和拒绝数量；
- 最常见的失败原因，以及需要多次尝试的任务。

指标只描述本机真实使用，不是公开基准。公开评测请走 `npm run bench:suite` 和 `docs/evaluation/`。报告默认写到 `reports/`，这个目录用于本机记录，不进入版本库。

运行控制台（`/runtime`）也会显示最近 7 天的同一组汇总，方便不打开终端时查看。

## 边界

- 收件箱不判断任务"应该"怎么修，只报告事实和需要人处理的动作。
- 自用报告不推断因果，不把失败归因于模型或用户；失败原因按任务记录原文聚合。
- 数据不出本机；报告文件里可能包含任务标题，分享前请自行检查。
