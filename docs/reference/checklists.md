# 默认清单

<p class="lead">清单应当放进任务模板、审批界面和验收流程，而不是只留在文档里。它帮助用户确认系统没有把“看起来完成”当成“真正完成”。</p>

## 审批与完成前检查

外部动作发生前，逐项确认：

- [ ] 动作类型和真实意图一致；
- [ ] 目标收件人、文件、账户、设备或资源正确；
- [ ] 内容和附件正确；
- [ ] 没有超出当前授权范围；
- [ ] 是否可逆、可能影响什么已经说明；
- [ ] 审批仍在有效期内，且没有被重复使用；
- [ ] 失败、重试和对账方式已经准备；
- [ ] 没有绕过网络、凭据或安全边界。

读取和整理可以在任务范围内授权；发送、发布、删除、付款和设备操作需要明确确认；不可逆动作即使已经预授权，也要有对象、金额或时间上的硬限制。

任务标记完成前，逐项确认：

- [ ] 目标产物存在，用户能够找到；
- [ ] 验证器已经通过，而不是只听执行器说完成；
- [ ] 关键事实有来源，修改有差异或版本；
- [ ] 没有未授权的副作用；
- [ ] 外部动作有回执，不确定结果已经对账；
- [ ] 失败、跳过和未完成事项已经说明；
- [ ] Token、时间、人工分钟和成本已经记录；
- [ ] 工作区、临时权限和执行权已经回收；
- [ ] 用户可以查看、撤销、重试或继续。

## 覆盖边界

Hearth 不承诺“任何软件、任何场景、100% 无人值守”。它承诺的是：对选择的个人数字工作提供端到端覆盖，对无法可靠完成的工作安全停下并交给人，对每次完成给出证据、权限记录和回执。

| 成熟度 | 含义 |
|---|---|
| 可尝试 | 系统能进入任务族并生成草稿 |
| 可完成 | 在代表性任务上通过验证 |
| 可依赖 | 多次真实使用稳定，失败可恢复 |
| 可主动 | 在授权范围内无需人工触发 |
| 可无人值守 | 长时间运行且风险可控 |

“可尝试”不能当作“可依赖”，“可完成”也不能当作“可无人值守”。阶段验收按真实任务和证据判断，不按功能名称判断。
