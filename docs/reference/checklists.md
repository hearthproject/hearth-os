# 默认审批与完成清单

<p class="lead">把这些清单放进任务模板、审批界面和验收流程，而不是留在文档里。</p>

## 默认审批清单

高风险动作前，逐项确认：

- [ ] 动作类型正确；
- [ ] 目标收件人/文件/仓库/日历/资源正确；
- [ ] 使用账户正确；
- [ ] 内容和附件正确；
- [ ] 范围没有超出 Mandate；
- [ ] 是否可逆已说明；
- [ ] 失败和对账方式已说明；
- [ ] 审批有 nonce 和过期时间；
- [ ] 已准备回执和撤销/补偿；
- [ ] 没有绕过安全控制。

## 默认完成清单

任务标记完成前，逐项确认：

- [ ] 目标产物存在且可定位；
- [ ] 验证器通过；
- [ ] 关键断言有来源；
- [ ] 修改有 diff 或版本；
- [ ] 没有未授权的副作用；
- [ ] 外部动作有 Receipt；
- [ ] 失败和未完成项已说明；
- [ ] Token、时间和成本已记录；
- [ ] 工作区、凭据和 lease 已回收；
- [ ] 用户可以查看、撤销或继续。

## 任务覆盖的最终定义

Hearth 的目标不是承诺“任何软件、任何场景、100% 无人值守”。它的目标是：

- 对八类数字内容工作提供端到端覆盖；
- 对每类任务逐步提高可靠性和自主性；
- 对无法可靠完成的任务安全停下并交给人；
- 让用户不必理解内部架构，也不必重复交代上下文；
- 让每次完成都有证据、权限和回执。

覆盖的成熟度应分层表述：

| 层级 | 含义 |
|---|---|
| 可尝试 | 系统能进入该任务族并产生草稿 |
| 可完成 | 在代表性任务上通过验证 |
| 可依赖 | 多次真实使用稳定，失败可恢复 |
| 可主动 | 在 Mandate 内无需人工触发 |
| 可无人值守 | 长时间运行且风险可控 |

不要用“可尝试”冒充“可无人值守”。
