# 文档地图与维护

<p class="lead">所有正式文档只存放在仓库的 `docs/`。文档站由这个目录直接构建，README 只负责仓库入口，因此仓库内容与线上站点始终是同一份文档。</p>

## 单一文档源

| 内容 | 唯一位置 | 说明 |
|---|---|---|
| 中文文档 | `docs/` | 默认阅读路径，也是内容维护的事实源 |
| 英文镜像 | `docs/en/` | 与中文页面保持路径、标题层级和结构对应 |
| 站点配置 | `docs/.vitepress/` | 导航、侧栏、主题和构建配置 |
| 完整路线图 | `docs/reference/full-roadmap.md` | 站内唯一的长文归档页 |
| 仓库入口 | `README.md`、`README.zh-CN.md` | 只做项目简介和导航，不复制详细正文 |

> 不再维护第二份 `sources/` 文档目录。需要完整细节时，使用站内[完整路线图归档](/reference/full-roadmap)，不要另外寻找原稿副本。

## 阅读层级

产品路线图是总纲，开发计划负责拆解，Stage 和 D 增量负责施工与验收：

1. **产品路线图**回答为什么做、当前阶段做什么、什么时候算完成；
2. **从 0 到 100 开发计划**把总纲拆成七个连续模块；
3. **Stage 模块页**说明前置条件、阶段出口和本阶段不做什么；
4. **D 增量页**给出可独立施工和验收的纵向切片；
5. **四个工作包**进一步说明实施步骤、工程落点、接口和失败恢复。

阅读时先确认当前阶段的范围和出口，再进入具体开发页；不要从单个工作包反推整个产品范围。

## 主题页面与完整归档

- 主题页面是日常阅读和维护的主路径，按产品、架构、交付和参考拆分。
- [完整路线图归档](/reference/full-roadmap)保留长文细节，适合检索、引用和差异核对。
- 归档页与主题页面都位于 `docs/`，不是两个独立文档源。
- 修改事实、协议或阶段门槛时，同时更新主题页面、归档页和英文镜像。

## 维护流程

1. 先修改中文页面，确认结论、边界和链接仍然准确。
2. 在 `docs/en/` 的相同相对路径创建或更新英文镜像。
3. 更新相关入口、侧栏和交叉链接，避免留下失效路径。
4. 运行 `npm run docs:build`，先消除构建错误和站内死链。
5. 在本地预览中检查长表格、代码块、移动端宽度和语言切换。

## 提交前检查

- 正式文档只修改 `docs/`，不要新增第二个文档根目录。
- 中文与英文页面路径对应，标题层级和列表数量一致。
- 交付路线仍保持“总纲 → 开发计划 → Stage → D 增量 → 工作包”的层级。
- README 只保留项目简介、快速开始和文档导航，不复制长篇正文。
- 文档界面不展示版本号、发版徽章或正式发布语气。
- 不提交 `docs/.vitepress/dist`、缓存、本地密钥或无证据的完成声明。

## 文档与发版边界

- 当前文档描述规格、设计判断和开发计划，不代表产品已经发布。
- 开发日志按天记录概述、提交、具体修改与作者，不冒充产品发版说明。
- 只有实现开始并形成可安装版本后，才维护正式版本号和发布说明。
- 文档内容更新直接通过 PR 或提交完成，不另建“文档版”发布流程。
