# Execution Safety and Side-Effect Governance

<p class="lead">All external side effects must pass through the Workspace, Sandbox, network, Credential Broker, outbox, idempotency keys, and Receipts.</p>

## Execution Gateway and Sandbox

Execution Gateway is the security layer between Executors and actual resources. It is responsible for:

- Workspace lifecycle, mounts, and file permissions;
- Sandbox Provider selection, snapshots, and reclamation;
- Network egress policy;
- Credential Broker;
- Effect Dispatcher;
- Quotas, auditing, cancellation, and recovery.

It does not determine business intent and does not replace Policy.

### Workspace Types

| Type | Purpose | Characteristics |
|---|---|---|
| Read-only | Research, review, evidence reading | Non-writable, cacheable |
| Ephemeral | One-off execution | Destroyed on completion |
| Copy-on-write | Modify files while preserving originals | Snapshots, diff, rollback capable |
| Persistent Project | Long-term project workspace | Versioned, quotas, periodic cleanup |
| Remote Workspace | Device or remote execution | lease, encrypted transport, offline recovery |

Start with least privilege and the shortest lifetime by default. After a Task ends, temporary permissions, mounts, and network rules must be reclaimed.

### Isolation Levels

| Level | Typical Implementation | Use Cases |
|---|---|---|
| Process | Restricted process, resource limits | Trusted scripts, lightweight tools |
| Container | Docker/OCI | General code, testing, document conversion |
| MicroVM | Firecracker, etc. | Untrusted code, external files, high-risk research |
| Virtual Desktop | VM + desktop | GUI applications, untrusted desktop software |
| Remote Device | User device agentd | Tasks that must execute on a specific device |

Container is suitable for operational isolation but is not an absolute security boundary against malicious code. Untrusted code, macros, browser downloads, and high-risk files require stronger isolation.

### Sandbox Provider Interface

```ts
interface SandboxProvider {
  create(spec: SandboxSpec): Promise<SandboxHandle>;
  resume(snapshot: SnapshotRef): Promise<SandboxHandle>;
  snapshot(handle: SandboxHandle): Promise<SnapshotRef>;
  exec(handle: SandboxHandle, cmd: CommandSpec): Promise<CommandResult>;
  mount(handle: SandboxHandle, mount: MountSpec): Promise<void>;
  expose(handle: SandboxHandle, port: PortSpec): Promise<Endpoint>;
  destroy(handle: SandboxHandle): Promise<void>;
}
```

Hearth relies on interfaces and does not hard-code business logic into Docker, Firecracker, or any cloud provider's API.

### Network Egress

- Deny outbound traffic by default;
- Enable domain and port allowlists per Task;
- Log requests through a proxy and block metadata addresses and local management interfaces;
- Use read-only network access or a browser proxy for research Tasks;
- Write operations do not go directly to arbitrary URLs generated by the model;
- Downloaded content enters a quarantine zone and is used only after scanning and parsing;
- Attempts to bypass egress are treated as security incidents.

### Credential Broker

```text
User OAuth / API Key
  → Encrypted storage
  → User-authorized scope
  → Run requests short-lived capability
  → Broker validates Mandate / Approval
  → Issues short-lived token or performs execution on behalf
  → Records usage, expires and revokes
```

Principles:

- The model never sees refresh tokens, private keys, cookies, or full secrets;
- Credentials are injected only when a Connector calls an external API;
- Credentials are scoped by account, resource, action, device, and time;
- All usage is audited;
- Revoked immediately when the Task ends;
- Users can revoke all connections at any time;
- Logs, errors, and model context are automatically redacted.

### Effect Dispatcher

External side effects must not be performed directly by the Executor; instead, they should go through typed Effects:

```text
Effect Intent
  → Parameter validation
  → Preview
  → Policy / Mandate check
  → Approval
  → outbox
  → Idempotent execution
  → Receipt / Reconciliation
```

Effects should declare the target system and resources, idempotency key, whether they are reversible, failure compensation, approval level, Receipt fields, timeout, and reconciliation method.

### Security Threat Matrix

| Threat | Defense |
|---|---|
| Prompt injection | Untrusted external content, capability isolation, approval, tool allowlist |
| Unauthorized file/network access | Minimal Workspace mounts, egress allowlist, Sandbox |
| Secret leakage | Broker, short-lived credentials, log redaction, context filtering |
| Duplicate external side effects | Idempotency keys, outbox, Receipt, reconciliation |
| Malicious documents/downloads | Quarantine, scanning, parsing sandbox, macro execution disabled |
| Supply chain attacks | Version pinning, dependency auditing, signing/verification, least privilege |
| Device loss | Revocation, key rotation, local wipe, short-lived sessions |
