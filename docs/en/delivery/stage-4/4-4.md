# 4.4 Control interruption and accept proactive service

## Current status

- **Implemented:** Daily limits from 0 to 50, quiet hours, cooldowns, aggregation windows, temporary pause and resume; the budget snapshot shows usage, limit, and next allowed time; the "Needs you" page collects pending approvals.
- **Still open:** No acceptance yet across 5–10 real proactive tasks for "no more than one interruption per task"; no push delivery statistics or long-term user feedback.

## Goal

Make proactive mode quiet, useful, and controllable, and prove with real tasks that it has not become notification noise.

## How to do it

1. Set a daily interruption limit, quiet hours, and grouping rules for similar events.
2. Provide entries to pause, degrade, or turn off proactive mode at any time, and show which mode is active.
3. Record whether each suggestion was accepted, ignored, or turned into a task, and whether the user found it useful.
4. Test with 5–10 real proactive tasks: no more than one interruption per task on average, and the user understands why they were notified.
5. High-risk actions still require approval, and phone approvals cannot be reused.
6. If the user starts turning off notifications, ignoring approvals, or feeling interrupted, reduce proactivity instead of adding features.
