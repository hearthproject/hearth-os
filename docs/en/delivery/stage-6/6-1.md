# 6.1 Sync and switch across devices

## Current status

- **Implemented:** Each instance has its own `instanceId`; sync peer tokens are shown once and stored as a hash plus an encrypted copy; events are pulled incrementally by sequence and deduplicated; imported events rebuild projections; conflicts keep both records and let the user choose local or remote. The connection runtime isolates subscriptions and execution ownership by generation, an offline outbox retains pending actions, and cached projections expose data freshness.
- **Still open:** Only filtered event projections sync; artifact bodies, workspaces, and local absolute paths are not copied; no real remote node or phone is connected, and two real devices have not completed switch, offline-reconnect, or cross-node reconciliation acceptance.

## Goal

Let the user see the same tasks, artifacts, and memory on a computer, phone, and other devices; switching devices does not lose tasks or create two conflicting agents.

## How to do it

1. Give each device its own identity; the user can view, name, and remove devices.
2. Sync task, artifact, and memory changes by time, and let a returning device catch up only on what it missed.
3. On conflict, keep both records, merge by a clear rule, and ask the user when it cannot decide.
4. Only one device is responsible for executing a task at a time to avoid duplicate actions.
5. Allow queuing while offline and continue after reconnecting; an external action that already happened must not run again.
6. Verify with two real devices: state matches after switching, tasks are not lost, and artifacts open.
