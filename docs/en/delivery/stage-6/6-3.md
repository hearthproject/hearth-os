# 6.3 Back up, restore, and upgrade

## Current status

- **Implemented:** Generates `*.hearth-backup` encrypted archives; scrypt derives the key and AES-256-GCM encrypts it; restore checks `user_version`, schema, and `integrity_check`, rebuilds projections, then copies in a transaction with rollback on failure; the legacy `/api/backup` returns `410`.
- **Still open:** Archives exclude artifact bodies, task workspaces, source bodies, outbox attachments, and screenshots, so they are not a complete portable backup; there is no version-upgrade pipeline or real cross-version restore drill.

## Goal

Let the user fully back up, restore, export, and upgrade without losing tasks, artifacts, or memory when changing machines, versions, or making a mistake.

## How to do it

1. Provide encrypted backup that includes tasks, artifacts, memory, settings, and necessary authority information.
2. Support full restore and selective export, and let the user verify that everything is present after restore.
3. Check version compatibility and space before upgrading, and allow rollback if the upgrade fails.
4. After migration, verify that task state, artifacts, memory, and skills still work.
5. Explain where backups live, how to restore, and what to do if it fails, without requiring the developer.
6. Run one complete migration drill: backup, restore, upgrade, and rollback all succeed.
