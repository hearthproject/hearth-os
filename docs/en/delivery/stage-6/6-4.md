# 6.4 Long-running operation and v1.0 acceptance

## Current status

- **Implemented:** Health snapshots cover uptime, memory, disk, schema, task counts, scheduler, approvals, kill switch, and the latest maintenance; maintenance runs every six hours; diagnostic export excludes paths, keys, and environment secrets; the operations page shows health, maintenance, and backup boundaries.
- **Still open:** No multi-week continuous run, resource-drift data, real v1.0 install/upgrade/migration/exit acceptance, or complete regression matrix across task types.

## Goal

Let Hearth run quietly for the long term and release v1.0 after full capability acceptance. Long-running operation is not just avoiding crashes; resources must stay bounded, state must not drift, and permission must not expand.

## How to do it

1. Add health checks, resource limits, logs, and alerts so the user knows when something is wrong.
2. Regularly clean temporary files, expired tasks, and unneeded caches so resources do not grow forever.
3. Run a continuous test for at least several weeks and check memory, task state, sync, and permission stability.
4. Complete overall acceptance across the main task types, including install, upgrade, backup, restore, revocation, and a privacy explanation.
5. Check that every high-risk action still requires approval and every external action has a receipt.
6. Release v1.0 only when the user can install, use, migrate, and leave independently.
