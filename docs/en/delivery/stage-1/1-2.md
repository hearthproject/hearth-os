# 1.2 Build the complete experience prototype

## Current status

- **Done:** The real web control surface walks through task cards, approval, artifacts, and failure recovery across queued, running, awaiting-approval, complete, failed, and recoverable states.
- **Boundary:** The prototype does not fake success; unknown, failed, and incomplete states are shown honestly.

## Goal

Build a clickable prototype that covers the full user path so the product can be understood before real development starts. The prototype must include task cards, approval, artifacts, and failure recovery, not just a home page.

## How to do it

1. Design four main entries: today, needs you, artifacts, and settings.
2. Cover every important task state: queued, running, waiting for information, waiting for approval, completed, failed, recoverable, and cancelled.
3. Keep one primary action per state and state clearly what the user should do next.
4. Make task cards, approval pages, artifact pages, and failure explanations click through as one complete flow.
5. Use sample data, but never fake success; show unknown, failed, and incomplete states honestly.
6. Ask the first user to walk through it on desktop and phone, then fix the confusing parts.
