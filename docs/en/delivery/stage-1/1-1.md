# 1.1 Define the first scenario and real tasks

## Goal

Define who Hearth serves first and what problem it solves, then turn that problem into a set of real tasks that can be accepted. At the end of this step, the team should be able to state the first user, the first task family, what is explicitly out of scope, and what counts as done.

## How to do it

1. Find a first user who will provide real tasks and feedback, and record the repeated work they most want to hand over.
2. Collect 20–30 real tasks, then select 10–12 with clear inputs, outputs, and acceptance.
3. Choose only one frequent task family with low external risk and easy-to-check results.
4. Write a one-sentence position and a not-now list so the first phase is not pulled in every direction.
5. Record how these tasks are done today, how long they take, and where mistakes happen.
6. Define MVP acceptance: at least 8 real tasks pass, and failed tasks explain why and can be recovered.
