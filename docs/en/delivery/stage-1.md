# Phase 1 · Minimum Complete MVP

## Goal

Phase 1 delivers the smallest complete product that a real user can use every day in a browser. It serves one narrow task family, but it must cover the full path from creating a task through execution, approval, artifact review, and failure recovery. The goal is not broad coverage; it is making the first real path reliable.

This phase has four steps:

| Step | Goal |
|---|---|
| [1.1 Define the first scenario and real tasks](/en/delivery/stage-1/1-1) | Define the first user, task family, non-goals, and acceptance tasks. |
| [1.2 Build the complete experience prototype](/en/delivery/stage-1/1-2) | Walk through tasks, approval, artifacts, and recovery in a clickable prototype. |
| [1.3 Complete the smallest real task loop](/en/delivery/stage-1/1-3) | Let a task execute, ask for approval, produce results, and recover from failure. |
| [1.4 Accept the MVP with real tasks](/en/delivery/stage-1/1-4) | Make the first user independent of the developer. |

## How to do it

1. Choose the first user and the first task family, then define acceptance with real tasks.
2. Walk the full path and every important state through a clickable prototype.
3. Complete the real task loop: execution, approval, artifacts, and failure recovery.
4. Have the first user use it for a week and accept the MVP with real tasks.
