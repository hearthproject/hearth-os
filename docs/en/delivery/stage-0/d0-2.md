## What this increment solves

An end-to-end prototype with four entry points and seven task states that works at both desktop and phone widths.

Stage 0 produces product truth and implementation contracts. Without real tasks, a clickable prototype, and repeatable evaluation, later work mistakes assumptions for facts.

## Before you start

- An empty repository, a recordable set of real work samples, and one first user willing to keep giving feedback.
- Baselines for fully manual work and direct Codex use are observable before the system exists.
- This stage does not connect real sending, payment, deletion, or system-setting changes.
- D0.1 deliverables have passed review; do not enter this increment otherwise.

## Four implementation work packages

> Every work package must produce runnable code, a reproducible check, or a concrete UI result; interfaces alone or pages alone do not count as complete.

### 01 · Four entries and information architecture

Today shows running and recently completed work; Needs you contains approvals, missing information, and takeovers; Artifacts groups previewable files by task; Settings holds workspaces, connections, and notifications. Users first see what needs action, not a capability inventory.

### 02 · Seven states and one primary action

Define reason, next step, and one primary button for queued, running, waiting for approval, needs information, completed, failed, and recoverable. Move cancel, retry, and raw events into details so one state does not present competing primary actions.

### 03 · Complete task script

Use realistic data to connect task creation, plan and progress, approval or missing information, artifact opening, a deliberate failure, and recovery. Include at least one path that cannot recover automatically and must hand over to a human.

### 04 · Usability review and projection map

Ask the first user to complete the path without instructions; record time to first success, hesitation, and misclicks. Maintain a state-to-primary-action-to-projection map so every visible field points to a real contract.

## Engineering map

### Primary directories and modules

- `packages/core/src/schema` — domain entities, state machines, and failure taxonomy
- `packages/eventlog` — event log, projections, and migrations
- `packages/evals` — task set, runner, scoring, and manual review
- `apps/web` — Today, Needs you, Artifacts, Settings, and task-detail prototype
- `fixtures/tasks` — real task samples and failure samples
- `docs/adr` — build-vs-integrate, event model, and frontend projection decisions

### Key interfaces

| Interface | Contract that must hold |
| --- | --- |
| `Event` | id, type, schemaVersion, occurredAt, actor, subject, causationId, correlationId, payload; append-only with immutable history. |
| `TaskCardProjection` | taskId, title, state, primaryAction, reason, lastEventAt, artifacts, budget; the page never reads database columns. |
| `ExecutorEvent` | normalized event, artifact reference, structResult, validation, failureClass, recoverable; executors never write the primary database. |
| `Approval` | effectPreview, scope, expiresAt, decision, idempotencyKey; approval binds to the real action and parameters. |

### Shared verification commands

```bash
pnpm lint && pnpm typecheck
pnpm test && pnpm test:contract
pnpm eval:smoke: rerun all 12 task scores
pnpm dev: inspect desktop and 390px mobile prototypes
```

## Acceptance rehearsal

1. Start hearthd from a clean data directory, open the [D0.2 page](/en/delivery/stage-0/d0-2), and confirm it relies on no browser cache or hand-seeded data.
2. Complete the four work packages in order: Four entries and information architecture; Seven states and one primary action; Complete task script; Usability review and projection map. Preserve the matching test output, screenshot, or artifact version after each package.
3. Reproduce the failure case "A prototype state cannot be mapped". The page must show "The page shows Needs attention and records the unknown projection field and task ID.", then recover with "Add the mapping, update contract tests, and replay the original path."; no duplicate effect or unregistered state is allowed.
4. Restart the service and reopen the task. Runtime state, approvals, artifacts, and recovery entry points must all come from durable projections rather than the current page.
5. Run the shared verification commands above and export the evidence. The completion gate is: A new user can finish the main path without instructions; each state has one primary action; no internal jargon appears; failures give a next step; states map to real projections.

## Deliverables

- Clickable prototype and walkthrough script
- State-action-projection map
- Desktop and phone captures
- Usability observation notes

## Completion decision

- [ ] A new user can finish the main path without instructions; each state has one primary action; no internal jargon appears; failures give a next step; states map to real projections.
- [ ] Deliverables match the contracts and task-card projection with no unregistered field or state.
- [ ] At least one failure path has an actionable recovery, and key actions leave audit events.
- [ ] The demo needs no manual database edit, terminal-only stitching, or permanent mock.

## Failure and recovery

| Case | User sees | Recovery |
| --- | --- | --- |
| A prototype state cannot be mapped | The page shows Needs attention and records the unknown projection field and task ID. | Add the mapping, update contract tests, and replay the original path. |
| A real task cannot be accepted | The task stays in the candidate pool with a reason; it never becomes a build commitment. | Clarify inputs, artifacts, or acceptance, or replace the task. |
| Baselines are not comparable | The task stays out of the evaluation set so distorted data cannot prove value. | Recapture manual minutes, success rate, Token usage, and failure type. |

## Out of scope

- Do not build a complete kernel before the interface.
- Do not substitute document completion for a clickable prototype and repeatable evaluation.
- Do not connect real high-risk external side effects.
