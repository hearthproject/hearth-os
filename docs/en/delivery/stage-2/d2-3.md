## What this increment solves

Users can open pages, collect sources, download authorized files, fill low-risk form drafts, and take over when a CAPTCHA appears.

Stage 2 moves from read-only access toward real writes. Every new authority must first prove provenance, revocation, approval, and receipts still hold.

## Before you start

- Stage 1's local MVP, two task families, approval, idempotency, receipts, and recovery are stable.
- A real email, calendar, document, or data account is scoped for the first user, with a test account available.
- Connectors request least privilege only; every write has preview, approval, and a receipt.
- D2.2 deliverables have passed review; do not enter this increment otherwise.

## Four implementation work packages

> Every work package must produce runnable code, a reproducible check, or a concrete UI result; interfaces alone or pages alone do not count as complete.

### 01 · Browser isolation and network egress

Each Playwright task uses a separate profile, download directory, and temporary session; reuse login state only in an explicitly authorized profile. Domain allowlists, egress limits, download-type checks, and timeouts form the boundary. Pages cannot invoke local commands or reach connector credentials.

### 02 · Untrusted pages and prompt-injection boundary

Mark page text, attachments, and search results as untrusted data and admit them only as structured observations. System policy forbids following page instructions. Pause on patterns such as ignore rules, reveal secrets, or submit now, preserve evidence, and never let page text expand authority.

### 03 · Research evidence, downloads, and degradation

Record visit time, URL, title, visible-text excerpt, screenshot, and downloaded-file hash to form a source list. When a page is unavailable, login expires, or a CAPTCHA appears, degrade explicitly; never treat an empty result as completed research. Quarantine and validate downloads before adding artifacts.

### 04 · Human takeover and action tiers

Provide live takeover for login, CAPTCHA, and complex interaction, then hand back with focus, URL, and next step recorded. Form autofill creates drafts only. Submission, publishing, purchase, and sharing require Effect Preview and approval, write a receipt on success, and reconcile unknown outcomes first.

## Engineering map

### Primary directories and modules

- `apps/hearthd/connectors` — OAuth, cursor sync, source normalization, and revocation
- `packages/connectors` — least-privilege adapters for email, calendar, documents, and data
- `packages/executors/python-sidecar` — parsing, OCR, table cleaning, and format conversion
- `packages/executors/browser` — Playwright worker, download verification, and takeover
- `packages/context` — Context Compiler, source trimming, and sensitive-field filtering
- `packages/memory` — Memory v0, recall reasons, and basic forgetting
- `packages/governor` — Token budgets, tiered routing, caching, and abnormal stops

### Key interfaces

| Interface | Contract that must hold |
| --- | --- |
| `SourceRef` | sourceId, connectorId, accountId, objectId, retrievedAt, scope, contentHash, revocationState; every citation resolves to the original object. |
| `ConnectorEffect` | effectType, target, parameters, dryRun, approvalId, idempotencyKey; connectors execute only registered actions. |
| `ContextPack` | taskId, selectedSources, tokenBudget, redactions, recallReasons; never include content from an unauthorized account. |
| `MemoryRecord` | kind, value, provenance, confidence, sensitivity, observedAt, expiresAt; correction and deletion remain traceable. |

### Shared verification commands

```bash
pnpm test:connectors: authority, expiry, revocation, rate limits, and account isolation
pnpm test:effects: preview, parameter binding, idempotency, outbox redelivery, and reconciliation
pnpm test:browser: injection, downloads, timeouts, takeover, and egress policy
pnpm eval:operator: compare research and daily tasks on manual minutes, Token, and success
```

## Acceptance rehearsal

1. Start hearthd from a clean data directory, open the [D2.3 page](/en/delivery/stage-2/d2-3), and confirm it relies on no browser cache or hand-seeded data.
2. Complete the four work packages in order: Browser isolation and network egress; Untrusted pages and prompt-injection boundary; Research evidence, downloads, and degradation; Human takeover and action tiers. Preserve the matching test output, screenshot, or artifact version after each package.
3. Reproduce the failure case "A connector expires or is revoked". The page must show "The task asks for reconnection and preserves drafts and completed steps.", then recover with "Reauthorize and continue without replaying successful external actions."; no duplicate effect or unregistered state is allowed.
4. Restart the service and reopen the task. Runtime state, approvals, artifacts, and recovery entry points must all come from durable projections rather than the current page.
5. Run the shared verification commands above and export the evidence. The completion gate is: Research tasks have traceable sources; page content cannot expand authority; downloads verify; high-risk submissions never auto-run; takeover resumes safely.

## Failure and recovery

| Case | User sees | Recovery |
| --- | --- | --- |
| A connector expires or is revoked | The task asks for reconnection and preserves drafts and completed steps. | Reauthorize and continue without replaying successful external actions. |
| Page content tries to expand authority | The task pauses, marks the content as untrusted, and asks the user to confirm. | Drop the injected instruction, preserve source evidence, and regenerate a safe plan. |
| A write result is unknown | The UI shows Reconciling, neither success nor blind retry. | Query the test account or external system, then write a receipt or compensate. |

## Out of scope

- Do not expand channels before one connector proves permission, idempotency, and receipt behavior.
- Do not automatically perform high-risk submissions, public publishing, or irreversible sharing.
- Do not let page content, attachments, or model output change authority.
