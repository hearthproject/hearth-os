# 2.1 Connect read-only information sources

## Current status

- **Implemented:** Local files, knowledge base, and public web sources; domain allowlists; source status, read time, errors, incremental reads, deduplication, disconnect, reconnect, and clear; IMAP read-only sync of the latest 20–50 messages into Sources without marking them read.
- **Still open:** Calendar shows only "not configured"; real mail accounts, TLS, app passwords, throttling, and permissions still need manual acceptance.

## Goal

Let Hearth safely read the sources the user uses every day, and show the source, time, and permission clearly. This step is read-only: no sending, editing, or deleting.

## How to do it

1. Connect one email source, one calendar source, one file source, and one knowledge base first; do not open everything at once.
2. Record source, time, account, and permission for every read so the user can trace where information came from.
3. Remove duplicates and update only what changed instead of rereading everything.
4. When login expires, permission is missing, or a source is unavailable, tell the user clearly instead of failing silently.
5. Provide an entry to disconnect a source and clear what was read from it.
6. Verify with a real account: the user can see what was read and confirm that nothing was written.
