## 怎么读这些日志

- 想知道**现在能做什么**，先看 [Day04](/log/day-04)，再回到[交付总览](/delivery/)核对哪些能力有真实验收。
- 想知道**阶段一如何被证明**，读 [Day03](/log/day-03) 和[第一阶段 MVP 验收](/delivery/mvp)。
- 想知道**文档站为什么改了**，读 [Day02](/log/day-02) 和[文档地图](/reference/source-map)。

## 记录规则

1. 只写当天真实发生的事：提交、变更规模、通过的检查和失败的证据。
2. 区分“代码闭环”“自动测试通过”和“真实验收通过”，三者不能互相替代。
3. 提交表使用真实 SHA 和 diffstat，不合并、不补写、不美化。
4. 当天没有跨过的边界写进“边界与下一步”，留给下一篇日志核对。
