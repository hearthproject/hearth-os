2026-11-08 是 Hearth 把已有能力收敛成入口的一天。当天 40 次提交涉及 91 个文件（+9,076/−329）：凌晨先修掉模型档案、路由、会话启动和执行器就绪中的断点，再用可重复的浏览器 E2E 固定行为；随后把方法推进到 schema 11 的可审计应用，把首次运行、主动提醒、记忆召回、飞书长连接和 SMTP/IMAP 邮件依次接到真实界面。测试从 Day04 的 54 个文件、296 个测试增长到 61 个文件、381 个测试。

今天的主线不是再加一个页面，而是让已有闭环能被新用户走通、能被手机上的审批接住、能被真实邮件账户验证。每一步仍然保留同一条边界：通知只负责让人看到，批准仍走同一个审批与效果账本；没有真实账户时，不伪造送达或回执。

## 凌晨：先修闭环，再固定验收

| 方向 | 结果 |
|---|---|
| 模型档案与密钥 | 删除档案前清空聊天档案指针；更新时把空 API Key 写成空密文，旧密钥不再复活；模型注册表校验失败返回 4xx，而不是 500 |
| 就绪判定 | `native`、Codex、DeepSeek Harness 的就绪状态统一从执行时使用的模型绑定推导，界面、路由和调度器共享同一健康结果 |
| 会话启动 | 新对话先读取服务端默认值再启用输入框；处理失效或已删除的会话；输入法组合期间忽略 Enter，不再误发消息 |
| 设置保存 | 空命令或路径按未配置处理，保存不再失败或清掉旧值；保存前加载审批与路由设置，避免把默认值写回；侧栏健康状态和执行器标签与运行时对齐 |
| 调度恢复 | 排队任务在执行器不可用时保持可恢复；调度异常被隔离，不可用执行器不能拖垮服务 |
| 浏览器 E2E | 新增隔离数据目录的可重复 E2E，覆盖首次运行、实时聊天、任务创建、会话切换与恢复、模型密钥掩码/清除、执行器设置、窄屏和浏览器控制台错误；离线模式跳过需要实时模型的场景 |

## 技能：方法变成可审计的执行输入

| 方向 | 结果 |
|---|---|
| schema 11 | 新增 `method_applications` 审计表、任务方法固定（pin）和候选生成/指纹列；旧数据库迁移测试保留任务、运行和检查点 |
| 方法上下文 | 方法提示渲染为有界、不可信块；固定方法与模板方法按确定性顺序解析；只有方法块真正进入提示时才记录一次应用 |
| 执行注入 | 选中的方法注入任务、跨执行器接管和修复提示；没有实际包含方法块时不写应用记录，避免审计与执行不一致 |
| 证据门槛 | 基线与试跑按模板配对，至少 2 个基线加 2 个试跑才能给出改进结论；试跑必须匹配逐次运行的应用、版本一致，且任务不能已被其他方法试跑 |
| 代次与回退 | 采用的方法晋升为编号代次，旧代次被取代；回退新代次时恢复上一代，不再只有一个可变状态 |
| 候选与自动学习 | 从上下文账本提取有序工具、决策和产物，按指纹合并候选并保留单一来源任务；增加方法学习开关，终态任务后尽力生成候选并记录试跑证据 |
| 技能界面 | 方法页在界面上统一为“技能”，恢复导航，并补齐代次生成、自动学习设置、试跑任务创建、配对评估、应用审计和代次回退 |

## 上午：首次运行、提醒与记忆

| 方向 | 结果 |
|---|---|
| 首次运行 API | 新增首次运行状态与就绪检查；只有“没有向导状态且聊天模型未配置”时才强制进入，完成、跳过和重置都有独立状态 |
| 四步向导 | `/welcome` 把服务商选择、连接测试、执行器检查、记忆与主动偏好、进入聊天串成一条路径；保存模型时一次完成建档、设为聊天模型并自动绑定原生执行器 |
| 导航与提醒 | 主导航直接暴露“需要你”“记忆”“技能”“邮件”；新增通知中心，把待审批和主动建议转成可读提醒，页面打开时可用应用内 toast 和可选的浏览器桌面通知 |
| 主动扫描 | 服务启动后先扫描一次，之后每 5 分钟扫描；任务、审批、外部效果和来源变化触发 2 秒防抖扫描，仍受开关、主动级别、每日上限、安静时段、同类冷却和去重约束 |
| 送达语义 | 建议只有真正送达时才发出 `delivered` 事件；页面关闭后不承诺推送，没有通知通道时回到应用内“需要你”；飞书消息和桌面通知都不能改变授权 |
| 记忆召回 | 直接聊天按对话召回相关记忆，并通过 SSE `memory` 事件提示召回数量；召回失败不阻塞回答；记忆捕获只发生在任务终态，避免中途状态被重复写入 |

## 飞书与真实邮件

| 方向 | 结果 |
|---|---|
| 飞书长连接 | 自建应用长连接网关，包含租户令牌缓存、事件解析、图片/文件下载、自动重连、open_id 白名单和连接状态；不需要公网回调地址 |
| 任务与审批 | 任务状态和一次性审批摘要发送到已映射会话；`/approve`、`/reject` 只接受白名单 open_id，并按当前会话关联任务的前缀匹配审批；拒绝不产生外部副作用 |
| 飞书设置 | 设置页新增 App ID/Secret（加密保存）、白名单、飞书/飞书国际版域名、启停和连接状态 |
| 邮件账户 | SMTP/IMAP 主机、端口、TLS、账户和口令保存到本机；口令经 AES-256-GCM 加密，编辑时留空保留原口令；支持连接测试、更新和删除 |
| SMTP 发送 | 发件箱草稿选择 SMTP 账户后生成 `email.smtp-send` 一次性审批：预览发件人、收件人、抄送/密送、主题、正文和不可撤回影响，TTL 为 10 分钟；批准后由效果账本发送并保存 `receipt.json` |
| 幂等与不确定 | 发送复用审批参数哈希、效果幂等键、确定性 Message-ID 和本地回执；目录先用 `sending.json` 占位，已有目录但没有回执时进入不确定状态，不盲目重发 |
| IMAP 同步 | 只读打开 INBOX，读取最近 20–50 封，不标记已读；按 Message-ID 去重写入来源，正文进入来源内容目录；默认每 15 分钟同步，账户可关闭 |
| 邮件工作台 | 账户、收件箱和写信三个视图；收件箱读取同步后的来源条目，写信只创建草稿，批准卡片显示邮件预览；本版没有附件选择 UI |

## 边界与下一步

- 邮件默认仍写本机发件箱；配置 SMTP 后才可提交真实发送审批。真实账户、退信、垃圾邮件语义、OAuth2 和附件选择 UI 尚未人工验收；IMAP 只读最近 20–50 封且不标记已读。
- 飞书长连接提供文本消息和一次性审批命令，但不是手机 PWA、系统推送或完整远程接管；真实租户、限频、重连和卡片按钮方案仍未验收，页面关闭后不会推送。
- 方法自动学习与 2+2 证据已进入调度和审计，但仍缺长期生产对照、错误方法演练和候选质量数据；不能把“能生成候选”当作“方法已经变好”。
- 首次运行只检查模型、执行器、记忆和主动服务，没有覆盖备份、安全和数据迁移；向导查询失败或非根路由不会强制拦截，属于有意保留的恢复路径。
- 主动扫描每 5 分钟运行并响应领域事件，但页面关闭后没有系统级推送；通知只是提醒，批准仍走同一条一次性审批链。
- 首次运行 API 测试对启动时延较敏感，并行负载下曾出现一次 5 秒超时；重跑通过，但测试超时余量仍需调整。
- 阶段二至六的真实验收状态没有变化：真实邮件/日历、飞书租户、手机入口、桌面高风险动作、记忆生产对照、双设备切换和数周连续运行仍然留空。
- 下一阶段继续按[交付路线](/delivery/)补真实证据，不新增只证明“页面存在”的入口。
