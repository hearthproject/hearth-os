2026-11-09 是 Hearth 把产品入口、任务工作流和评测基础设施同时向前推的一天。当天 89 次提交涉及 445 个文件（+24,538/−1,793）：上午补齐任务追加、Git 工作台、审批预览、PWA 壳和浏览器 E2E，随后把记忆的来源、合并、遗忘和技能生命周期做成可审计记录，最后为评测 case、控制台、运行编排和人工复核建立第一套完整控制面。

今天的主线不是增加更多概念，而是让已有能力能被日常使用、能被证据复核、能被独立评估。页面可以看起来完整，但任务追加必须受调度约束，技能必须保留权限与代次，评测控制台必须能追到每次运行的真实轨迹。

## 交互与任务工作流

| 方向 | 结果 |
|---|---|
| 任务追加 | 运行中可以排队“轮后继续”，或中止当前轮并带补充信息重跑；两种模式都保留任务、产物和既有证据 |
| Git 工作台 | 任务详情展示工作区/分支差异、文件列表、提交、文件预览、PR 与 CI 检查状态，不把终端输出当作最终结果 |
| 审批与工具 | 原生执行器在敏感工具前暂停；写文件、命令、联网和截图在必要审批下等待，批准后继续，拒绝后跳过并留下原因 |
| PWA 与导航 | 新增可安装 Manifest、应用图标、离线应用壳、移动底部导航和命令面板；窄屏下任务与审批页面可操作 |
| 截图与首页 | 用隔离实例生成 README 与文档站截图，首页改为产品界面、定位和当前状态，不再只讲抽象架构 |

## 记忆、技能与执行输入

| 方向 | 结果 |
|---|---|
| 记忆来源与信任 | 记忆记录来源、可信度、污染状态、敏感度、有效期和用途；召回按范围和信任状态过滤 |
| 记忆合并 | 合并只处理可解释的重复与冲突，保留来源链、版本和报告；不把模型摘要当作新事实 |
| 遗忘传播 | 遗忘覆盖投影、版本、事件、召回审计、设备同步、派生记忆和合并记录，并留下墓碑防止旧内容复活 |
| 技能生命周期 | 技能包支持导出、导入、检查、固定、归档和恢复；采用的方法可转成带权限范围的技能 |
| 自动管理 | 终态任务后尽力生成方法候选，过期技能可清理并回退；自动学习仍受开关和证据门槛约束 |

## 目标、完成与评测控制面

| 方向 | 结果 |
|---|---|
| 目标契约 | 暴露目标创建、查询、验收条件、预算、截止时间、停止条件和复核策略 API |
| 完成判定 | 新增证据驱动的完成判定，逐项检查验收条件、证据、缺失项和禁止动作；目标型任务关闭前必须有结论 |
| case 目录 | 建立 case 目录加载器、旧清单兼容、邮件/日历/文档/研究/代码/网页/桌面/跨应用样例 |
| 评测控制台 | 新增仪表盘、case 目录、实验启动、运行轨迹、人工复核、实验比较和系统状态页面 |
| 评测服务 | 评测生命周期持久化、运行编排、人工复核、控制面 API 和 artifact 边界形成代码闭环 |
| 文档 | 评测 Agent 工作流、README 首页和产品截图更新；评测 case 与主产品模板仍暂时共用部分结构 |

## 边界与下一步

- PWA 壳、移动底部导航和离线应用壳只是入口，不是手机配对、系统推送或远程接管；这些仍未验收。
- 任务追加按轮边界生效，不是向正在生成的 token 流实时注入；Git 工作台依赖真实仓库和凭据，未做多仓库压力验收。
- 记忆合并、遗忘传播和技能生命周期已有自动测试，但没有真实长期个人数据、错误记忆演练和生产方法对照。
- 完成判定已接入目标和调度，但主观质量、真实业务影响和跨设备交接仍需人工验收。
- 评测控制台、case 目录和服务形成代码闭环，但真实实验尚未运行；次日这些内容会迁到独立仓库，主仓库只保留桥接。
- 阶段二至六的真实账户、真实设备、手机入口和长期运行验收没有变化。
