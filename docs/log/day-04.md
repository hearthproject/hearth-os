2026-11-06 是 Hearth 从“阶段一 MVP”扩展到完整本机 Agent OS 的一天。当天 102 次提交涉及 432 个文件（+35,228/−4,327），把聊天优先界面、原生 Agent Runtime、四协议模型接入、来源与文档处理、本地发件箱、Windows 桌面助手、主动服务、记忆、方法进化、增量同步、租约、kill switch、加密备份、健康维护和脱敏诊断全部落到了可运行代码与自动测试中。

11 月 7 日，Day04 继续把执行器层收敛到同一条链路：当天 42 次提交涉及 165 个文件（+28,030/−1,845），建立七执行器共享注册表、SQLite 统一模型注册表、任务级上下文账本与执行器接管、失败诊断与路由回退，并把设置页重组为执行器、模型、上下文和数据四个分区。Qoder、WorkBuddy、Kimi 和 DeepSeek Harness 接入统一适配层；只作为过渡方案出现的 ZCode 集成被移除。

这两天没有用“页面存在”代替闭环：服务端、API、投影、执行器边界和测试一起提交。测试从 51 项扩展到 54 个测试文件、296 个测试；`npm run typecheck`、`npm run build` 和 `npm run docs:build` 均通过。阶段二至六仍然只算部分完成，原因不是代码没写，而是还缺真实账户、真实设备和长期运行验收。

## 11 月 7 日：执行器与上下文收敛

| 方向 | 结果 |
|---|---|
| 七执行器注册表 | `native`、`codex`、`deepseek-harness` 为一等执行器，`hermes`、`qoder`、`workbuddy`、`kimi` 为外部执行器；共用启动解析、健康探测、托管安装、模型绑定、上下文采集和设置界面 |
| 统一模型注册表 | 模型档案 `model_profiles` 与执行器绑定 `executor_model_bindings` 落入 SQLite；旧 `model-settings.json` / `executor-settings.json` 启动时导入并备份到 `.hearth/backups/legacy-dev/`；API Key 经 AES-256-GCM 加密，设置页只显示掩码 |
| 协议约束 | Codex 固定 OpenAI Responses；本地地址不进入统一模型管理；非原生执行器必须显式绑定模型；服务端强制校验执行器与协议兼容性 |
| 上下文账本 | 所有执行器把消息、工具调用、结果、检查点和通知写入 `context_items`；`executor_event_id` 去重，大正文落 `.hearth/context/blobs/`，任务摘要写入 `task_context_state` |
| 失败诊断与接管 | 先用规则区分非执行器故障与执行器故障；用 Hearth 当前聊天模型诊断；完全权限且低风险时自动切换，必要审批时只询问是否切换；默认最多接管两次，交接包带 `context_watermark_seq` |
| 路由与选择 | 对话输入框改为统一执行器选择器；对话级选择优先于全局默认；不可用或缺少能力时回退到任务匹配执行器；任务型请求尊重显式选择，不再依赖路由器模型 |
| 设置与数据 | 设置页重组为执行器、模型、上下文、数据四个分区；模型注册表和存储信息通过 API 暴露；SQLite schema 推进到 10；Codex 使用配置的 home 与注入环境，健康检查只报告托管绑定而不改写配置 |
| 执行器适配 | DeepSeek Harness 走官方 SDK/JSON-RPC；Hermes 走统一外部适配器并续跑上次 CLI 会话；新增 Qoder、WorkBuddy、Kimi 适配器；移除 ZCode |
| 文档与界面 | 新增存储与上下文架构文档（中英），更新执行器文档和 README；应用外壳适配视口，设置页提升可读性；聊天把模型推理与回答分开流式显示 |
