# 委派、交接与沙箱

<p class="lead">Hearth 需要把一段有界工作交给另一个执行者，同时不把任务所有权、预算和证据拆散。委派、交接和沙箱解决的是同一件事：让工作可以继续，但权限不能顺手扩大。</p>

## 设计目标

委派不是生成一个不受约束的新 Agent。子任务必须有明确目标、预算、工作区策略和失败边界，并通过同一条调度链路推进。父任务保留最终责任，子任务只完成被授权的那一段工作。

跨执行器继续时，接收方不能靠重新阅读聊天记录猜测上下文。交接包要带上目标、下一步、验收条件、已有证据、权限子集和上下文水位；旧执行者在交接后不能继续写入新状态。

沙箱首先是一组拒绝规则。路径不能越界，网络域不能超出授权，进程不能不在白名单，凭据不能进入模型上下文。沙箱发现越界时应该失败并留下原因，而不是让执行器自行解释或绕过。

## 单层持久委派

当前委派是单层的：父任务创建一个或多个有界子任务，不再生成递归的子 Agent 团队。子任务记录预算、工作区策略、父子关系和失败状态，生命周期由调度器推进。

工作区策略分为只读、隔离写入和共享读取。只读任务只能读取授权材料；隔离写入在独立工作区内产生结果；共享读取允许多个任务读取同一来源，但写入仍受各自权限约束。父任务获得子任务结果时，先核对预算、证据和产物，再把结果纳入自己的完成判定。

子任务使用租约和心跳保活。执行者暂停、崩溃或失去租约时，调度器可以回收并重新排队，而不是让父任务永久等待。外部副作用受委派守卫约束：已经确认发生的动作不能因为重跑而重复执行，不确定的动作进入对账。

## 交接包

执行器切换或任务暂停后继续时，系统准备一份可审阅的交接包。交接包记录目标、当前状态、下一步、验收条件、证据引用、已知失败、权限子集、来源上下文水位、生成代次和脱敏信息。

交接包只能缩小权限，不能扩大父任务授权。接收方在恢复执行前核对生成代次和上下文水位；旧代次迟到的结果不能覆盖新状态。交接验证会检查目标、下一步、验收项、证据、权限和代次是否完整，缺少必要项时拒绝继续，而不是带着空白重新开始。

交接产物要与终态证据一起保留。执行器关闭后，用户仍能看到哪些证据已经取得、哪些验收条件尚未满足，以及下一位执行者应该做什么。

## 沙箱边界

| 边界 | 检查内容 | 越界结果 |
|---|---|---|
| 工作目录 | 当前目录、读取根和写入根是否在授权范围内 | 拒绝执行并记录路径 |
| 读取与写入 | 请求的文件路径是否落在允许根目录内 | 拒绝读取或写入 |
| 网络 | 请求域名是否属于任务声明的域名 | 拒绝联网 |
| 进程 | 命令是否在允许的进程白名单中 | 拒绝启动 |
| 凭据 | 执行环境是否只能获得短期能力，而不是长期原始密钥 | 拒绝注入或脱敏 |
| 策略后端 | 声明的沙箱后端是否可用 | 不可用时失败关闭 |

沙箱检查按顺序完成，任何一项失败都不会继续执行。检查结果会留下可解释的记录，用户能看到是路径、网络、进程还是凭据边界阻止了动作。

渠道入站也使用幂等边界。飞书消息、文件或图片重复投递时，系统按渠道事件标识去重，避免同一条消息生成两个任务、两次审批或两个子任务。

## 设计取舍

- **单层而不是递归团队。** 先把父子任务、预算和交接做可靠，再考虑更复杂的协作；不为了展示多 Agent 而引入失控的权限树。
- **交接包而不是共享聊天。** 聊天记录包含大量无关内容，交接包只带完成下一段工作所需的证据和约束。
- **权限子集而不是复制权限。** 交接可以少给，不能多给；需要扩权时回到用户审批，不由执行器自行决定。
- **失败关闭而不是尽力继续。** 沙箱后端不可用、路径不明确或凭据边界不清时，宁可停下。
- **本地策略检查不是强隔离。** 当前本地后端主要验证路径、网络和进程规则，不能把普通进程当成恶意代码的绝对安全边界。

## 当前边界

单层委派、租约心跳、暂停回收、交接验证、权限子集、路径/网络/进程/凭据检查和渠道幂等已经形成代码闭环。尚无递归委派树、强隔离容器或虚拟机后端、真实远程节点调度和真实多执行器压力验收。
