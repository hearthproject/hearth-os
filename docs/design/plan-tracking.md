# 计划与任务清单设计说明

本文描述"先计划、再自动执行、界面跟踪清单"的设计。当前实现分四步推进，本文同时记录范围与决策。

## 1. 目标

- 智能体先提交结构化计划，再在同一个任务中自动按顺序执行。
- 每一步的状态（待办、进行中、已完成、已取消）实时同步到界面，形成清单跟踪。
- 高风险步骤才弹出确认，其余步骤自动执行。

## 2. 现状

- `submit_plan` 只接受一段自由文字，返回 `action: "plan"`。
- 运行时收到 `action: "plan"` 后直接结束任务，状态为 `waiting_input`，等待用户确认。
- 待办由 `todo_write` 维护，整体替换，不发出独立事件，界面不展示。

## 3. 决策

| 问题 | 决定 |
| --- | --- |
| 计划提交后是否自动执行 | 自动执行。只有高风险步骤弹出确认。 |
| 步骤数量上限 | 最多 20 步。超过时拒绝提交，要求拆成子任务分别提交。 |
| 计划模式是否保留 | 保留。计划模式下仍然只读，提交后结束任务等待确认，行为不变。 |
| 清单显示位置 | 对话的运行区域内联显示（方案 a）。 |

## 4. 分步实施

**第 1 步：结构化计划与连续执行**（本次实施）

- `submit_plan` 新增可选参数 `steps`（数组，每项包含 `title`，可选 `detail`），上限 20 项。
- 在构建模式下提交带 `steps` 的计划：写入待办（状态为 `pending`），不结束任务，直接进入执行。
- 计划模式下提交：沿用原行为（结束任务、等待确认），同时把步骤写入待办，供确认后执行时使用。
- 超过 20 步：返回错误，提示拆成子任务。

**第 2 步：状态事件与界面清单**（已实现）

- 运行时在每次工具执行结束后比较待办是否变化，变化时发出 `todos.updated` 事件，携带完整清单。
- 服务端把事件转为 `task.progress`（`kind: "todos"`），清单放在 `detail.todos` 中，整体替换，不累加。
- 前端 `InlineRun` 取最新一次清单，在运行区域显示"已完成 N / 共 M 项"及各项状态图标（`TodoChecklist` 组件）。清单事件不进入步骤列表。

**第 3 步：高风险确认**

- 为步骤增加风险标记（如删除文件、推送远端、修改依赖），标记为高风险的步骤执行前弹出确认。
- 其余步骤自动执行。

**第 4 步：提示与引导**

- 在构建模式的提示中说明：复杂任务先用 `submit_plan` 提交结构化步骤，执行中用 `todo_write` 更新状态。

## 5. 与其它设计的关系

- 数据结构复用 `AgentTodo`（见 `packages/agent-runtime/src/types.ts`）。
- 之后的 `write_todos`（增量更新、取消原因、插入新步骤）是第 2 步的前置条件之一。
- 子任务能力依赖"超过 20 步即拆分"的约定，以及待办的 owner 字段（后续多智能体工作再加）。

## 6. 未解决问题

- 计划步骤被取消或新增时，是否要求模型写原因，还是由工具强制。
- 计划模式提交的步骤，在确认后是否需要用户修改再执行。
- 风险标记由模型自己声明，还是由工具根据命令和路径推断。
