# 入口与交互

<p class="lead">Hearth 的入口不是无限滚动的聊天记录，也不是一张塞满任务卡的管理后台。它以聊天为起点，把一次任务的轨迹、审批、产物和恢复收进对话里的运行卡与右侧产物面板，让用户知道系统在做什么、哪里需要自己，以及结果是否可信。</p>

## 设计目标

入口要解决的是注意力，不是信息量。打开 Hearth 时，用户应该先看到自己刚才在说什么、系统正在执行什么、哪一步需要决定，而不是在多个页面之间寻找任务编号。

对话适合表达意图，但一次长任务需要状态、检查点、产物和失败恢复。0.3.4 的选择是把任务“内联”进对话：用户不必离开上下文去看另一个任务页，展开运行卡就能看到执行轨迹；需要文件时再打开右侧“对话产物”面板。

网页、命令行、手机和即时消息共享同一套任务事实。用户可以在电脑上发起，在手机上批准，再回到网页查看产物；设备只是观察和操作方式，不会产生互相对不上的状态。

通知必须克制。系统只在真正需要判断、授权或接管时提醒，并且一次提醒要说清楚发生了什么、建议怎么做、不处理会有什么后果。普通进度留在运行卡里，不占用用户时间。

## 首次运行与主导航

全新实例打开根路径时会进入 `/welcome` 四步向导：选择服务商并测试连接、检查执行器、选择记忆与主动偏好、进入聊天。向导通过一次模型设置请求完成建档、设为聊天模型，并自动绑定原生执行器。只有“没有向导状态且聊天模型未配置”时才强制进入；查询失败、其他路由和已完成设置的用户都不会被挡住。

主导航只保留两个主入口：

- **聊天**：对话、内联运行卡、审批与右侧产物面板。
- **资料库**：文件、记忆、资料和技能的统一树，带检索、预览、回收站和遗忘传播；页头「交接」从活跃记忆生成接手摘要、原记录和导出包，存进「资料 / 交接」或导出给下一个执行者或账号。

邮件、定时任务和连接收在“更多”；设置在底部。这个收缩是故意的：任务列表、任务详情和“需要你”收件箱已经下线，避免同一份状态在三个页面重复出现。

## 运行卡与产物面板

运行卡不是一条“正在处理”的占位消息。它按阶段显示：

- 当前执行器和预算；
- 叙述、工具调用、命令与文件改动摘要；
- 等待审批的参数预览；
- 失败原因、可恢复动作和结算状态；
- 产物与最终回答。

任务完成后，卡片默认折叠成一行摘要；展开可以看完整轨迹。右侧“对话产物”按需打开，列出产物、后台任务和附件，支持文本、Markdown、代码、JSON/CSV、图片与 PDF 预览；用户可以把产物另存到桌面或任意目录，但执行器写入仍限于任务工作区。

审批发生在卡片内部，不另开页面。工作区内可逆文件写入自动执行；shell、删除、邮件、桌面、陌生域名和提交/上传/下载类动作需要一次性授权，参数指纹绑定当次动作。文件或页面在批准后发生变化时，授权失效并要求重新确认。

## 多入口与提醒

通知分两层：页面打开时使用应用内 toast，并可选申请浏览器桌面通知；页面关闭后不承诺推送。需要离开电脑查看任务时，使用微信 IM：任务受理与最终结果会发到固定的「微信IM」会话，但审批仍需回到 Hearth 内完成。

Web 端提供可安装 PWA 壳、离线应用壳和移动底部导航；手机配对、系统级推送和远程接管仍未验收，因此不能把现有 PWA 壳写成完整移动客户端。

邮件工作台提供账户、最近邮件和写信三个视图。IMAP 只读同步把最近邮件写入来源，不标记已读；写信只创建草稿并生成一次性审批，批准后才通过 SMTP 发送并保存回执。真实账户、退信语义和附件选择仍需人工验收。

## 设计取舍

聊天与任务不是二选一，而是“对话承载意图，运行卡承载证据”。只做聊天会让人不断向上翻找；只做任务列表会丢掉意图上下文。Hearth 把两者放在同一条时间线里。

| 取舍 | Hearth 的选择 | 原因 |
|---|---|---|
| 主界面 | 聊天 + 内联运行卡 + 右侧产物面板 | 保留意图上下文，同时能展开查看执行证据 |
| 任务入口 | 对话内发起，不再单独维护任务列表 | 一处状态只出现一次，减少重复页面和失同步 |
| 多入口 | 统一归一化来源、身份和去重 | 同一个请求从邮件、网页或消息重复到达时只处理一次 |
| 状态来源 | 服务端记录重建界面 | 刷新、重连后仍然一致，不依赖浏览器临时状态 |
| 打断策略 | 按风险和等待时间决定 | 高风险动作尽快提醒，普通进度不制造通知疲劳 |
| 手机范围 | 审批、查看、接管和简单发起 | 手机适合短动作，复杂编辑仍留在桌面端 |

界面只发出命令，不直接改写任务事实。用户点击“批准”后，系统重新检查审批是否过期、参数是否变化、授权范围是否仍然有效，再把结果写入记录并更新界面。即使两个入口同时操作，也不会出现界面显示成功但实际没有执行的情况。

失败时界面要诚实：连接中断显示离线，状态不确定显示正在核对，执行器失败显示原因和可恢复动作，不能把“还在尝试”伪装成“已经完成”。用户接管时，系统先暂停自动执行，保存当前进度，再把可操作范围交给用户。
