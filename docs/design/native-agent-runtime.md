# 原生 Agent Runtime

<p class="lead">Hearth 的原生执行器不是一段“把任务发给模型”的提示词，而是一个可暂停、可恢复、受权限和预算约束的通用执行内核。它以 Pi 的简洁工具循环为起点，并借鉴 DeerFlow 的长任务编排和 OpenCode 的通用执行面，由 Hearth 自己实现，不引入这些项目的运行时。</p>

## 为什么自研 Runtime

聊天模型可以回答问题，但不能直接证明工作真的完成。要形成闭环，系统必须自己保存消息、执行工具、累计用量、限制权限、写入检查点，并在缺少产物时继续补齐。把这些职责交给外部 CLI 会让任务状态、权限和恢复语义分裂在两个进程里。

Hearth 因此保留两层执行能力：

| 执行器 | 定位 | 典型任务 |
|---|---|---|
| `native` | 通用单 Agent；工作区、仓库或代码意图任务自动启用 `coding` profile | 整理资料、生成文档、分析网页、通用文件处理、仓库修改、测试与验证 |
| `codex` | 面向代码仓库和多文件工程的专长执行器 | 修复项目错误、修改代码、运行测试、提交改动 |

原生执行器是默认的通用路径，并通过 `coding` profile 承担大多数仓库任务；Codex 仍是需要其专长运行时的显式选择。两者不会在失败后静默互换。编码 profile 的详细契约见 [Coding Harness](./coding-harness.md)。

## 轻量拟稿与修订

不需要读取附件、保存文件或外部操作的请假信、邮件草稿等请求，直接在聊天中生成一个简短版本；补充姓名、时间或语气时沿用当前草稿，不创建任务，也不加载任务经验与个人上下文包。明确要求保存单个 Markdown/文本文件的纯文字拟稿，使用一次生成、一次授权保存的专用路径；写入成功即结束，失败不换工具自动重试。

恢复原生任务时刷新系统指令、任务提示和本轮输出目录，保留历史工具记录及用户补充。旧目录只属于历史，不再作为写入目标。同一规范化路径连续两次被权限边界拒绝，会停止跨工具尝试并提示当前输出目录。

个人上下文包按最终序列化文本估算用量，省略项只显示短引用，整体受上下文预算限制。普通工作默认排除包含评测运行约束或评测产物路径的经验记忆，不删除原始记忆。

“预算翻倍”保留执行模式；“升级标准／深入模式”更新执行模式并提高到对应额度（不降低已扩展的额度）。两者都保留累计用量，升级后的额度仍不足时要求使用预算扩展。

## 内核形态

```text
任务 + 用户补充
      ↓
 系统提示 + 消息历史
      ↓
 模型流式回合 ──→ 文本回答 / 工具调用
      ↓                    ↓
 Token 与预算累计      执行受权限约束的工具
      ↓                    ↓
  写入检查点 ←──── 工具结果回填
      ↓
 完成 / 暂停等待输入 / 预算耗尽 / 取消
```

每轮只做一件事：模型返回内容与工具调用，Runtime 执行工具并把结果作为下一条消息回填。模型只输出文本不再被视为完成；任务完成的唯一可信信号是模型调用 `finish_task`，以及声明的产物确实存在且非空。

## 消息与协议

`@hearth/model-client` 负责四种协议：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Gemini。`model-agent.ts` 把它们统一成同一种流式 Agent 回合：文本增量、工具调用、工具参数拼接、结束原因和用量。

这样更换模型提供商不会改变 Runtime 的工具循环，也不需要为每家模型复制一套调度逻辑。原生执行器要求模型支持工具调用；不支持时直接给出明确错误，不伪装成成功。

## 通用工具面

| 工具 | 用途 | 默认边界 |
|---|---|---|
| `read_file`、`read_document`、`list_files`、`search_text` | 读取文本、PDF、DOCX、XLSX、CSV、JSON 和 HTML | 只能访问任务工作区与授权目录；文档大小和返回字符数有上限 |
| `glob`、`grep` | 按模式定位文件，用 RE2 兼容正则搜索 include/exclude 范围 | 有结果数、文件大小、扫描时长预算；拒绝路径逃逸 |
| `write_file`、`edit_file`、`apply_patch` | 生成、预览修改、原子应用补丁、移动和删除文件 | `edit_file` 支持 dry-run 差异预览；补丁先全量预校验，再一次性写入，避免部分成功 |
| `write_spreadsheet`、`write_document` | 生成 XLSX/CSV 和 DOCX 办公文件 | 只能写入授权目录，并经过文件动作审批 |
| `shell` | 运行必要检查命令 | 只在工作区任务中授权；默认进入 AppContainer 沙箱（`read-only` / `workspace-write`），网络 `deny` / `open` 显式选择；完整输出写入任务日志、只回填尾部；超时杀死整个进程树；支持 `pty` 交互会话与 `shell_output` / `shell_input` / `shell_resize` / `shell_wait` / `shell_kill` |
| `fetch_url`、`web_search` | 读取网页或执行 Tavily/SearXNG 搜索 | 网络默认关闭；研究任务显式授予公共网络能力；每次抓取仍审批，并检查重定向、DNS 和私网地址 |
| `delegate_task` | 有界委派只读或隔离写子任务 | 新上下文、单层、串行、每任务最多两个；不自动合并 |
| `mcp__<serverId>__<toolName>` | 调用本地 stdio MCP 工具 | 只注入已启用且探测成功的服务器；Schema 校验、结果限长、密钥脱敏和逐次审批 |
| `ask_user` | 缺少关键信息时暂停 | 进入 `waiting_input`，不继续猜测 |
| `finish_task` | 声明完成并给出中文总结 | 纯文本回复不算完成；仍需通过产物检查 |

符号链接逃逸、路径越界、私有地址和未授权域名都在工具层拒绝。权限按任务固定，不在执行过程中由模型自行扩大。

## 上下文与执行稳定性

工具结果裁剪与历史摘要是两个独立步骤：即使尚未达到摘要阈值，也会把裁剪后的工具结果用于下一轮模型输入。原始工具完成事件仍保留完整结果；重复裁剪不会叠加截断标记。

系统提示词由通用执行规则与任务交付规则组成。JSON 契约只对 JSON 产物注入；财务、排期、恢复、代码测试等专项规则按任务标题和目标选择，避免每轮携带所有任务类型的规则。

模型档案保存 `contextWindowTokens` 和 `maxOutputTokens`。旧配置迁移为 128K 上下文窗口和 8K 最大输出，设置页可以修改。Runtime 按上下文窗口减去 `max(16K, 15%)` 的预留空间，并保留约 20K 近期 Token 触发压缩。

压缩只从完整回合边界开始，绝不拆散 assistant 工具调用和对应 tool 结果。近期工具输出保持原样，较早输出按 60% 头部和 35% 尾部裁剪，并注入文件/命令/测试进度账本与项目规则；摘要失败时回退到安全截断，任务仍可继续。恢复后的消息序列再次超限时也会重新压缩。

执行错误只对 429、5xx 和网络错误做两次瞬态重试；4xx、用户取消和权限拒绝不重试。上下文超限先强制压缩再重试。相同工具名、参数和结果连续重复时先提示，达到 5 次后失败，避免无限循环；只读工具可在 `maxParallelTools` 内并行执行。

## 项目与 Worktree

本地项目必须指向 Git 根目录和存在的分支。项目任务默认使用 `native` 与 `workspace`，并在 `hearth/<task-id>` 分支上创建独立 Worktree；任务恢复复用同一 Worktree。成功和失败都保留分支与目录，只有用户明确清理且工作区干净时才删除，脏目录拒绝清理。GitHub 任务继续默认走 Codex，不会静默切换执行器。

## 有界委派

`delegate_task` 使用全新消息上下文，只允许只读或隔离写。只读子代理移除写入工具和 Shell；隔离写从父 Worktree 当前 HEAD 创建子 Worktree，完成后提交并返回分支与提交号。父任务检查后才能手动 cherry-pick，系统不会自动合并。

子代理单层嵌套、串行执行、每个父任务最多两个，禁止继续委派和 MCP。子代理用量计入父任务预算与用量；任一限制越界都明确失败。

## 本地 MCP

首版只支持本地 stdio 服务器。服务器命令、参数和环境变量由用户显式配置；环境变量使用现有 `SecretBox` 加密，视图只暴露键名，不继承 Hearth 模型密钥或任意父进程密钥。探测失败、启动崩溃和调用超时彼此隔离，不拖垮任务进程。

工具统一命名为 `mcp__<serverId>__<toolName>`。发现时检查名称、描述、工具数量、Schema 和跨服务器冲突；调用前再次校验 JSON Schema，并限制结果大小。工具输出、错误和服务器 stderr 都会脱敏。

MCP 调用默认逐次进入现有工具审批，审批绑定服务器、工具名和参数摘要；只有完全权限模式自动放行并记录审计。系统不做自动重试，也不承诺 exactly-once；可能产生外部副作用的 MCP 工具仍需要用户理解其语义并自行决定是否调用。

## 能力矩阵

下表的判断来自公开能力和代码成熟度，不是共享基准结果。不能据此宣称 Hearth 已在数值上超过 Pi、DeerFlow 或 OpenCode。

| 维度 | Hearth native | Pi | DeerFlow | OpenCode |
|---|---|---|---|---|
| 通用编码执行面 | glob/grep、原子编辑、Shell、办公文件、搜索、子代理、本地 MCP 和 Worktree 已具备 | 核心文件工具和精简编码循环成熟 | 长任务中间件、沙箱、子代理、记忆和延迟工具更完整 | 通用执行面广；编码 profile 已补齐模糊编辑、后台 Shell、todo、测试门禁、计划、快照回滚和 ACI 基准 |
| 长时任务编排 | 有预算、检查点、恢复、目标验收和审批治理 | 以精简循环为主 | 长任务编排能力更强 | 通用执行强，但控制面不是 Hearth 的任务账本模型 |
| 上下文管理 | 按窗口 Token 触发、完整回合压缩、摘要失败回退、压缩后检查点 | 有会话树和压缩 | 有完整上下文中间件 | 压缩能力成熟 |
| 委派 | 单层、串行、最多两个、只读或隔离写、不自动合并 | 首版不作为重点 | 子代理和多阶段编排更强 | 子代理更成熟、覆盖更广 |
| MCP | 仅本地 stdio，逐次审批，崩溃隔离 | 不作为核心能力 | 不以 MCP 为核心参照 | 公开能力更完整 |
| 项目与 Worktree | 本地 Git 项目注册、隔离 Worktree、手动清理 | 更偏精简编码范围 | 沙箱与长任务编排更强 | Worktree 覆盖最完整 |
| 控制与证据 | 审批、效果记录、检查点、恢复、产物验证和任务治理最强 | 控制面较轻 | 治理模型不同 | 控制面较轻 |

因此更准确的结论是：OpenCode 的通用执行面最完整，DeerFlow 的长时编排更强，Pi 在精简编码范围内更成熟；Hearth native 的控制面最强，执行面已经补齐到可做多文件编码、研究办公、有界委派、本地 MCP 和本地项目 Worktree，但在 LSP、格式化器、远程 MCP、浏览器自动化、视觉理解和自动合并上仍有明显差距。

## 预算、检查点与恢复

主模型、上下文摘要和委派工具返回的用量统一累计到运行用量与检查点。`inputTokens`、`outputTokens` 是总量，缓存读取、缓存写入和推理 Token 是其中的明细，不再次叠加到预算。摘要后立即检查 Token 预算，达到上限便停止下一次模型调用；兼容只返回字符串的旧摘要回调，但这种回调无法提供摘要用量。

每次原生运行都有四类预算：最大轮次、最大工具调用次数、最大 Token 和最大时长。默认预算按执行模式（快速 / 标准 / 深入）设定，显式传入的预算优先；`unlimited` 不再作为产品默认。

Runtime 在每个模型回合、每个工具步骤、等待输入和最终完成时写入检查点。检查点包含消息、用量、轮次和工具调用计数。0.3.4 起，服务端 checkpoint 是 SQLite `events` 的物化视图：写文件前先追加 `runtime.checkpoint.snapshot`，`run_checkpoints.event_seq` 记录快照位置；文件缺失或损坏时从事件按 `event_seq` 回放重建。恢复时：

1. 宿主 `HostKernel` 先完成 `lease → store → operations → runs → tasks → background → ready` 阶段，恢复完成前 `/api/ready` 保持 503。
2. 找到最近一次可恢复的检查点，复制当时的工作区；恢复闸门沿父 run 链检查 prepared/dispatched 操作、运行中后台进程和 checkpoint proof，未知副作用不自动重放。
3. 恢复消息与预算计数，必要时把用户补充作为新的 `user` 消息追加。
4. 从暂停位置继续，而不是从头重跑。
5. 最终产物缺失时，带着上一轮 Agent 上下文补交，最多两轮；仍不满足则明确失败。

检查点存放在隔离工作区的 `.hearth/checkpoints/` 下，对话运行卡只展示数量和折叠的技术信息，不把中间 JSON 当作用户产物。

## 完成契约

- 通用与交付任务必须生成声明的产物，默认是 `result.md`。
- 工作区任务必须给出最终总结，并保留代码改动和测试证据。
- 中间 JSON、命令日志、检查点和运行时文件不进入用户产物列表。
- 声明的产物为空、执行器没有返回总结或预算耗尽，都不能标记为完成。
- 用户需要的最终结果出现在对话运行卡和产物面板；执行命令、检查点和内部事件收进折叠区域。

## 任务提案

需要联网或读写工程工作区的任务，先在聊天中生成任务提案，而不是直接执行。提案说明执行器、任务类型、期望产物、网络域名和原因。用户确认后才创建任务并进入调度队列；拒绝则不产生任务。

普通通用任务可以直接派出。这样既保持“说一句话就开始”的简单交互，又让高权限动作有明确的用户授权点。

## 运行时账本与后台进程

工具调用不再只靠内存里的 Promise。审批通过后先写 `prepare`（意图、参数摘要、`beforeDigest`），再写 `dispatch`，工具返回后才 `settle`；超时、中止或外部写缺回执记为 `unknown`，下一进程拒绝自动重放，并把未结算结果交给模型先核对。

- 服务端 `SqliteOperationLedger` 写入 `run_operations`；standalone / 评测使用 JSONL 账本。
- 服务端 runtime journal 并入 SQLite `events`（schema v40）；消息、工具结算、检查点和 run 边界是同一份事实。
- 后台 shell 写入 `background_processes`（session、PID、真实创建时间、命令、日志路径、task/run、状态与退出码）；宿主重启时按 PID + 创建时间判定，活的杀进程树、复用的只标 `lost`。
- 终态 run 输出 `run-evidence.json`，并执行物理 cleanup；已登记 shell 进程会被真正终止，`confirmed / failed` 写回操作账本。

## 当前边界

- 子代理只支持单层、串行、最多两个；不做并行团队、递归委派或自动合并。
- MCP 只支持本地 stdio；不支持远程 HTTP、OAuth、托管多租户或工具级 exactly-once。
- 搜索默认关闭；公共网络能力不会绕过私网拦截和逐次抓取审批。
- 不支持远程 MCP、图片/扫描件视觉理解、PPTX、LSP、格式化器或自动 cherry-pick。
- PTY / 后台 shell 不跨宿主重启恢复终端状态，重启只做 `lost` 标记与孤儿清理。
- Windows 沙箱只有 `deny | open` 两种网络模式；域级 allowlist 会 fail-closed。
- 执行使用当前聊天模型，不内置第二套“执行模型”；工作区任务优先在本地 Worktree 中执行。
- 不把中间步骤、内部 JSON 或终端输出当作交付结果。
- 没有共享基准，不声称已量化超过 Pi、DeerFlow 或 OpenCode；只按公开能力说明差距和已补齐范围。
