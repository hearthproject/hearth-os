# 原生 Agent Runtime

<p class="lead">Hearth 的原生执行器不是一段“把任务发给模型”的提示词，而是一个可暂停、可恢复、受权限和预算约束的通用执行内核。它以 Pi 的简洁工具循环为起点，并借鉴 DeerFlow 的长任务编排和 OpenCode 的通用执行面，由 Hearth 自己实现，不引入这些项目的运行时。</p>

## 为什么自研 Runtime

聊天模型可以回答问题，但不能直接证明工作真的完成。要形成闭环，系统必须自己保存消息、执行工具、累计用量、限制权限、写入检查点，并在缺少产物时继续补齐。把这些职责交给外部 CLI 会让任务状态、权限和恢复语义分裂在两个进程里。

Hearth 因此保留两层执行能力：

| 执行器 | 定位 | 典型任务 |
|---|---|---|
| `native` | 通用单 Agent，直接调用当前聊天模型和内置工具 | 整理资料、生成文档、分析网页、简单文件处理 |
| `codex` | 面向代码仓库和多文件工程的专长执行器 | 修复项目错误、修改代码、运行测试、提交改动 |

原生执行器是默认的通用路径。只有明确属于仓库或工程工作时，路由器才选择 Codex；两者不会在失败后静默互换。

## 内核形态

```text
任务 + 用户补充
      ↓
 系统提示 + 消息历史
      ↓
 模型流式回合 ──→ 文本回答 / 工具调用
      ↓                    ↓
 Token 与预算累计      执行受权限约束的工具
      ↓                    ↓
  写入检查点 ←──── 工具结果回填
      ↓
 完成 / 暂停等待输入 / 预算耗尽 / 取消
```

每轮只做一件事：模型返回内容与工具调用，Runtime 执行工具并把结果作为下一条消息回填。模型只输出文本不再被视为完成；任务完成的唯一可信信号是模型调用 `finish_task`，以及声明的产物确实存在且非空。

## 消息与协议

`@hearth/model-client` 负责四种协议：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Gemini。`model-agent.ts` 把它们统一成同一种流式 Agent 回合：文本增量、工具调用、工具参数拼接、结束原因和用量。

这样更换模型提供商不会改变 Runtime 的工具循环，也不需要为每家模型复制一套调度逻辑。原生执行器要求模型支持工具调用；不支持时直接给出明确错误，不伪装成成功。

## 通用工具面

| 工具 | 用途 | 默认边界 |
|---|---|---|
| `read_file`、`read_document`、`list_files`、`search_text` | 读取文本、PDF、DOCX、XLSX、CSV、JSON 和 HTML | 只能访问任务工作区与授权目录；文档大小和返回字符数有上限 |
| `glob`、`grep` | 按模式定位文件，用 RE2 兼容正则搜索 include/exclude 范围 | 有结果数、文件大小、扫描时长预算；拒绝路径逃逸 |
| `write_file`、`edit_file`、`apply_patch` | 生成、预览修改、原子应用补丁、移动和删除文件 | `edit_file` 支持 dry-run 差异预览；补丁先全量预校验，再一次性写入，避免部分成功 |
| `write_spreadsheet`、`write_document` | 生成 XLSX/CSV 和 DOCX 办公文件 | 只能写入授权目录，并经过文件动作审批 |
| `shell` | 运行必要检查命令 | 只在工作区任务中授权；保存完整输出到任务日志，只回填尾部；超时杀死整个进程树 |
| `fetch_url`、`web_search` | 读取网页或执行 Tavily/SearXNG 搜索 | 网络默认关闭；研究任务显式授予公共网络能力；每次抓取仍审批，并检查重定向、DNS 和私网地址 |
| `load_skill`、`read_skill_resource` | 按需加载已采纳技能和技能包资源 | 提示词只注入索引；加载时校验内容哈希和任务权限；资源路径不能越出技能包 |
| `delegate_task` | 有界委派只读或隔离写子任务 | 新上下文、单层、串行、每任务最多两个；不自动合并 |
| `mcp__<serverId>__<toolName>` | 调用本地 stdio MCP 工具 | 只注入已启用且探测成功的服务器；Schema 校验、结果限长、密钥脱敏和逐次审批 |
| `ask_user` | 缺少关键信息时暂停 | 进入 `waiting_input`，不继续猜测 |
| `finish_task` | 声明完成并给出中文总结 | 纯文本回复不算完成；仍需通过产物检查 |

符号链接逃逸、路径越界、私有地址和未授权域名都在工具层拒绝。权限按任务固定，不在执行过程中由模型自行扩大。

## 上下文与执行稳定性

模型档案保存 `contextWindowTokens` 和 `maxOutputTokens`。旧配置迁移为 128K 上下文窗口和 8K 最大输出，设置页可以修改。Runtime 按上下文窗口减去 `max(16K, 15%)` 的预留空间，并保留约 20K 近期 Token 触发压缩。

压缩只从完整回合边界开始，绝不拆散 assistant 工具调用和对应 tool 结果。压缩前先保留完整回合，再生成摘要，并把压缩结果写入检查点；摘要失败时回退到安全截断，任务仍可继续。恢复后的消息序列再次超限时也会重新压缩。

执行错误只对 429、5xx 和网络错误做两次瞬态重试；4xx、用户取消和权限拒绝不重试。上下文超限先强制压缩再重试。相同工具名和参数连续重复时只提示一次，超过阈值后失败，避免无限循环。

## 技能、项目与 Worktree

已采纳技能默认只以索引进入提示词，正文通过 `load_skill` 按需读取。加载会校验内容哈希、审计结果和任务权限；技能只能提供执行方法，不能扩张路径、网络、工具或审批权限。`read_skill_resource` 只允许读取技能包内列出的相对资源。

本地项目必须指向 Git 根目录和存在的分支。项目任务默认使用 `native` 与 `workspace`，并在 `hearth/<task-id>` 分支上创建独立 Worktree；任务恢复复用同一 Worktree。成功和失败都保留分支与目录，只有用户明确清理且工作区干净时才删除，脏目录拒绝清理。GitHub 任务继续默认走 Codex，不会静默切换执行器。

## 有界委派

`delegate_task` 使用全新消息上下文，只允许只读或隔离写。只读子代理移除写入工具和 Shell；隔离写从父 Worktree 当前 HEAD 创建子 Worktree，完成后提交并返回分支与提交号。父任务检查后才能手动 cherry-pick，系统不会自动合并。

子代理单层嵌套、串行执行、每个父任务最多两个，禁止继续委派和 MCP。子代理用量计入父任务预算与用量；任一限制越界都明确失败。

## 本地 MCP

首版只支持本地 stdio 服务器。服务器命令、参数和环境变量由用户显式配置；环境变量使用现有 `SecretBox` 加密，视图只暴露键名，不继承 Hearth 模型密钥或任意父进程密钥。探测失败、启动崩溃和调用超时彼此隔离，不拖垮任务进程。

工具统一命名为 `mcp__<serverId>__<toolName>`。发现时检查名称、描述、工具数量、Schema 和跨服务器冲突；调用前再次校验 JSON Schema，并限制结果大小。工具输出、错误和服务器 stderr 都会脱敏。

MCP 调用默认逐次进入现有工具审批，审批绑定服务器、工具名和参数摘要；只有完全权限模式自动放行并记录审计。系统不做自动重试，也不承诺 exactly-once；可能产生外部副作用的 MCP 工具仍需要用户理解其语义并自行决定是否调用。

## 能力矩阵

下表的判断来自公开能力和代码成熟度，不是共享基准结果。不能据此宣称 Hearth 已在数值上超过 Pi、DeerFlow 或 OpenCode。

| 维度 | Hearth native | Pi | DeerFlow | OpenCode |
|---|---|---|---|---|
| 通用编码执行面 | glob/grep、原子编辑、Shell、办公文件、搜索、技能、子代理、本地 MCP 和 Worktree 已具备 | 核心文件工具和精简编码循环成熟 | 长任务中间件、沙箱、子代理、技能、记忆和延迟工具更完整 | 当前公开执行面最广；规则工具、编辑、Shell、技能、子代理、MCP、压缩和 Worktree 覆盖齐全 |
| 长时任务编排 | 有预算、检查点、恢复、目标验收和审批治理 | 以精简循环为主 | 长任务编排能力更强 | 通用执行强，但控制面不是 Hearth 的任务账本模型 |
| 上下文管理 | 按窗口 Token 触发、完整回合压缩、摘要失败回退、压缩后检查点 | 有会话树和压缩 | 有完整上下文中间件 | 压缩能力成熟 |
| 委派 | 单层、串行、最多两个、只读或隔离写、不自动合并 | 首版不作为重点 | 子代理和多阶段编排更强 | 子代理更成熟、覆盖更广 |
| MCP | 仅本地 stdio，逐次审批，崩溃隔离 | 不作为核心能力 | 不以 MCP 为核心参照 | 公开能力更完整 |
| 项目与 Worktree | 本地 Git 项目注册、隔离 Worktree、手动清理 | 更偏精简编码范围 | 沙箱与长任务编排更强 | Worktree 覆盖最完整 |
| 控制与证据 | 审批、效果记录、检查点、恢复、产物验证和任务治理最强 | 控制面较轻 | 治理模型不同 | 控制面较轻 |

因此更准确的结论是：OpenCode 的通用执行面最完整，DeerFlow 的长时编排更强，Pi 在精简编码范围内更成熟；Hearth native 的控制面最强，执行面已经补齐到可做多文件编码、研究办公、技能复用、有界委派、本地 MCP 和本地项目 Worktree，但在 LSP、格式化器、远程 MCP、浏览器自动化、视觉理解和自动合并上仍有明显差距。

## 预算、检查点与恢复

每次原生运行都有四类预算：最大轮次、最大工具调用次数、最大 Token 和最大时长。超过预算会停止并返回可解释的结果，不继续消耗。

Runtime 在每个模型回合、每个工具步骤、等待输入和最终完成时写入检查点。检查点包含消息、用量、轮次和工具调用计数。恢复时：

1. 找到最近一次可恢复的检查点，复制当时的工作区。
2. 恢复消息与预算计数，必要时把用户补充作为新的 `user` 消息追加。
3. 从暂停位置继续，而不是从头重跑。
4. 最终产物缺失时，带着上一轮 Agent 上下文补交，最多两轮；仍不满足则明确失败。

检查点存放在隔离工作区的 `.hearth/checkpoints/` 下，任务详情只展示数量和折叠的技术信息，不把中间 JSON 当作用户产物。

## 完成契约

- 通用与交付任务必须生成声明的产物，默认是 `result.md`。
- 工作区任务必须给出最终总结，并保留代码改动和测试证据。
- 中间 JSON、命令日志、检查点和运行时文件不进入用户产物列表。
- 声明的产物为空、执行器没有返回总结或预算耗尽，都不能标记为完成。
- 用户需要的最终结果出现在任务详情顶部；执行命令、检查点和内部事件收进折叠区域。

## 任务提案

需要联网或读写工程工作区的任务，先在聊天中生成任务提案，而不是直接执行。提案说明执行器、任务类型、期望产物、网络域名和原因。用户确认后才创建任务并进入调度队列；拒绝则不产生任务。

普通通用任务可以直接派出。这样既保持“说一句话就开始”的简单交互，又让高权限动作有明确的用户授权点。

## 当前边界

- 子代理只支持单层、串行、最多两个；不做并行团队、递归委派或自动合并。
- MCP 只支持本地 stdio；不支持远程 HTTP、OAuth、托管多租户或工具级 exactly-once。
- 搜索默认关闭；公共网络能力不会绕过私网拦截和逐次抓取审批。
- 不支持浏览器自动化搜索、图片/扫描件视觉理解、PPTX、LSP、格式化器、Shell 后台会话和自动 cherry-pick。
- 执行使用当前聊天模型，不内置第二套“执行模型”；工作区任务优先在本地 Worktree 中执行。
- 不把中间步骤、内部 JSON 或终端输出当作交付结果。
- 没有共享基准，不声称已量化超过 Pi、DeerFlow 或 OpenCode；只按公开能力说明差距和已补齐范围。
