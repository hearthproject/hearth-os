# 个人上下文、本体与注意力

<p class="lead">上下文不是把所有历史塞给模型，注意力也不是越多提醒越好。Hearth 先整理人和事的关系，再按预算组装 Context Pack，最后用打扰预算决定什么时候值得让用户看到。</p>

## 设计目标

个人上下文要能回答“这是谁、和什么有关、现在是什么状态、做过什么决定、答应过什么”。这些信息必须带来源、可信度、敏感度和有效期，不能变成一段无法追溯的模型摘要。

交给模型的上下文要有边界。每次任务只要完成当前工作所需的证据；超出预算的内容保留引用和摘要，允许按需展开，而不是默认全部内联。来源过长时保存正文位置，任务记录只保留可核对的引用。

注意力要有成本意识。主动建议只有在用户能采取行动、且现在确实值得打断时才出现。重复、低价值、无法执行或已经忽略的建议不能换个说法继续推送。

## 个人本体

个人本体保存实体、别名、关系、状态、决定和承诺。实体覆盖人、组织、项目、目标、任务、文档、产物、账户、设备和主题；别名把同一个人或项目在不同来源中的写法归并到一起。

状态记录某个实体在某个键上的值和有效期，例如项目负责人、账户状态或设备归属。决定记录选择、理由、备选方案、决定者和证据；承诺记录对方、内容、到期时间、状态和证据。冲突状态不会被静默覆盖，而是进入需要用户确认的注意力项。

可信度区分已确认、已观察、推断和过期。敏感度区分普通、敏感和秘密。用户纠正、撤回或删除来源时，相关状态、承诺和记忆要跟着更新，不能只在当前页面消失。

## Context Pack

Context Pack 按聊天、任务、目标、交接和委派范围组装，带 Token 预算和内容引用。每个条目有来源、摘要、可信度、有效期、为何入选和是否可展开。

| 通道 | 用途 |
|---|---|
| `must_know` | 不放入就会导致错误动作的目标、约束、禁止事项和关键状态 |
| `relevant` | 与当前问题直接相关的证据、决定、承诺和历史结果 |
| `recallable` | 预算不足时只保留引用和摘要，需要时再展开 |
| `omitted` | 明确未放入的内容，记录原因，避免误以为系统已经知道 |

子交接包只能引用父包可用的内容，不能通过展开引用绕过父级权限。展开引用会重新检查来源、敏感度和有效期，已过期、已遗忘或被标记为不可信的内容不会被复活。

## 记忆与召回

记忆记录来源、可信度、污染状态、敏感度、有效期和用途。写入前先判断是否允许捕获；召回时按范围、敏感度和信任状态过滤，避免把未确认、已过期或不可信记忆当作事实。

记忆合并只处理可解释的重复和冲突，保留来源链和版本。遗忘会传播到投影、版本、事件、召回审计、设备同步、派生记忆和合并记录，并留下墓碑，防止旧内容通过缓存或同步重新出现。导出包含记忆本身及其来源和遗忘记录。

## 标准意图与注意力

标准意图把用户长期关注的规则保存下来，例如“每周检查一次项目风险”或“有需要我审批的事项时提醒”。心跳按意图和任务状态生成候选注意力项，候选必须说明为什么现在需要用户、下一步能做什么、不处理的后果和等待对象。

注意力预算控制每日上限、安静时段、同类冷却、单目标上限和高优先级上限。用户忽略、稍后提醒、接受或标记错误都会形成反馈；被忽略的内容会降低后续评分。`NO_REPLY` 表示用户明确不需要回应，系统不能把它当作未读继续追问。

提醒渠道不改变授权。应用内收件箱、桌面通知和飞书消息只负责让人看到，审批仍走一次性审批与效果账本。没有送达通道时回到应用内“需要你”，不伪造推送成功。

## 设计取舍

- **本体不是知识库。** 只保存会影响判断和动作的关系、状态、决定和承诺，不追求把所有信息搬进结构化表。
- **引用优先于复制。** 长文、日志和产物保留位置与摘要，避免上下文膨胀和版本漂移。
- **冲突可见。** 两个来源给出一致性不足的状态时，系统停下来让用户选择，不用“最后写入者赢”掩盖问题。
- **打扰需要理由。** 每条注意力项都要回答为什么现在、下一步做什么、不处理会怎样。
- **建议不等于执行。** 主动服务可以建议和转任务，不能绕过审批直接做外部动作。

## 当前边界

个人本体、实体归并、状态冲突、Context Pack 通道、记忆来源与可信度、合并、遗忘传播、标准意图、心跳和注意力反馈已经形成代码闭环。实体匹配和上下文排序仍以本地启发式为主，真实长期个人数据、手机推送、远程接管和跨设备上下文一致性尚未验收。
