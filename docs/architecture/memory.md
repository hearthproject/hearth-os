# 记忆系统

<p class="lead">记忆不是聊天记录，而是受约束的判断缓存。它必须有来源、置信度、敏感度、冲突和遗忘策略。</p>

## Memory OS

记忆不是聊天记录，也不是越多越好。它是“受约束的判断缓存”，必须可解释、可纠正、可遗忘。

### 五类记忆

| 类型 | 内容 | 生命周期 | 用途 |
|---|---|---|---|
| Working Memory | 当前目标、约束、步骤和临时观察 | 任务结束清理 | Task Pack、当前计划 |
| Episodic Memory | 过去任务、结果、失败、人工纠偏 | 中期，可摘要 | “上次类似任务怎么做” |
| Semantic Memory | 人物、项目、组织、事实、关系 | 长期，需来源和有效期 | 项目背景、联系人、决策 |
| User Model | 偏好、沟通风格、边界、习惯、价值排序 | 长期，高度可编辑 | 减少重复说明 |
| Procedural Memory | 技能、工作流、工具配方、验证器 | 版本化，可回滚 | 重复任务复用、Evolution |

Skill 包含权限、版本、评估和回滚元数据；Memory 只保存“曾经有效的经验”。

### 记忆记录

每条记忆至少包含：

- id、类型、subject、statement；
- scope（用户、项目、人物、设备）；
- sourceRefs 和 sourceTrust；
- confidence、sensitivity；
- createdAt、lastUsedAt、expiresAt；
- supersedes、conflictsWith；
- status：quarantined / active / superseded / forgotten；
- forgetPolicy。

关键不是字段多，而是每条记忆都能回答：从哪里来、有多可信、谁能看、何时过期、与哪条冲突、用户如何纠正或删除。

### 写入与检索

记忆写入不是“模型说值得记就记”。应先进入候选区，检查来源、敏感度、重复、冲突和用户授权；高敏感内容默认不自动写入。

检索按任务需要、scope、来源可信度、时效、敏感度和 Token 预算筛选；不能把全部记忆塞入上下文，也不能让不同项目/账户互相污染。

### 记忆预算

- 总记忆量预算；
- 单条长度预算；
- 注入上下文预算；
- 召回频率和衰减；
- 过期和归档。

记忆预算与 Token Governor 联动，避免“记忆越多越智能”的假象。

### 冲突、更新与置信度

- 新事实不能静默覆盖旧事实；
- 保留来源和时间；
- 冲突时标记或请求用户确认；
- 低置信度记忆不能单独触发高风险动作；
- 用户明确纠正优先；
- 过期事实可降权或遗忘。

### 遗忘

遗忘必须传播到索引、缓存、设备副本和派生摘要。用户应能确认：

- 忘了什么；
- 为什么忘；
- 哪些设备和索引已更新；
- 是否仍存在于备份；
- 如何验证。

### 记忆投毒与提示词注入

网页、邮件、文档和外部工具输出都是不可信来源。它们可以成为候选记忆，但不能直接获得高可信度，更不能通过记忆扩大权限。高敏感或外部不可信内容应隔离、降权或拒绝写入。

### 多设备同步与 UI

- 同步记忆必须携带版本、来源和 tombstone；
- 删除不能在另一台设备“复活”；
- 敏感记忆按设备范围过滤；
- 记忆浏览器显示“记住了什么、为什么召回、来自哪里”；
- 用户可纠正、删除、导出；
- “为什么召回”不能只给模型解释，要有来源和规则证据。

### 记忆指标

- 召回准确率；
- 错误记忆导致的返工；
- 用户纠正率；
- 遗忘合规率；
- 注入 Token 和延迟；
- 敏感信息泄漏尝试被阻断率。
