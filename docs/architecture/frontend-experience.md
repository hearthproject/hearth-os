# 前端与移动体验

<p class="lead">用户只需要知道三件事：Agent 在做什么、是否需要我、下一步点哪里。前端不是后置包装层。</p>

## 前端与移动端体验

Hearth 的前端不是展示 Agent 内部架构的控制台，而是安静的注意力界面。

### 设计原则

1. **任务优先**：用户看到要完成的事，不是模型、工具和线程；
2. **一个状态一个主动作**：任务卡任何时刻只有一个最值得点击的动作；
3. **渐进披露**：默认只显示目标、状态、证据和下一步；
4. **安静默认**：没有需要人的事情就不打扰；
5. **状态诚实**：不把运行中伪装成即将完成，不把模型说完成显示成已完成；
6. **手机对等**：手机能完成查看、审批、接管、发起和通知；
7. **无内部术语**：主界面不出现 Worker、Harness、Token、Mandate；
8. **界面先出现**：每个增量先明确用户看到什么、能点什么、失败后怎么恢复，再接后端实现。

前端不是后端完成后的展示层，而是产品纵向切片的一部分。Stage 0 用原型验证信息架构，Stage 1 用真实页面连接真实状态，之后每个阶段都把新增能力投影为可操作界面。功能只有在浏览器中有完整用户路径、证据和恢复入口，才算进入阶段验收。

### 信息架构

主导航保持四项：

```text
今日  |  需要你  |  产物  |  设置
```

- **今日**：正在做、刚完成、接下来要做什么；
- **需要你**：审批、补充信息、失败接管和异常；
- **产物**：报告、文档、代码、表格、截图、回执；
- **设置**：连接、记忆、权限、设备、通知和预算。

“新任务”是全局动作，不占导航项。桌面端使用 `⌘K` / `Ctrl+K`，移动端使用明显悬浮按钮。

### 首页

首屏回答：今天有什么、什么需要我、正在做什么、最近完成了什么。默认不展示 Token、模型名、执行器名、内部步骤和调试日志；需要时进入详情查看。

### 任务卡

任务卡应回答：

- 这是什么任务？
- 现在进行到哪一步？
- 有没有产物或验证证据？
- 是否需要我？
- 我下一步能做什么？

字段包括标题、状态、关键阶段进度、产物、验证、风险、主动作和时间。每个状态只有一个主动作。

### 状态与主动作

| 状态 | 用户看到 | 主动作 |
|---|---|---|
| 排队中 | 等待设备或时间 | 调整优先级 |
| 执行中 | 当前阶段 | 查看进度 |
| 等待审批 | 将要发生什么 | 审批 |
| 等待信息 | 缺少什么 | 补充信息 |
| 失败 | 原因和补救 | 恢复/重试/转人工 |
| 已完成 | 产物和验证 | 查看产物 |

### 需要你

“需要你”只收集真正阻塞人的事项：审批、补信息、失败接管、高风险确认。纯状态变化和可自动重试的失败不进入。

### 审批界面

审批卡必须让用户在十秒内判断：动作、账户、收件人/资源、附件和内容、可逆性、有效期、失败补偿。高风险动作显示真实范围、差异、二次确认和撤销方式。

### 产物中心

产物是可检查的交付物，不是附件列表：

- 版本、来源任务和执行器；
- 生成时间、哈希和大小；
- 验证结果与证据；
- 预览、下载、复制链接；
- 与上一版 diff；
- 相关审批和回执；
- 删除、归档和导出。

### 详情与时间线

详情页展示目标、约束、计划、关键工具调用、产物与验证、审批和回执、错误/重试/换路、预算与成本、关联记忆和技能。默认不展示模型内部思维过程；展示可审计事件、证据和决策原因。

### 新任务

支持自然语言、文件和图片、项目/联系人/截止时间、自主级别和验收标准预览。用户只写“帮我整理一下”时，系统应生成可编辑任务卡，而不是立刻无边界执行。

### 接管界面

显示当前浏览器/桌面，明确说明需要用户做什么；暂停自动输入；允许操作、批注、补充信息；记录接管前后状态；支持交还、缩小范围和终止。

### 通知

只用于高信号事件：需要审批、补充信息、失败无法恢复、用户明确关心的完成、设备离线阻塞、安全异常。

规则：同一任务聚合、静默时段、先摘要后详情、推送脱敏、点击直达动作、关闭渠道后不得绕过、通知频率与任务价值一起评估。

### 手机端

手机优先 PWA，Stage 4 只承担五件事：

1. 查看任务与产物；
2. 审批高风险动作；
3. 接管异常任务；
4. 发起新任务；
5. 接收高信号通知。

手机不应：默认运行完整 Agent、持有长期主凭据、直接暴露本地端口、后台无界执行高风险任务、用推送正文泄露敏感信息。

安全设计：安全隧道或推送中继、短期码和公钥配对、会话过期与生物识别、审批绑定 nonce/参数/过期时间、设备丢失可撤销、离线只读缓存不产生副作用。

### 可访问性与性能

键盘完成主要流程；不只依赖颜色；屏幕阅读器和可访问性标签；减少动画和深色模式；首屏快速加载、长列表虚拟化；弱网显示缓存和明确状态；中英文不截断关键动作；单手操作时主动作在可达区域。

### 体验指标

- 用户理解当前状态的时间；
- 从“需要你”到完成审批的时间；
- 审批误点率和撤销率；
- 每任务打断次数；
- 手机完成关键动作的成功率；
- 通知打开后的处理率；
- 找不到产物或恢复入口的次数。

## 与 MVP 的关系

MVP 必须让用户通过浏览器完成创建、查看、审批演练、取消、重试、恢复和取回产物。Stage 0 先做可点击原型，Stage 1 D1.1 连接真实任务状态，D1.3 达到完整 MVP。

没有真实 Web 路径的“MVP”不成立；没有失败态和恢复入口的界面也不算完成。
