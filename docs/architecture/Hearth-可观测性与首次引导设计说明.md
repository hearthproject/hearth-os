## 0. 一句话总览

这是三个无状态的只读聚合服务（健康、诊断、引导，合计约三百行）：把存储与运行时状态拼成快照供界面轮询与下载，几乎不含业务决策。真正的运维能力（备份、同步、维护）都在别处，本文不碰。

## 1. 先定性：四个容易误解的地方

| 误解 | 代码里的实际做法 |
|---|---|
| 以为「降级」会综合判断执行器、调度器、停止开关 | 只有三条规则能触发降级；执行器不可用、调度器停止、停止开关开启都**只上报不降级** |
| 以为降级会返回非 200 | 健康接口始终返回 200，状态只体现在响应体里 |
| 以为诊断导出做了字段级脱敏 | 它主要是「不导出任何明细，只给计数与类型名」；唯一的显式脱敏是维护错误里的本地路径替换 |
| 以为引导检查项都是门槛 | 只有「聊天模型是否已配置」决定要不要引导，其余三项纯展示 |

## 2. 健康快照：都看什么

| 维度 | 内容 |
|---|---|
| 总体 | 状态（正常 / 降级）、应用名、当前时间、启动时间、运行时长、schema 版本、实例编号 |
| 进程 | 常驻内存、堆已用、堆总量 |
| 磁盘 | 可用空间、数据库文件大小、预写日志大小（读取失败按 0 处理） |
| 任务 | 总数，以及排队、运行中、可继续、等待审批四项分状态计数 |
| 维护 | 最近一次运行时间与状态、最近错误 |
| 调度与安全 | 调度器是否启用且在运行、全局停止开关是否拉下 |
| 执行器 | Codex 是否可跑、供应商与模型、鉴权来源、问题清单；Hermes 健康 |
| 问题列表 | 触发降级的具体原因 |

**触发降级只有三条**：schema 版本与代码期望值不一致、最近一次维护失败、可用磁盘低于 256 MB。问题列表非空即为降级，否则正常。

健康接口在快照之上还会额外叠加两块**前端专用**字段：聊天模型是否已配置及其视图、以及 Codex 的配置路径、主目录、基础地址、线协议、密钥变量名与「密钥是否存在」。所以直接拿共享契约里的健康快照类型去解析这个接口，会漏掉这些字段。

前端每 20 秒轮询一次，按状态显示「正常 / 需要关注」，展示运行时长、内存、可用磁盘、数据库与日志大小、五项任务计数、调度器状态、停止开关、schema 版本与实例编号前 8 位、Codex 状态或问题清单，并逐条渲染告警。

## 3. 诊断导出：聚合而非明细

导出是一份带格式标记与版本号的 JSON，包含四块：

1. **健康快照**（上一节全部内容）；
2. **最近 10 次维护记录**；
3. **运行时环境**：Node 版本、平台、架构、进程号；
4. **规模统计**：七张表的行数（事件、任务、运行、审批、产物、记忆、方法候选），以及按类型分组、取前 30 名的事件类型计数。

另有三个检查标记：前端编译产物是否存在、是否仅本机可访问、备份是否强制加密。**后两个是硬编码为真，不是实时检测结果**，这一点读代码时尤其容易高估。

响应头设为不缓存、JSON 类型、并带日期命名的附件下载名；界面上就是一个「下载脱敏诊断」链接。所谓脱敏，实际靠的是「只给行数、类型名、数值，不给任何任务/记忆/事件正文」这一设计，加上维护错误里把本地盘符路径替换成占位符并截断到 500 字符。

## 4. 首次引导：一个门槛，三个展示项

引导状态只有两种值：已完成、已跳过，附带完成时间；读取时会严格校验，格式不对就当作「从未引导过」。

**是否需要引导的唯一判据**：从未完成或跳过引导，**且**聊天模型还没配置。其它三项检查（可用执行器列表、记忆自动捕获开关、主动式是否启用）只用于向导页展示，不参与门禁。这三个判定都是装配时以惰性闭包注入的，可用执行器取自执行器清单里健康探测为可跑的那些。

由此产生一个后果：一旦用户完成或跳过了引导，即使后来把模型配置删掉，也不会再弹出引导。

前端门禁只在首页路径生效：若接口返回需要引导，就重定向到欢迎页；该查询的缓存有效期是 10 秒。向导页用主动式检查项初始化偏好（未引导过时默认开启）。

## 5. 其余运维端点（仅列用途，不展开实现）

| 分组 | 端点用途 |
|---|---|
| 维护 | 查看最近运行与策略、手动触发一次运行 |
| 备份 | 列表、创建、下载、按编号恢复、整体恢复；另有一个固定返回「必须加密备份」错误的守门端点，用来禁止明文备份 |
| 同步 | 查看状态、新增/拉取/轮换/吊销对端、解决冲突、以及唯一允许非本机入站的事件导出端点 |

这些端点的实现分别见[Hearth-存储设计说明](./Hearth-存储设计说明.md)（备份、同步、维护算法）与[Hearth-服务组装与API接入设计说明](./Hearth-服务组装与API接入设计说明.md)（入站白名单例外）。它们默认都受仅本机访问的安全钩子约束。

## 6. 只读代码才会发现的事实

1. 降级只有三条规则，且健康接口永远返回 200。
2. 健康接口返回的字段比共享契约里的健康快照更多，多出来的是前端专用字段。
3. 诊断导出的两个安全标记是常量真值，不是运行时校验。
4. 引导只看模型配置；一旦完成或跳过就永久不再触发。
5. 这三个服务都是无状态只读聚合，源码规模很小；本模块没有其它散落的运维或引导机制。

## 7. 与其它模块的分界

| 方向 | 内容 |
|---|---|
| 输入 | 存储层的计数与元数据、schema 版本常量、执行器健康探测、装配时注入的调度器状态与四个引导判定 |
| 输出 | 健康快照、诊断导出文件、引导状态与检查项、若干运维端点 |
| 不讲 | 备份/同步/维护的算法（存储）、周期任务间隔（定时任务）、安全钩子（服务组装）、前端整体架构（前端） |
