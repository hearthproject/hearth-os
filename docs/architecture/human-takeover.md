# 人工接管与审批

<p class="lead">人不是失败后的补丁，而是执行系统的一等参与者。审批、接管和人的错误都必须被设计。</p>

## Human Executor 与接管

人不是失败后的补丁，而是系统的一等执行器。

### 审批卡

审批必须让用户在十秒内判断：

- 将要做什么；
- 使用哪个账户；
- 目标收件人/文件/仓库/日历/资源；
- 内容和附件；
- 可逆性；
- 失败和补偿方式；
- 审批有效期和范围。

### 接管协议

- 显示当前浏览器/桌面；
- 明确说明需要用户做什么；
- 暂停自动输入；
- 允许操作、批注和补充信息；
- 记录接管前后状态；
- 支持交还、缩小范围和终止。

### 人的错误也是输入

用户拒绝、修改、撤销和接管不是噪声，而是评估和技能改进的重要样本；但不能把用户纠正自动变成更高权限。

## 阶段映射

| 执行器 | 首次出现 |
|---|---|
| Codex | 第一阶段 1.3 |
| Native（薄层） | 第一阶段至第二阶段 |
| Connector | 第二阶段 |
| Browser | 第二阶段 |
| Document/Data | 第二阶段 |
| GUI + Human 实时接管 | 第三阶段 |
| 手机接管入口 | 第四阶段 |

第一阶段先定义能力矩阵和界面约定，并在最小任务闭环中只接入一种执行能力；后续阶段再逐步接入其他执行器。
