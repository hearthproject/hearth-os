## 0. 一句话总览

这是「物理准备层」：把各种输入落成文件、在真实 Git 仓库上开出隔离工作树、按模板声明装好 Python/Node 依赖，再提供只读的 diff、文件与 PR 预览视图。它不负责跑模型，也不负责判定任务是否成功。

---

## 1. 先定性：三个容易误解的地方

| 误解 | 代码里的实际做法 |
|---|---|
| 以为服务端 `runtime.ts` 是 Agent 运行时 | 它是**装依赖的脚本编排器**（虚拟环境、包安装），与共享包 `agent-runtime` 毫无关系 |
| 以为「沙箱」是个容器 | 它只是路径、网络、工具、进程的**策略求值器**；五种后端枚举里实际只用了本地后端 |
| 以为模板里的验收描述会变成结构化验收项 | 取模板时验收字段被统一映射成**空数组**，真正的验收项来自别处 |

---

## 2. 工作区：输入落地与提示词

每个任务有自己的目录，下面分「输入」与「输出」两块。不同类型输入落成不同文件：纯文本与粘贴内容落成 Markdown 或纯文本，网页落成页面 Markdown 加元数据，GitHub 上下文落成说明与结构化数据，附件落成副本。随后生成任务提示词，路径解析被约束在工作区内。

有一个很用心的防幻觉设计：如果 URL 输入抓取失败，系统会写一份**说明失败原因的 Markdown**，并明确禁止模型据此补写正文。这样模型不会把「抓不到」当成「内容为空」而凭空编造。致命错误（非法地址、协议不支持、地址带凭据、主机不允许、私网地址等）与非致命错误是分开处理的。

产物侧的总量闸门是 1000 个文件、合计 100 MB；只有落在受管输出目录下的文件才被认作产物（发布流程见存储文档）。

## 3. Git 工作树：一任务一分支

| 环节 | 规则 |
|---|---|
| 分支名 | 固定前缀加任务编号 |
| 路径 | 工作区根目录下的独立 worktrees 子目录 |
| 创建 | 先校验分支名合法性，再执行添加；分支已存在则复用，否则从基准提交新建 |
| 视图校验 | 当前分支不符时直接标记「不可用」 |
| 清理 | 要求工作树干净，否则拒绝；删除分支失败仍会返回「已移除但分支保留」 |

错误分类很细：缺少项目、项目路径失效、不是 Git 仓库、分支名非法、分支不匹配、工作树脏。Git 命令统一 30 秒超时。

「清理成功」不等于「分支已删除」——返回值里单独有一个标记说明分支是否还在，这是排查残留分支时最该看的一项。

## 4. 只读 Git 视图与 PR 预览

视图服务把若干 Git 命令的结果聚合成一份给界面用的快照：当前提交、当前分支、工作区状态、与基准的差异统计、提交数、最近若干条提交。上限是差异 512 KB、单文件 1 MB、提交列表 20 条；路径读取有防越界校验。

**一个隐藏回退**：如果没有独立工作树，视图会去任务目录下的 `repo` 子目录找仓库（那是 GitHub 浅克隆落点）。两条来源共用同一套差异视图，所以无论任务改的是本地项目还是远程 PR，界面看到的结构一致。

PR 预览是一份产出文件，校验规则包括：标题与正文必填、标题不超过 160 字、正文不超过 6 万字符、有关联议题时正文必须包含引用、分支与基准必须与仓库上下文严格一致。评论正文从评审稿里用成对标记抠出，标记有两套兼容写法。

## 5. 任务级依赖环境

按任务模板里的声明预装依赖，产物写在任务目录的隐藏子目录里：一个说明文件记录可用的 Python / Node 可执行路径，一份准备日志。

| 项 | 规则 |
|---|---|
| Python | 优先用 uv 建虚拟环境并装依赖，失败回退到标准 venv 与 pip |
| Node | 按声明走 `ci` 或 `install` |
| 安装超时 | 20 分钟 |
| 日志上限 | 20 万字符，超限保留末尾并加截断说明 |

这是一层「让模型拿到能跑的环境」的保障，与模型调用、工具循环完全无关。

## 6. 模板与本地项目

任务模板是纯声明式数据：编号、标题、类别、描述、目标、输入定义、允许的网络主机、输出目录、期望产物、验收说明、审批类型、GitHub 上下文、运行时声明。类别有文档、网页、代码、数据、人物、营销六类，实际定义 15 个模板。

本地项目注册要求路径是 Git 仓库根且默认分支本地存在；路径支持展开用户目录并解析真实路径；名称清洗后上限 100 字符。项目是开工作树的前提。

> 前面提到的「验收字段被映射为空数组」值得再强调一次：模板里的验收描述只是给人看的说明，不会自动变成完成判定里的结构化验收项。

---

## 7. 沙箱：策略求值而非隔离容器

沙箱服务定义五种后端（本地、容器、SSH、虚拟机、远程 worker）与五类失败（逃逸、网络违规、凭据过期、策略拒绝、后端不可用），但当前只注册了本地后端，其余是枚举占位。

它的一次求值会根据输入判断是否需要审批，而判据**只看「是否属于外部副作用」这一个布尔值**，不看路径或网络是否越界。真正的路径与网络拦截发生在 Agent 运行时的工具层（见[Hearth-Agent运行时设计说明](./Hearth-Agent运行时设计说明.md)）。

---

## 8. 只读代码才会发现的事实

1. 服务端 `runtime.ts` 是装依赖的，不是 Agent 运行时。
2. 模板的验收说明不会变成结构化验收项。
3. 工作树清理成功时分支可能仍在。
4. 五种沙箱后端只有本地后端落地；是否需要审批只看外部副作用标记。
5. 无工作树时 Git 视图会回退到任务目录下的浅克隆仓库。
6. URL 抓取失败会写一份「失败说明」并禁止模型补写，这是明确的防幻觉措施。

## 9. 与其它模块的分界

| 方向 | 内容 |
|---|---|
| 输入 | 任务记录、项目记录、任务模板、来源条目与附件、权限定义 |
| 输出 | 工作区与输入文件、任务提示词、工作树路径与分支、Git 差异视图、依赖环境路径、PR 预览数据 |
| 不讲 | 产物发布与内容寻址（存储）、工具权限（Agent 运行时）、GitHub 副作用（数据源）、完成判定（执行调度器） |
