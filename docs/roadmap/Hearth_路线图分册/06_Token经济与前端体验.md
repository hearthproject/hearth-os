## Token 经济

目标不是“少用 Token”，而是“每次有效完成更省”。Token、成本、延迟和人工分钟必须一起看，不能通过降低质量制造虚假节省。

### 预算层级

```text
全局日预算
  → 用户/项目预算
  → Task 预算
  → Run 预算
  → Step 预算
  → 单次上下文注入预算
  → 输出 Token 预算
```

预算包括 Token、成本、时间、工具调用次数、网络请求和人工打断。任何一级耗尽都必须暂停、降级或转人工，不能静默透支。

### Token Governor

Token Governor 是跨执行器的成本控制面：

- 规则优先：不需要模型的任务直接走确定性路径；
- 任务分类：判断任务族、复杂度、风险和隐私级别；
- 模型目录：维护能力、价格、延迟、上下文和可用性；
- Context Compiler：构建最小充分上下文；
- Router：按预期成功率/成本选择执行器；
- Cache：复用解析、检索、摘要和已验证产物；
- Meter：实时记录输入、输出、缓存和工具开销；
- Watchdog：发现异常消耗、循环和预算超支；
- Attribution：把成本归因到任务、项目、技能和执行器。

### Context Compiler

Context Compiler 把“系统知道的一切”压缩成“这次任务真正需要的证据”。Context Pack 通常包含：

1. 目标和验收标准；
2. 当前任务状态；
3. 用户明确约束和偏好；
4. 相关事实与来源引用；
5. 必要文件片段和 artifact 引用；
6. 可用工具和权限；
7. 输出 schema；
8. 预算和截止时间；
9. 已知失败和禁止路径；
10. 需要人决策的问题。

规则：

- 不把完整聊天历史当上下文；
- 不把完整邮箱、仓库或网页塞入；
- 长材料先索引、分页、检索和摘要；
- 只保留有来源的断言；
- 用稳定前缀和缓存友好结构复用系统提示；
- 摘要不能丢掉关键限定条件、数字和引用；
- 任务结束后清理 Working Memory。

### 模型与执行器阶梯

| 层级 | 能力 | 典型用途 | 成本策略 |
|---|---|---|---|
| T0 确定性 | 规则、SQL、脚本、API、diff | 过滤、转换、对账、读取 | 不调用模型 |
| T1 本地分类器 | 小模型、embedding、规则模型 | 分类、优先级、实体识别 | 本地、低延迟 |
| T2 小模型 | 短上下文、结构化输出 | 摘要、提取、短草稿 | 按量、严格上限 |
| T3 Native 大模型 | 通用推理与工具 | 短链路规划、复杂分类 | 中等成本 |
| T4 Codex | 长链路、多文件、复杂产物 | 代码、研究、长文档 | 高成本、强验证 |
| T5 Human | 判断、责任、接管 | 高风险、歧义、不可逆 | 最稀缺，需预算 |

路由按任务形态、历史成功率、隐私和成本动态选择，不按工具偏好。

### 增量读取

优先使用文件 diff 和版本比较、增量同步和游标、按页/段/表/行检索、文档索引和引用定位、结构化字段提取、重复材料摘要、artifact 引用、相关代码文件和测试结果、网页可访问性树和页面 diff。

### 缓存、批处理与本地模型

- 缓存解析、检索、摘要、embedding 和已验证产物；
- 能批量聚合的低价值任务不逐条调用大模型；
- 隐私敏感、低延迟或离线任务优先本地模型；
- 本地模型不是免费：仍要计算延迟、维护和质量成本；
- 缓存必须有版本、失效和删除策略，不能复活已遗忘内容。

### 硬预算与异常停止

- 每级预算有硬上限；
- 循环、重复工具调用和异常上下文增长触发 Watchdog；
- 预算耗尽后暂停或降级，不静默继续；
- 用户能查看“为什么花这么多”；
- 人工打断也是成本；
- 高风险任务不能为了省预算跳过验证。

### 成本归因与指标

- 每任务、项目、执行器、模型、技能和用户可见动作的成本；
- Verified Success per dollar；
- Token per verified task；
- 人工分钟与 Token 的联合下降；
- 缓存命中、重复读取和无效重试；
- 异常消耗和预算停止次数。

### 反模式

- 只优化 Token，不优化人工分钟和成功率；
- 用更小模型反复失败；
- 把所有记忆和全文塞入上下文；
- 用自然语言摘要替代结构化提取；
- 重试不设上限；
- 缓存污染；
- 隐藏成本；
- 为省模型调用跳过验证或审批。

### 默认策略

1. 能规则/脚本就不调用模型；
2. 能结构化就不生成自然语言；
3. 能引用 artifact 就不重复全文；
4. 能小模型就不大模型；
5. 能缓存就不重复；
6. 能停止就不过度重试；
7. 能转人工就不做高风险无人值守。

## 前端与移动端体验

Hearth 的前端不是展示 Agent 内部架构的控制台，而是安静的注意力界面。

### 设计原则

1. **任务优先**：用户看到要完成的事，不是模型、工具和线程；
2. **一个状态一个主动作**：任务卡任何时刻只有一个最值得点击的动作；
3. **渐进披露**：默认只显示目标、状态、证据和下一步；
4. **安静默认**：没有需要人的事情就不打扰；
5. **状态诚实**：不把运行中伪装成即将完成，不把模型说完成显示成已完成；
6. **手机对等**：手机能完成查看、审批、接管、发起和通知；
7. **无内部术语**：主界面不出现 Worker、Harness、Token、Mandate；
8. **界面先出现**：每个增量先明确用户看到什么、能点什么、失败后怎么恢复，再接后端实现。

前端不是后端完成后的展示层，而是产品纵向切片的一部分。Stage 0 用原型验证信息架构，Stage 1 用真实页面连接真实状态，之后每个阶段都把新增能力投影为可操作界面。功能只有在浏览器中有完整用户路径、证据和恢复入口，才算进入阶段验收。

### 信息架构

主导航保持四项：

```text
今日  |  需要你  |  产物  |  设置
```

- **今日**：正在做、刚完成、接下来要做什么；
- **需要你**：审批、补充信息、失败接管和异常；
- **产物**：报告、文档、代码、表格、截图、回执；
- **设置**：连接、记忆、权限、设备、通知和预算。

“新任务”是全局动作，不占导航项。桌面端使用 `⌘K` / `Ctrl+K`，移动端使用明显悬浮按钮。

### 首页

首屏回答：今天有什么、什么需要我、正在做什么、最近完成了什么。默认不展示 Token、模型名、执行器名、内部步骤和调试日志；需要时进入详情查看。

### 任务卡

任务卡应回答：

- 这是什么任务？
- 现在进行到哪一步？
- 有没有产物或验证证据？
- 是否需要我？
- 我下一步能做什么？

字段包括标题、状态、关键阶段进度、产物、验证、风险、主动作和时间。每个状态只有一个主动作。

### 状态与主动作

| 状态 | 用户看到 | 主动作 |
|---|---|---|
| 排队中 | 等待设备或时间 | 调整优先级 |
| 执行中 | 当前阶段 | 查看进度 |
| 等待审批 | 将要发生什么 | 审批 |
| 等待信息 | 缺少什么 | 补充信息 |
| 失败 | 原因和补救 | 恢复/重试/转人工 |
| 已完成 | 产物和验证 | 查看产物 |

### 需要你

“需要你”只收集真正阻塞人的事项：审批、补信息、失败接管、高风险确认。纯状态变化和可自动重试的失败不进入。

### 审批界面

审批卡必须让用户在十秒内判断：动作、账户、收件人/资源、附件和内容、可逆性、有效期、失败补偿。高风险动作显示真实范围、差异、二次确认和撤销方式。

### 产物中心

产物是可检查的交付物，不是附件列表：

- 版本、来源任务和执行器；
- 生成时间、哈希和大小；
- 验证结果与证据；
- 预览、下载、复制链接；
- 与上一版 diff；
- 相关审批和回执；
- 删除、归档和导出。

### 详情与时间线

详情页展示目标、约束、计划、关键工具调用、产物与验证、审批和回执、错误/重试/换路、预算与成本、关联记忆和技能。默认不展示模型内部思维过程；展示可审计事件、证据和决策原因。

### 新任务

支持自然语言、文件和图片、项目/联系人/截止时间、自主级别和验收标准预览。用户只写“帮我整理一下”时，系统应生成可编辑任务卡，而不是立刻无边界执行。

### 接管界面

显示当前浏览器/桌面，明确说明需要用户做什么；暂停自动输入；允许操作、批注、补充信息；记录接管前后状态；支持交还、缩小范围和终止。

### 通知

只用于高信号事件：需要审批、补充信息、失败无法恢复、用户明确关心的完成、设备离线阻塞、安全异常。

规则：同一任务聚合、静默时段、先摘要后详情、推送脱敏、点击直达动作、关闭渠道后不得绕过、通知频率与任务价值一起评估。

### 手机端

手机优先 PWA，Stage 4 只承担五件事：

1. 查看任务与产物；
2. 审批高风险动作；
3. 接管异常任务；
4. 发起新任务；
5. 接收高信号通知。

手机不应：默认运行完整 Agent、持有长期主凭据、直接暴露本地端口、后台无界执行高风险任务、用推送正文泄露敏感信息。

安全设计：安全隧道或推送中继、短期码和公钥配对、会话过期与生物识别、审批绑定 nonce/参数/过期时间、设备丢失可撤销、离线只读缓存不产生副作用。

### 可访问性与性能

键盘完成主要流程；不只依赖颜色；屏幕阅读器和可访问性标签；减少动画和深色模式；首屏快速加载、长列表虚拟化；弱网显示缓存和明确状态；中英文不截断关键动作；单手操作时主动作在可达区域。

### 体验指标

- 用户理解当前状态的时间；
- 从“需要你”到完成审批的时间；
- 审批误点率和撤销率；
- 每任务打断次数；
- 手机完成关键动作的成功率；
- 通知打开后的处理率；
- 找不到产物或恢复入口的次数。

## 与 MVP 的关系

MVP 必须让用户通过浏览器完成创建、查看、审批演练、取消、重试、恢复和取回产物。Stage 0 先做可点击原型，Stage 1 D1.1 连接真实任务状态，D1.3 达到完整 MVP。

没有真实 Web 路径的“MVP”不成立；没有失败态和恢复入口的界面也不算完成。
