## 这一增量解决什么

Hearth 能长期驻留，用户能看到资源、任务、失败和健康状态，不需要每天维护。

Stage 6 把单机产品变成长期驻留、可迁移、可撤销的个人 Agent OS；多设备是同一逻辑身份的能力扩展，不是复制多个 Agent。

## 开始前

- 单设备的安装、恢复、备份、安全和升级路径已稳定。
- 事件、lease、fencing token、记忆版本和设备身份已有稳定契约。
- 多设备必须共享一个逻辑身份、事件、记忆和授权，同时不绕过审批、幂等和撤销。
- D6.4 的交付物已经验收；未通过时不进入本增量。

## 实施步骤

1. 实现资源调度、配额、并发上限和公平性。
2. 加入 watchdog、自动恢复、日志轮转和磁盘管理。
3. 建立长期指标、健康检查和维护模式。
4. 对资源耗尽、内存泄漏和状态漂移进行压力测试。
5. 评估远程 Sandbox 是否必要，默认不引入新的安全边界。
6. 让用户能导出诊断信息并安全降级。

## 数据与接口契约

| 检查点 | 必须满足 |
| --- | --- |
| 同步事实 | 事件按 cursor 增量同步；投影可从事件重建；冲突有明确处理。 |
| 单写者 | lease 与 fencing token 保证同一任务只有一个执行权；离线队列不能重复副作用。 |
| 设备撤销 | 撤销设备立即失效其会话、审批和读取权限，同时保留可审计记录。 |
| 迁移完整性 | 备份、恢复、迁移和升级必须验证事件、产物、记忆、技能与凭据引用。 |
| 长期运行 | 健康检查、配额、资源回收、维护模式与 kill switch 可观测、可恢复。 |

## 交付物

- 资源/并发配额
- watchdog 与日志轮转
- 长期运行指标
- 资源耗尽降级演练

## 验证清单

- [ ] 长期运行无内存泄漏和状态漂移；资源耗尽可安全降级；维护模式不丢任务；用户能导出诊断信息。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 同步冲突或设备离线 | 任务显示设备与同步状态，不把离线误判为失败。 | 保留本地队列、重连后按 cursor 合并，避免重复执行。 |
| 旧设备仍可访问 | 设备状态标记“撤销未完成”，阻断审批和读取。 | 使会话失效、轮换密钥、清除本地缓存，并重新验证。 |
| 迁移后数据不一致 | 恢复进入“需要验证”，阻止对外宣称完成。 | 对比事件、产物、记忆与技能清单，修复后重跑迁移演练。 |

## 本增量不包含

- 不把多个不一致的 Agent 包装成多设备支持。
- 不用同步冲突或离线队列解释重复外部动作。
- 不在没有迁移演练和设备撤销的情况下宣布 v1.0。
