## 这一步要交付什么

用户可以导出、备份、恢复和迁移 Hearth；升级失败可以回滚，历史事件、记忆和技能保持一致。

Stage 6 把单机产品变成长期驻留、可迁移、可撤销的个人 Agent OS；多设备是同一逻辑身份的能力扩展，不是复制多个 Agent。

## 开始前

- 单设备的安装、恢复、备份、安全和升级路径已稳定。
- 事件、lease、fencing token、记忆版本和设备身份已有稳定契约。
- 多设备必须共享一个逻辑身份、事件、记忆和授权，同时不绕过审批、幂等和撤销。
- D6.3 的交付物已经验收；未通过时不进入本增量。

## 四个实施工作包

> 每个工作包都要产生可运行的代码、可复现的验证或明确的界面结果；只写接口或只做页面都不算完成。

### 01 · 加密备份与完整恢复

备份包含事件范围、产物根、记忆引用、技能版本、配置和校验清单，使用独立密钥加密。恢复先验证版本、校验和与密钥，再在隔离目录重放事件；只有事件、产物、记忆和技能验证全部通过后才切换为可用实例。

### 02 · 迁移清单与版本锁定

每次升级生成 MigrationPlan，列出源版本、目标版本、schema 变更、执行器版本、不可逆步骤、备份引用和回滚路径。升级前检查磁盘、权限、队列和兼容性；执行器版本锁定，避免恢复后静默使用不同行为。

### 03 · 升级、回滚与迁移验证

升级按步骤执行并记录 checkpoint，失败时自动进入维护模式并恢复备份。回滚只恢复已知可用版本，保留失败证据；迁移后核对事件连续性、产物哈希、记忆来源、技能签名和凭据引用，任何一项不一致都阻断启动。

### 04 · 空库演练与用户健康检查

从空数据库完成安装、创建任务、备份、删除数据、恢复、升级和回滚，确认不依赖手工改库。健康页显示版本、最后备份、迁移状态、已知限制和下一步；验收要求历史事件、记忆、技能和凭据引用在迁移后保持一致。

## 工程落点

### 主要目录与模块

- `apps/hearthd/sync` — 事件游标、增量拉取、重连与投影副本
- `packages/devices/router` — 能力目录、路由、lease、fencing 与单写者
- `packages/devices/security` — 远程撤销、密钥轮换、配对与设备审计
- `packages/backup` — 加密备份、恢复、导出/导入与迁移清单
- `packages/upgrade` — schema migration、版本锁定、升级检查与回滚
- `apps/hearthd/operations` — 调度、配额、watchdog、日志与维护模式
- `apps/web` — 设备状态、健康检查、诊断导出与恢复入口

### 关键接口

| 接口 | 必须保持的契约 |
| --- | --- |
| `SyncCursor` | deviceId、stream、lastEventId、lastSyncedAt、filterHash、resumeToken；重连不能跳过事件。 |
| `DeviceLease` | taskId、deviceId、scope、expiresAt、fencingToken；同一执行权最多一个有效写者。 |
| `BackupManifest` | backupId、schemaVersion、executorVersions、eventRange、artifactRoots、memoryRefs、checksum、encryption；恢复必须可验证。 |
| `MigrationPlan` | fromVersion、toVersion、preconditions、backupRef、steps、verification、rollback；升级前必须通过检查。 |
| `HealthSnapshot` | serviceState、disk、memory、queueDepth、stuckTasks、lastBackup、knownLimits；面向用户的健康解释。 |
| `RevocationRecord` | deviceId、reason、requestedAt、sessionsInvalidated、keysRotated、localEraseState、auditId；撤销必须可追踪。 |

### 共享验证命令

```bash
pnpm test:sync：断线、乱序、重复、游标丢失和敏感字段过滤
pnpm test:devices：租约、 fencing、离线交接、撤销与密钥轮换
pnpm test:backup：空库安装、恢复、迁移、升级失败和回滚
pnpm test:soak：长时间运行、资源耗尽、状态漂移和自动恢复
```

## 验收演练

1. 从干净的数据目录启动 hearthd，打开 [D6.4 页面](/delivery/stage-6/d6-4)，确认当前页面没有依赖浏览器缓存或手工种子数据。
2. 按顺序完成四个工作包：加密备份与完整恢复、迁移清单与版本锁定、升级、回滚与迁移验证、空库演练与用户健康检查。每完成一个工作包，保存对应测试输出、截图或产物版本。
3. 复现失败案例“同步冲突或设备离线”。页面必须显示“任务显示设备与同步状态，不把离线误判为失败。”，然后按“保留本地队列、重连后按 cursor 合并，避免重复执行。”恢复；不得出现重复副作用或未登记状态。
4. 重启服务并重新打开任务，确认运行状态、审批、产物和恢复入口都来自持久投影，而不是只存在于当前页面。
5. 运行上方的共享验证命令并导出证据。完成门槛是：迁移后事件、产物、记忆、技能和凭据引用可验证；回滚可用；旧数据不丢失；升级不要求手工修改数据库。

## 交付物

- 加密备份/完整恢复
- schema 迁移与回滚
- 数据导出/导入
- 从空库安装演练

## 完成判定

- [ ] 迁移后事件、产物、记忆、技能和凭据引用可验证；回滚可用；旧数据不丢失；升级不要求手工修改数据库。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 同步冲突或设备离线 | 任务显示设备与同步状态，不把离线误判为失败。 | 保留本地队列、重连后按 cursor 合并，避免重复执行。 |
| 旧设备仍可访问 | 设备状态标记“撤销未完成”，阻断审批和读取。 | 使会话失效、轮换密钥、清除本地缓存，并重新验证。 |
| 迁移后数据不一致 | 恢复进入“需要验证”，阻止对外宣称完成。 | 对比事件、产物、记忆与技能清单，修复后重跑迁移演练。 |

## 本增量不包含

- 不把多个不一致的 Agent 包装成多设备支持。
- 不用同步冲突或离线队列解释重复外部动作。
- 不在没有迁移演练和设备撤销的情况下宣布 v1.0。
