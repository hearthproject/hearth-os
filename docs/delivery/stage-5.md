# Stage 5 · 记忆与进化

<p class="lead">让 Hearth 积累个人上下文并改进方法，但记忆污染和技能漂移不能变成不可解释的黑箱。顺序是先让记忆可纠正，再可遗忘，再让技能可评估，最后才允许晋升。</p>

## 前置条件

- 任务来源、权限和审批边界稳定，敏感信息已被正确分级。
- 记忆写入、检索和注入不会绕过 Mandate 或扩大权限。
- 已有代表性任务、成功/失败样本和可重复的评估集。

## 开发步骤

1. **交付 Memory Core。** 落地五类记忆、来源、敏感度、时间、置信度、作用域和检索预算；提供记忆浏览器与“为什么召回”视图。
2. **处理冲突与遗忘。** 实现写入冲突、纠正、删除、tombstone、遗忘传播、导出和数据迁移。
3. **挖掘轨迹与技能候选。** 从真实轨迹中提取可复用方法，形成候选、版本、权限和评估集，不允许自动扩大权限。
4. **建立评估与晋升门。** 运行 Shadow、Canary、Promote、Rollback；使用对照评估、安全回归和人工复核。
5. **完成首个晋升案例。** 至少让一个技能走完候选、评估、试点、晋升和回滚的完整链路，并向用户解释原因。
6. **完成 Stage 5 发布。** 评估记忆准确率、注入质量、遗忘、导出、技能收益、权限和安全回归。

## 增量拆分

| 增量 | 用户可见结果 | 完成证据 |
|---|---|---|
| [D5.1](/delivery/stage-5/d5-1) Memory Core 与记忆浏览器 | 用户能查看、理解和纠正被使用的记忆 | 五类记忆、来源、预算、召回解释 |
| [D5.2](/delivery/stage-5/d5-2) 记忆冲突、遗忘与导出 | 错误记忆可纠正，遗忘可传播，数据可导出 | tombstone、传播、导出、迁移测试 |
| [D5.3](/delivery/stage-5/d5-3) 轨迹、技能候选与评估集 | 系统能从任务中提出可复用方法 | 轨迹挖掘、候选、版本、评估样本 |
| [D5.4](/delivery/stage-5/d5-4) Evolution 晋升门与 Stage 5 发布 | 新方法有对照证据，并可回滚 | Shadow、Canary、Promote、Rollback 案例 |

## 退出验收

- [ ] 记忆可解释、可纠正、可遗忘、可导出，遗忘能够传播。
- [ ] 记忆注入准确率达标，敏感信息不进入不允许的上下文。
- [ ] 技能晋升有对照评估，权限不会因自进化扩大。
- [ ] 至少一个技能完成晋升与回滚演示。
- [ ] 用户能理解系统为什么召回某段记忆或采用某个新方法。

## 本模块不做

- 不做没有来源、没有评估、没有回滚的自进化。
- 不让记忆投毒改变权限、审批策略或系统事实。
- 不用“模型觉得有用”替代可重复评估。
