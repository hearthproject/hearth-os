# 2.3 起草、审批与外部写入

## 当前状态

- **已实现：** 草稿可编辑、保存、丢弃；提交后生成一次性、短时有效审批；批准后由效果账本写入本地发件箱，或在配置 SMTP 账户后提交真实发送审批并保存回执；拒绝或失效会同步草稿状态。
- **仍未完成：** 未配置 SMTP 时只写本机 `.hearth/outbox`；真实账户、退信与垃圾邮件语义、附件选择尚未验收或实现；日历和其他外部系统写入未实现。

## 目标

让 Hearth 能在用户确认后发送邮件、修改日历或写入其他工作系统，并保证同一次操作不会重复执行。先用测试账户跑通，再接触真实账户。

## 怎么做

1. 先生成草稿，不直接发送；草稿要能修改、保存和丢弃。
2. 审批页必须展示准确的对象、账户、内容、附件、影响和是否可撤销。
3. 审批只在短时间内有效，并且只能使用一次；用户拒绝后不执行。
4. 先用测试账户完成“读取—起草—审批—发送或写入—回执”的完整流程。
5. 发送或写入后保存回执；失败时说明是否可能已经执行，并提供核对和补救方式。
6. 只把任务真正需要的背景信息交给执行过程，并显示使用了哪些信息。
7. 没有隔离措施时，不直接接管用户的主账户。
