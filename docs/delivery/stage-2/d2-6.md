## 这一步要交付什么

Hearth 成为可处理研究、邮件、日历、文档和网页任务的日常操作员。

Stage 2 从只读能力逐步走向真实写入。每增加一种权限，都先证明来源、撤销、审批和回执仍然成立。

## 开始前

- Stage 1 的本地 MVP、两个任务族、审批、幂等、回执和恢复路径稳定。
- 已限定首位用户的真实邮箱、日历、文档或数据账户，并准备测试账户。
- 连接器只能申请最小范围；任何写入都必须有预览、审批和回执。
- D2.5 的交付物已经验收；未通过时不进入本增量。

## 四个实施工作包

> 每个工作包都要产生可运行的代码、可复现的验证或明确的界面结果；只写接口或只做页面都不算完成。

### 01 · 代表性任务验收矩阵

覆盖只读研究、文档转换、网页研究、邮件草稿、日历冲突和测试账户写入，每个任务固定输入、验收器、失败样本和风险级别。同一任务同时比较人工、直接 Codex 和 Hearth，记录人工分钟、成功率、Token、返工与失败类型。

### 02 · 失败分类与连接器降级

统一过期授权、限流、来源缺失、网页不可用、审批拒绝、结果未知和部分成功等失败类别。每类都有用户可见说明和下一步，连接器不可用时保留已完成步骤与草稿，恢复授权后不重放成功的外部动作。

### 03 · 隐私、导出与跨账户审计

生成数据导出与隐私说明，列明保存哪些来源、凭据、摘要和日志，如何撤销与删除。自动扫描跨账户引用、未授权来源和敏感字段进入上下文的情况；发现串扰必须阻断发布并清理缓存与索引。

### 04 · Stage 2 发布与剩余边界

完成安全与评测报告，列出仍不能自动执行的高风险动作、需要人工确认的场景和已知限制。确认用户理解每个外部动作的来源、审批参数和回执，然后才进入 Stage 3 的桌面执行。

## 工程落点

### 主要目录与模块

- `apps/hearthd/connectors` — OAuth、游标同步、来源归一化与撤销
- `packages/connectors` — 邮件、日历、文档和数据的最小权限适配器
- `packages/executors/python-sidecar` — 解析、OCR、表格清洗与格式转换
- `packages/executors/browser` — Playwright worker、下载验证与人工接管
- `packages/context` — Context Compiler、来源裁剪与敏感字段过滤
- `packages/memory` — Memory v0、召回原因与基础遗忘
- `packages/governor` — Token 预算、阶梯路由、缓存与异常停止

### 关键接口

| 接口 | 必须保持的契约 |
| --- | --- |
| `SourceRef` | sourceId、connectorId、accountId、objectId、retrievedAt、scope、contentHash、revocationState；引用必须能回到原始对象。 |
| `ConnectorEffect` | effectType、target、parameters、dryRun、approvalId、idempotencyKey；连接器只执行已登记动作。 |
| `ContextPack` | taskId、selectedSources、tokenBudget、redactions、recallReasons；不得包含未授权账户内容。 |
| `MemoryRecord` | kind、value、provenance、confidence、sensitivity、observedAt、expiresAt；纠正与删除必须可追踪。 |

### 共享验证命令

```bash
pnpm test:connectors：授权、过期、撤销、限流和跨账户隔离
pnpm test:effects：预览、参数绑定、幂等、outbox 重投与对账
pnpm test:browser：注入、下载、超时、接管和网络出口策略
pnpm eval:operator：研究与日常任务对比人工分钟、Token 和成功率
```

## 验收演练

1. 从干净的数据目录启动 hearthd，打开 [D2.6 页面](/delivery/stage-2/d2-6)，确认当前页面没有依赖浏览器缓存或手工种子数据。
2. 按顺序完成四个工作包：代表性任务验收矩阵、失败分类与连接器降级、隐私、导出与跨账户审计、Stage 2 发布与剩余边界。每完成一个工作包，保存对应测试输出、截图或产物版本。
3. 复现失败案例“连接器过期或被撤销”。页面必须显示“任务显示重连要求，保留草稿和已完成步骤。”，然后按“重新授权后继续，不重放已成功的外部动作。”恢复；不得出现重复副作用或未登记状态。
4. 重启服务并重新打开任务，确认运行状态、审批、产物和恢复入口都来自持久投影，而不是只存在于当前页面。
5. 运行上方的共享验证命令并导出证据。完成门槛是：Stage 2 退出条件全部满足；至少一个真实测试账户闭环稳定；不出现跨账户数据串扰；用户能理解每个外部动作的来源和回执。

## 完成判定

- [ ] Stage 2 退出条件全部满足；至少一个真实测试账户闭环稳定；不出现跨账户数据串扰；用户能理解每个外部动作的来源和回执。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 连接器过期或被撤销 | 任务显示重连要求，保留草稿和已完成步骤。 | 重新授权后继续，不重放已成功的外部动作。 |
| 网页内容试图扩大权限 | 任务暂停并提示内容不可信，要求用户确认。 | 丢弃注入指令，保留来源证据并重新生成安全计划。 |
| 写入结果未知 | 显示“等待对账”，不显示成功或允许盲目重试。 | 查询测试账户或外部系统，确认后补写回执或执行补偿。 |

## 本增量不包含

- 不在一个连接器上证明权限、幂等和回执之前扩展多个渠道。
- 不自动执行高风险提交、公开发布或不可逆分享。
- 不让网页内容、附件或模型输出直接改变权限。
