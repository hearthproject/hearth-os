# 剩余路线

<p class="lead">剩余路线不再按“先写哪个模块”组织，而按“还缺哪类真实验收”组织。每条工作流都必须有明确的退出条件，不能因为代码合并或页面完成就自动推进。</p>

## 推进原则

1. **真实验收优先于新功能。** 已经有代码闭环的能力，先用真实账户、真实设备或真实任务证明，再决定是否扩展。
2. **风险先于覆盖率。** 桌面高风险动作、外部写入、设备丢失和备份恢复必须先有失败演练。
3. **证据先于结论。** 每个阶段保留任务输入、运行清单、产物摘要、审批和回执；失败也要保留。
4. **不自动晋级。** 阶段状态由验收记录决定，不由提交数量、页面数量或测试数量决定。

## 七条工作流

| 工作流 | 目标 | 退出条件 |
|---|---|---|
| W1 日常内容真实验收 | 接入真实邮件/日历，完成日常内容闭环 | 10–15 个真实任务；时间、准确率、恢复和用户意愿有记录 |
| W2 桌面安全与高风险 | 补齐遮挡、隔离桌面、高风险动作与补偿 | 至少 5 个真实桌面任务；敏感区域不外泄；接管和失败演练通过 |
| W3 手机入口与主动服务 | 手机审批/接管，主动任务打扰可控 | PWA 配对、推送、远程审批；5–10 个主动任务平均打断不超过一次 |
| W4 记忆与方法生产对照 | 证明记忆和方法真的有用且可回退 | 错误记忆/错误方法演练；采用前后成功率、人工时间、成本对照 |
| W5 多设备与设备丢失 | 真实双设备切换、撤销和恢复 | 断网恢复、设备丢失、令牌轮换、备份恢复与迁移核对通过 |
| W6 长期运行与升级 | 数周连续运行与版本升级回退 | 资源/状态漂移数据；升级失败可回退；全任务类型回归矩阵 |
| W7 v1.0 发布 | 形成可安装、可升级、可退出的版本 | 安装/升级/迁移/退出验收；发布说明与已知限制 |

## W1 · 日常内容真实验收

**为什么现在做：** 来源、提取、草稿、审批、本地发件箱已经有代码闭环，但没有真实账户和真实发送回执。没有这一步，阶段二不能称为完成。

**工作内容：**

- 接入一个真实测试邮箱和一个日历账户，先只读，再写入。
- 用 10–15 个真实日常任务覆盖：邮件摘要、日程整理、文档提取、表格清洗、网页资料归档、草稿回复。
- 记录每个任务的耗时、人工修改量、失败原因和恢复方式。
- 明确“本地发件箱”和“真实发送”的界面差异，避免用户误判。

**退出条件：**

- 至少 10 个任务通过，且失败任务有可恢复记录。
- 真实发送有回执；未发送时界面明确显示未发送。
- 用户能在不看内部日志的情况下核对来源、产物和外部动作。

## W2 · 桌面安全与高风险

**为什么现在做：** Windows 助手已经能配对、观察、接管和执行低风险动作，但敏感区域遮挡、隔离桌面、高风险确认和补偿仍缺失。没有这些边界，不能扩大桌面自动化范围。

**工作内容：**

- 敏感区域遮罩与截图脱敏。
- 高风险动作预览、二次确认和可恢复补偿。
- 隔离桌面或等效的输入边界验证。
- 窗口丢失、权限变化、用户接管和 UIA setvalue 的失败演练。

**退出条件：**

- 至少 5 个真实桌面任务完成，成功率、接管次数和失败原因有记录。
- 敏感区域不会进入截图、日志或模型上下文。
- 高风险动作在没有明确批准时无法执行。

## W3 · 手机入口与主动服务

**为什么现在做：** 主动建议、收件箱和注意力预算已经存在，但入口只在同机 Web；手机 PWA、配对、推送和远程审批尚未实现。

**工作内容：**

- 手机 PWA 与短期配对。
- 推送/通知渠道与送达记录。
- 移动端审批、拒绝、稍后提醒和接管。
- 5–10 个真实主动任务的打扰验收。

**退出条件：**

- 手机可以完成审批和接管，丢失后可立即撤销。
- 主动任务平均每个任务打断不超过一次。
- 用户能临时暂停、设置安静时段并查看预算使用。

## W4 · 记忆与方法生产对照

**为什么现在做：** 记忆候选、召回、纠正、遗忘、方法评估、晋升和回退都有代码闭环，但缺少真实长期使用和采用前后对照。

**工作内容：**

- 错误记忆注入、纠正、遗忘和导出核对。
- 错误方法演练：候选不得扩大权限，失败必须可回退。
- 真实任务的基线/采用后对照：成功率、人工时间、token 和审批次数。

**退出条件：**

- 错误记忆可以被发现、纠正和遗忘，导出不含已遗忘正文。
- 方法晋升有试跑证据，回退保留原因和审计。
- 至少一组真实任务证明采用后更好，或明确记录没有改进。

## W5 · 多设备与设备丢失

**为什么现在做：** 增量同步、对端认证、租约、撤销、令牌轮换和加密备份已经存在，但没有两台真实设备、断网恢复和设备丢失演练。

**工作内容：**

- 两台真实设备完成增量同步和任务接管。
- 断网、恢复、冲突和 epoch fencing 演练。
- 设备丢失后的撤销、令牌轮换和读取阻断验证。
- 加密备份恢复后核对任务、产物和工作区边界。

**退出条件：**

- 两台设备可以切换任务，旧 owner 的提交被拒绝。
- 撤销设备后无法审批、接管或读取。
- 备份恢复可重复，且明确列出未包含的产物和附件。

## W6 · 长期运行与升级

**为什么现在做：** 健康快照、维护、诊断和加密备份已经存在，但没有数周连续运行、资源漂移和版本升级回退数据。

**工作内容：**

- 至少数周连续运行，记录内存、磁盘、任务积压和维护结果。
- 建立应用版本升级与失败回退流水线。
- 建立全任务类型回归矩阵。
- 演练 schema 不兼容、维护失败和诊断导出。

**退出条件：**

- 连续运行期间没有不可恢复的状态漂移。
- 升级失败可以回退，数据不丢。
- 维护失败会标记 degraded，并能导出脱敏诊断。

## W7 · v1.0 发布

**为什么最后做：** v1.0 不是“功能更多”，而是安装、升级、迁移、退出和已知限制都可以被用户核对。

**工作内容：**

- 安装包或一键启动方式。
- 升级、迁移和退出说明。
- 发布说明、已知限制和支持边界。
- 最终整体验收。

**退出条件：**

- 新用户可以在不看源码的情况下安装、配置和使用。
- 升级和迁移有可回退路径。
- 发布说明不把部分完成写成已完成。

## 里程碑顺序

| 里程碑 | 包含工作流 | 完成标志 |
|---|---|---|
| M1 可用性收敛 | W1、W2 | 日常内容与桌面各有真实任务通过；高风险边界可证明 |
| M2 入口与学习 | W3、W4 | 手机审批可用；记忆/方法有生产对照 |
| M3 可靠性与迁移 | W5、W6 | 双设备、设备丢失、长期运行和升级回退有证据 |
| M4 v1.0 | W7 | 安装、升级、迁移、退出和发布说明完成 |

里程碑可以并行，但不能跳过退出条件。某个工作流没有真实证据时，后续里程碑只能保持“部分完成”。

## 明确不做

- 不把主动建议做成自动执行器。
- 不让模型自行扩大工具、网络或审批权限。
- 不用模拟邮件、模拟设备或假数据替代真实验收。
- 不在没有失败演练的情况下扩大高风险桌面动作。
- 不为了“看起来完整”提前拆微服务或多 Agent 团队。

## 停止条件

出现以下信号时，应暂停扩展并回到风险与恢复：

- 真实任务连续失败且无法解释。
- 外部动作出现重复执行或无法对账。
- 设备撤销后仍能读取或操作。
- 备份恢复后出现不可解释的数据丢失。
- 用户无法在看不懂内部日志的情况下判断任务是否完成。

更多风险与停止条件见[风险与停止条件](/reference/risks)。
