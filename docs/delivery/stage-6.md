# Stage 6 · 多设备与长期运行

<p class="lead">把单机产品扩展为长期驻留、多设备、可迁移、可撤销的个人 Agent OS。多设备不是复制多个 Agent，而是共享一个逻辑身份、事件、记忆和授权。</p>

## 前置条件

- 单设备安装、恢复、备份、安全与升级路径已经可用。
- 事件、lease、fencing token、记忆版本和设备身份有稳定契约。
- 多设备不会绕过审批、幂等和撤销边界。

## 开发步骤

1. **实现读取与事件同步。** 建立设备身份、cursor、增量同步、冲突处理、事件重放和投影一致性。
2. **加入能力路由与离线队列。** 按设备能力分配 GUI、文件和执行任务；断网时排队，恢复后幂等重放，不重复副作用。
3. **完成撤销与密钥轮换。** 处理设备丢失、远程撤销、密钥轮换、会话失效和安全迁移。
4. **打通备份、恢复与升级。** 支持加密备份、完整恢复、导出/导入、schema migration、执行器版本锁定、升级前检查和回滚。
5. **建立长期运行能力。** 加入健康检查、资源配额、日志、监控、资源回收、故障恢复和长期数据迁移演练。
6. **完成系统审计。** 通过所有阶段出口，完成八类任务覆盖审计、安全红队、故障注入、迁移演练、隐私说明、安装器、升级路径和最终评测报告。

## 增量拆分

每个增量现在按四层阅读：结果与门槛 → 四个实施工作包 → 工程落点与接口 → 验收演练。工作包可以拆给不同开发者并行，但必须按依赖顺序合并；只完成一个包不等于完成增量。

| 增量 | 用户可见结果 | 完成证据 |
|---|---|---|
| [D6.1](/delivery/stage-6/d6-1) 多设备读取与事件同步 | 用户在多个设备看到一致任务与产物 | 设备身份、cursor、增量同步、重放 |
| [D6.2](/delivery/stage-6/d6-2) 设备能力路由与离线队列 | 任务去合适设备，断网后可恢复 | 能力路由、离线队列、幂等重放 |
| [D6.3](/delivery/stage-6/d6-3) 设备撤销、密钥轮换与安全迁移 | 设备丢失可立即撤销，数据可安全迁移 | 撤销、轮换、会话失效、迁移演练 |
| [D6.4](/delivery/stage-6/d6-4) 备份、恢复、迁移与升级 | 用户可以完整备份、恢复和升级 | 加密备份、schema migration、回滚 |
| [D6.5](/delivery/stage-6/d6-5) 长期运行、资源调度与运维 | 系统可长期驻留，不需要每天维护 | 健康检查、配额、监控、资源回收 |
| [D6.6](/delivery/stage-6/d6-6) 完整审计与发布 | 一个可安装、可迁移、可撤销的个人 Agent OS | 八类任务覆盖、红队、故障注入、最终评测 |

## 退出验收

- [ ] 一个逻辑 Agent 在多个设备上保持一致，设备切换不丢任务。
- [ ] 离线恢复率达标，设备切换和重试不重复外部副作用。
- [ ] 设备撤销立即可靠，撤销后无法继续审批或接管。
- [ ] 迁移后事件、产物、记忆和技能可验证。
- [ ] 长期运行无内存泄漏、状态漂移或不可解释的权限扩大。
- [ ] 安装、升级、备份、恢复、隐私和数据导出路径完整。

## 本模块不做

- 不把多设备做成多个互不一致的 Agent。
- 不用同步冲突或离线队列作为重复副作用的借口。
- 不在没有迁移演练和撤销能力时宣告系统完成。

## 完成之后

完成本模块后，项目进入长期维护与扩展阶段。后续仍会增加任务族、连接器和优化，但基础产品、恢复、安全、审批和迁移能力不再作为“以后补”的欠账。
