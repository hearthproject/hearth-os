# 交付路线与实施计划

<p class="lead">这份路线只回答两件事：先做什么，后做什么；每个阶段怎样从可用走到可靠。</p>

## 总体目标

Hearth 的目标是把个人数字工作变成可靠的任务。路线不从架构模块出发，而从用户能完成的事情出发：先交付一个最小完整产品，再逐步扩大工作范围、主动性、记忆和多设备能力。

## 六个阶段

每个阶段都包含四个小阶段，点击阶段名称可以进入详细计划。

| 阶段 | 目标 | 完成后得到什么 |
|---|---|---|
| [第一阶段 · 最小完整 MVP](/delivery/stage-1) | 交付一个以 15 个跨行业真实任务为基线、至少通过 10 个的最小完整产品。 | 一个能每天使用、覆盖多个任务族的本地任务工作台 |
| [第二阶段 · 日常内容工作](/delivery/stage-2) | 从首批跨行业任务扩展到邮件、日历、文档、表格和网页。 | 能处理日常内容并在审批后安全写入的个人操作员 |
| [第三阶段 · 桌面操作](/delivery/stage-3) | 让 Hearth 操作没有开放接口的桌面软件和跨应用流程。 | 能操作桌面软件、可暂停、可接管、失败可恢复的助手 |
| [第四阶段 · 主动服务与手机入口](/delivery/stage-4) | 在有限授权内主动工作，并把手机作为审批和接管入口。 | 能在合适时机提醒，并可在手机上审批和接管的助手 |
| [第五阶段 · 记忆与能力进化](/delivery/stage-5) | 让系统积累背景并改进方法，但所有变化都可查看、可纠正、可回退。 | 会积累背景、改进方法且可纠正可回退的助手 |
| [第六阶段 · 多设备与长期运行](/delivery/stage-6) | 让同一套任务、记忆和授权在多台设备上长期安全使用。 | 可多设备使用、可迁移、可长期运行的个人 Agent OS |

## 怎么推进

1. **先完整后扩展。** 先把首批 15 个任务中的至少 10 个做完整，再增加新的信息来源、操作方式和设备。
2. **先只读后写入，先低风险后高风险。** 每一类外部操作都先观察、再起草、再审批执行。
3. **每阶段都用真实任务验收。** 不以代码写完或页面做完作为完成标准。
4. **安全和恢复从第一阶段就有。** 审批、产物、失败恢复、权限边界不放到最后补。

从[第一阶段 · 最小完整 MVP](/delivery/stage-1)开始。
