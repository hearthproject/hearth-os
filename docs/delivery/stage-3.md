# Stage 3 · Computer Operator

<p class="lead">覆盖没有 API 的桌面软件和跨应用流程。顺序是先观察、再接管、再低风险动作，最后才开放高风险动作；无法验证或无法接管时，不允许自动执行。</p>

## 前置条件

- Stage 1–2 的恢复、审批、幂等、回执和网页隔离已经稳定。
- 已明确设备能力、窗口范围、应用白名单和不可逆动作清单。
- 接管与撤销路径先于自动操作完成。

## 开发步骤

1. **注册桌面设备。** 实现设备配对、`agentd` 注册、能力目录、健康检查、权限声明、设备详情、断开与撤销。
2. **建立观察与接管。** 接入可访问性树、截图、窗口范围、实时接管、键鼠暂停/交还、截图脱敏和审计事件。
3. **完成低风险 GUI 动作。** 在应用白名单内完成打开文件、定位菜单、填写草稿、导出结果，并用截图/可访问性树验证结果。
4. **处理半完成与失败。** 检测部分成功、窗口丢失、输入争抢、权限变化和不可恢复状态，提供暂停、接管或回滚。
5. **开放高风险动作。** 加入隔离虚拟桌面、影响预览、二次确认、不可逆动作清单、桌面快照、补偿脚本和恢复演练。
6. **完成 Stage 3 发布。** 用至少 5 个真实桌面任务评估完成率、接管体验、安全边界、Token 和人工分钟。

## 增量拆分

| 增量 | 用户可见结果 | 完成证据 |
|---|---|---|
| D3.1 设备 agentd 与设备可见性 | 用户看到可信设备、能力和在线状态 | 配对、能力目录、健康检查、撤销 |
| D3.2 GUI 观察与人工接管 | 用户能看到窗口、暂停、操作并交还 | 接管界面、窗口范围、状态记录、截图脱敏 |
| D3.3 低风险 GUI 动作与验证 | 白名单应用内完成低风险操作并展示证据 | 应用白名单、动作预览、结果验证、失败重试 |
| D3.4 高风险 GUI 与 Stage 3 发布 | 高风险动作有影响说明、二次确认与补偿 | 隔离桌面、审批、快照、恢复、5 个真实任务 |

## 退出验收

- [ ] 至少 5 个真实桌面任务可以完成并验证。
- [ ] 接管流程可用，用户能暂停、操作、交还或终止。
- [ ] GUI 失败不会留下半完成的高风险状态。
- [ ] 不读取密码库、不越权修改系统安全设置。
- [ ] Token 和人工分钟在可接受范围，用户理解撤销或补偿方式。

## 本模块不做

- 不在无法验证、无法接管时自动执行桌面动作。
- 不开放无边界的系统级控制。
- 不把 OCR 或截图识别当作唯一事实来源。
