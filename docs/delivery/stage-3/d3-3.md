## 这一步要交付什么

Hearth 能在白名单应用中完成打开文件、定位菜单、填写草稿和导出结果等低风险操作，并展示验证截图。

Stage 3 的顺序是观察、接管、低风险动作、高风险动作；无法观察和接管的桌面自动化不具备产品资格。

## 开始前

- Stage 1–2 的恢复、审批、幂等、回执和网页隔离已经稳定。
- 有一台可配对的专用桌面设备，明确哪些窗口、应用和文件范围允许操作。
- GUI 任务可以在隔离桌面中运行，且用户能随时暂停和接管。
- D3.2 的交付物已经验收；未通过时不进入本增量。

## 四个实施工作包

> 每个工作包都要产生可运行的代码、可复现的验证或明确的界面结果；只写接口或只做页面都不算完成。

### 01 · 应用、窗口与动作白名单

按应用、窗口标题、可访问性角色和动作类型建立允许列表，默认拒绝所有未登记对象。文件操作限制在授权根目录，键鼠动作限制在目标窗口内；白名单更新需要审计，不能由网页内容或模型输出自行修改。

### 02 · 定位器与执行前检查

优先使用可访问性角色、名称和控件关系定位元素，坐标只作为最后备选。执行前检查目标窗口仍在前台、元素可见、焦点正确、前置条件成立；窗口漂移、元素消失或权限变化时停止并请求重新定位。

### 03 · 受限输入与动作执行

实现窗口聚焦、键盘输入、鼠标点击、文件选择和滚动等最小动作，禁止读取密码库、修改系统安全设置和操作非白名单应用。每个动作记录目标、参数、执行时间和策略判定，输入内容不得写入无关日志。

### 04 · 前后条件验证与半完成

动作后验证预期窗口、控件值、文件存在或页面状态，并保存截图和可访问性证据。若出现部分输入、窗口切换或文件部分保存，标记“需要检查”并阻止继续；提供重试、人工接管和补偿入口，不能把一次成功点击当成通用能力。

## 工程落点

### 主要目录与模块

- `apps/agentd` — 设备配对、能力声明、健康检查与撤销
- `packages/devices` — 设备身份、会话、能力目录与在线状态
- `packages/desktop-observation` — 窗口边界、截图、可访问性树与脱敏
- `packages/desktop-control` — 白名单、定位器、输入动作与前后条件
- `packages/desktop-verification` — 截图比较、焦点检查、半完成检测
- `packages/approval` — 桌面 Effect Preview、二次确认与补偿说明
- `apps/web` — 设备页、观察视图、实时接管和恢复界面

### 关键接口

| 接口 | 必须保持的契约 |
| --- | --- |
| `DeviceManifest` | deviceId、publicKey、agentdVersion、capabilities、allowedRoots、expiresAt、revocationState；未声明的能力不可调用。 |
| `ObservationFrame` | captureId、windowBounds、screenshotRef、accessibilityTree、capturedAt、redactions；只采集完成任务所需的最小范围。 |
| `DesktopAction` | actionType、targetWindow、locator、preconditions、expectedPostconditions、riskLevel、timeout；执行前必须通过策略检查。 |
| `DesktopReceipt` | actionId、beforeRef、afterRef、verification、partialState、compensation、approvalId；失败时保留可恢复证据。 |

### 共享验证命令

```bash
pnpm test:device：配对、能力越权、离线、撤销和会话失效
pnpm test:desktop：观察、接管、焦点变化、半完成和补偿
pnpm test:desktop-fault：窗口漂移、元素消失、输入争抢和崩溃
pnpm eval:computer：至少 8 个真实桌面任务及失败样本
```

## 验收演练

1. 从干净的数据目录启动 hearthd，打开 [D3.3 页面](/delivery/stage-3/d3-3)，确认当前页面没有依赖浏览器缓存或手工种子数据。
2. 按顺序完成四个工作包：应用、窗口与动作白名单、定位器与执行前检查、受限输入与动作执行、前后条件验证与半完成。每完成一个工作包，保存对应测试输出、截图或产物版本。
3. 复现失败案例“窗口或元素不匹配”。页面必须显示“任务暂停并显示当前窗口截图和需要确认的元素。”，然后按“重新定位、请求接管或调整白名单，不盲目点击坐标。”恢复；不得出现重复副作用或未登记状态。
4. 重启服务并重新打开任务，确认运行状态、审批、产物和恢复入口都来自持久投影，而不是只存在于当前页面。
5. 运行上方的共享验证命令并导出证据。完成门槛是：至少 3 个真实桌面任务完成并验证；不读取密码库、不修改系统安全设置；每个动作有范围；失败可暂停或接管；UI 显示进度与证据。

## 交付物

- 应用/窗口白名单
- 动作预览与验证截图
- 3 个真实桌面任务
- 失败/接管记录

## 完成判定

- [ ] 至少 3 个真实桌面任务完成并验证；不读取密码库、不修改系统安全设置；每个动作有范围；失败可暂停或接管；UI 显示进度与证据。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 窗口或元素不匹配 | 任务暂停并显示当前窗口截图和需要确认的元素。 | 重新定位、请求接管或调整白名单，不盲目点击坐标。 |
| 自动输入与用户争抢 | 自动输入立即暂停，控制权交给用户。 | 等待用户交还并确认焦点、窗口和下一步。 |
| 高风险动作半完成 | 任务显示“需要检查”，隐藏继续按钮并保留快照。 | 按补偿脚本或人工接管恢复，记录未完成影响。 |

## 本增量不包含

- 不在无法观察、无法验证或无法接管时开放自动操作。
- 不读取密码库，不修改系统安全设置，不操作未授权窗口。
- 不把一次成功的坐标点击当成通用 GUI 能力。
