## 这一增量解决什么

用户对不可逆或高影响桌面动作看到完整影响、二次确认和补偿方式；失败后不会留下未知的高风险状态。

Stage 3 的顺序是观察、接管、低风险动作、高风险动作；无法观察和接管的桌面自动化不具备产品资格。

## 开始前

- Stage 1–2 的恢复、审批、幂等、回执和网页隔离已经稳定。
- 有一台可配对的专用桌面设备，明确哪些窗口、应用和文件范围允许操作。
- GUI 任务可以在隔离桌面中运行，且用户能随时暂停和接管。
- D3.3 的交付物已经验收；未通过时不进入本增量。

## 实施步骤

1. 建立隔离虚拟桌面，限制访问范围并记录快照。
2. 列出不可逆动作清单和高风险审批矩阵。
3. 在 Effect Preview 中展示目标、影响、不可逆性和补偿脚本。
4. 实现桌面快照、失败恢复和半完成状态检测。
5. 至少用 5 个代表性桌面任务验收，覆盖接管、高风险审批和恢复。
6. 完成 Stage 3 安全、评测和运维文档，确认用户理解撤销或补偿方式。

## 数据与接口契约

| 检查点 | 必须满足 |
| --- | --- |
| 设备能力 | agentd 注册时声明窗口、文件、键鼠和应用能力；未声明的能力不可调用。 |
| 观察与接管 | 截图、可访问性树和窗口范围组成可审计观察；接管的输入必须暂停自动输入。 |
| 动作验证 | 每个 GUI 动作都有前后状态、窗口范围、截图/可访问性证据和半完成检测。 |
| 安全边界 | 密码库、系统安全设置、未列入白名单的应用和不可逆动作默认禁止。 |
| 高风险执行 | 不可逆或高影响桌面动作必须进入隔离桌面、二次确认和补偿/快照路径。 |

## 交付物

- 隔离虚拟桌面
- 高风险审批与动作清单
- 快照/补偿/恢复演练
- 5 个真实桌面任务

## 验证清单

- [ ] 至少 5 个代表性桌面任务完成；接管和高风险审批可用；无密码库/系统设置越权；失败不留半完成高风险状态；用户理解如何撤销或补偿。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 窗口或元素不匹配 | 任务暂停并显示当前窗口截图和需要确认的元素。 | 重新定位、请求接管或调整白名单，不盲目点击坐标。 |
| 自动输入与用户争抢 | 自动输入立即暂停，控制权交给用户。 | 等待用户交还并确认焦点、窗口和下一步。 |
| 高风险动作半完成 | 任务显示“需要检查”，隐藏继续按钮并保留快照。 | 按补偿脚本或人工接管恢复，记录未完成影响。 |

## 本增量不包含

- 不在无法观察、无法验证或无法接管时开放自动操作。
- 不读取密码库，不修改系统安全设置，不操作未授权窗口。
- 不把一次成功的坐标点击当成通用 GUI 能力。
