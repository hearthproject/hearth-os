# 3.3 分级完成桌面操作

## 当前状态

- **已实现：** 目标应用绑定与执行前聚焦复核；点击、短文本、Enter/Tab/Escape/Ctrl+S；UIA invoke/setvalue 白名单；UWP 宿主窗口映射；命令状态记录和不支持动作结构化拒绝。
- **仍未完成：** 高风险动作预览与二次确认、隔离桌面、快照、补偿，以及真实 UIA setvalue 验收。

## 目标

让 Hearth 能在用户允许的应用里完成低风险桌面操作，并在确认结果后再处理高风险操作。每一步都要能验证，不能只靠“看起来完成了”。

## 怎么做

1. 先做低风险操作：打开文件、定位菜单、填写草稿、导出结果。
2. 每一步都通过窗口内容和操作后的变化确认结果，必要时截图留证。
3. 失败时先停下，说明是窗口丢失、权限变化、输入冲突还是结果不符，再决定重试或转人工。
4. 高风险操作先在隔离桌面中预览影响，要求二次确认，并准备快照或补偿办法。
5. 检测到只完成一半、窗口被关闭或用户开始操作时，立即停止并交还。
6. 不读取密码库，不修改系统安全设置，不执行没有恢复路径的不可逆操作。
