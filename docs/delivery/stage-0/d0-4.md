## 这一增量解决什么

可重复的 12 任务评测、明确的安全边界，以及可运行的类型检查、测试、CI 和 fake executor。

Stage 0 的产出是产品真相与实现契约。没有真实任务、可点击原型和可重复评测，后续开发会把假设当成事实。

## 开始前

- 一个空仓库、可记录的真实工作样本，以及一位愿意持续反馈的首位用户。
- 允许观察全人工流程与直接使用 Codex 的基线，不要求系统已经存在。
- 本阶段不接入真实发送、支付、删除或系统设置修改。
- D0.3 的交付物已经验收；未通过时不进入本增量。

## 实施步骤

1. 为 12 个任务建立评测 runner、评分规则、失败分类和人工复核记录。
2. 完成威胁模型、风险分级、审批矩阵、秘密处理规则与高风险动作禁用清单。
3. 初始化 monorepo、lint、类型检查、单元/契约测试、ADR 模板和文档目录。
4. 实现 fake executor，使完整 UI 流程可以无真实副作用地运行和回放。
5. 定义 Token、成本、延迟、人工分钟、打断次数与失败类型的采集字段。
6. 把评测、schema 校验、迁移检查和危险动作拦截接入 CI，作为合并门槛。

## 数据与接口契约

| 检查点 | 必须满足 |
| --- | --- |
| 任务卡投影 | 界面只消费稳定的 TaskCard projection，不读取数据库字段或内部任务对象。 |
| 事件事实源 | 状态变化必须进入 append-only Event Log；同一事件流可以重建页面。 |
| 未知状态 | 未识别的状态只能进入“需要处理”，不能默认显示为完成或成功。 |
| 契约测试 | mock server 与前端契约测试随 schema 一起提交，CI 拦截回归。 |

## 交付物

- 12 任务评测 runner
- 威胁模型与审批矩阵
- Monorepo/CI/测试基线
- fake executor 演示记录

## 验证清单

- [ ] 评测可在本地重复运行；高风险动作必须有审批路径；CI 能阻止 schema 和契约回归；fake executor 能驱动完整 UI；没有真实外部副作用。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 原型状态无法映射 | 页面显示“需要处理”，并记录未识别的 projection 字段和任务 ID。 | 补齐状态映射、更新契约测试，再重新演示原路径。 |
| 真实任务无法验收 | 任务保留在候选池，标注原因，不进入开发承诺。 | 补清输入、产物或验收方式，或换一个真实任务。 |
| 基线不可比较 | 该任务不进入评测集，避免用失真的数据证明价值。 | 重新记录人工分钟、成功率、Token 与失败类型。 |

## 本增量不包含

- 不先做完整内核再补界面。
- 不用文档完成度替代可点击原型与可重复评测。
- 不接入真实高风险外部副作用。
