## 这一步要交付什么

核心实体、状态迁移、UI 投影、事件接口和契约测试共同组成一份可实施的协议。

Stage 0 的产出是产品真相与实现契约。没有真实任务、可点击原型和可重复评测，后续开发会把假设当成事实。

## 开始前

- 一个空仓库、可记录的真实工作样本，以及一位愿意持续反馈的首位用户。
- 允许观察全人工流程与直接使用 Codex 的基线，不要求系统已经存在。
- 本阶段不接入真实发送、支付、删除或系统设置修改。
- D0.2 的交付物已经验收；未通过时不进入本增量。

## 四个实施工作包

> 每个工作包都要产生可运行的代码、可复现的验证或明确的界面结果；只写接口或只做页面都不算完成。

### 01 · 领域实体与不变量

定义 Source、Event、Thread、Intent、Task、Ticket、Mandate、Policy、Assignment、Run、Executor、Approval、Artifact、Receipt、Budget 的字段、关系和不可破坏条件。例如同一 Ticket 最多一个有效 Assignment，Artifact 内容寻址，Receipt 必须绑定幂等键。

### 02 · 事件、状态机与投影

把创建、排队、执行、审批、失败、恢复和完成写成显式事件；任务卡、收件箱、产物和成本都由投影生成。未知事件或未知状态只能进入“需要处理”，不能推断为成功。

### 03 · 持久执行接口

固定 Event Log、outbox、lease、fencing token、schema migration 和 SSE 的边界。规定先落盘再执行、外部副作用先写 intent、重试复用幂等键，以及崩溃后如何安全重投。

### 04 · Mock server 与契约测试

mock server 只消费同一事件流来驱动原型；为主路径、审批拒绝、未知状态、重复事件和恢复编写契约测试。schema 使用版本号，旧事件重放不能产生外部副作用。

## 工程落点

### 主要目录与模块

- `packages/core/src/schema` — 领域实体、状态机与失败分类
- `packages/eventlog` — Event Log、投影与 migration
- `packages/evals` — 任务集、runner、评分与人工复核
- `apps/web` — 今日、需要你、产物、设置与任务详情原型
- `fixtures/tasks` — 真实任务样本与失败样本
- `docs/adr` — Build vs Integrate、事件模型与前端投影决策

### 关键接口

| 接口 | 必须保持的契约 |
| --- | --- |
| `Event` | id、type、schemaVersion、occurredAt、actor、subject、causationId、correlationId、payload；只追加，不能覆盖历史。 |
| `TaskCardProjection` | taskId、title、state、primaryAction、reason、lastEventAt、artifacts、budget；页面不读取数据库字段。 |
| `ExecutorEvent` | 标准化事件、产物引用、structResult、validation、failureClass、recoverable；执行器不直接写主库。 |
| `Approval` | effectPreview、scope、expiresAt、decision、idempotencyKey；审批绑定真实动作和参数。 |

## 验收演练

1. 从干净的数据目录启动 hearthd，打开 [D0.3 页面](/delivery/stage-0/d0-3)，确认当前页面没有依赖浏览器缓存或手工种子数据。
2. 按顺序完成四个工作包：领域实体与不变量、事件、状态机与投影、持久执行接口、Mock server 与契约测试。每完成一个工作包，保存对应测试输出、截图或产物版本。
3. 复现失败案例“原型状态无法映射”。页面必须显示“页面显示“需要处理”，并记录未识别的 projection 字段和任务 ID。”，然后按“补齐状态映射、更新契约测试，再重新演示原路径。”恢复；不得出现重复副作用或未登记状态。
4. 重启服务并重新打开任务，确认运行状态、审批、产物和恢复入口都来自持久投影，而不是只存在于当前页面。
5. 运行上方的共享验证命令并导出证据。完成门槛是：前端不依赖内部数据库字段；核心状态迁移有唯一解释；schema 可版本化；事件流能重建投影；未知状态安全显示为“需要处理”。

## 交付物

- 领域实体与状态机图
- TaskCard/Approval/Artifact 契约
- mock server 与契约测试
- schema 版本与迁移说明

## 完成判定

- [ ] 前端不依赖内部数据库字段；核心状态迁移有唯一解释；schema 可版本化；事件流能重建投影；未知状态安全显示为“需要处理”。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 原型状态无法映射 | 页面显示“需要处理”，并记录未识别的 projection 字段和任务 ID。 | 补齐状态映射、更新契约测试，再重新演示原路径。 |
| 真实任务无法验收 | 任务保留在候选池，标注原因，不进入开发承诺。 | 补清输入、产物或验收方式，或换一个真实任务。 |
| 基线不可比较 | 该任务不进入评测集，避免用失真的数据证明价值。 | 重新记录人工分钟、成功率、Token 与失败类型。 |

## 本增量不包含

- 不先做完整内核再补界面。
- 不用文档完成度替代可点击原型与可重复评测。
- 不接入真实高风险外部副作用。
