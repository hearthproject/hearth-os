# 1.1 明确首个场景与真实任务

## 目标

确定 Hearth 首先为谁解决什么问题，并把这个问题变成一组可以验收的真实任务。阶段结束时，团队应当能说清楚首个用户、首个任务族、明确不做什么，以及什么结果算完成。

## 怎么做

1. 找到一位愿意提供真实任务和反馈的首位用户，记录他每天重复做、最希望交给系统的工作。
2. 收集 20–30 个真实任务，从中选出 10–12 个输入、产物和验收方式都清楚的任务。
3. 只选一个高频、外部风险低、结果容易检查的任务族作为首个范围。
4. 写出一句话定位和“暂不做什么”清单，避免第一阶段被新想法带偏。
5. 记录这些任务现在怎么做、花多少时间、哪里容易出错，作为后续对比。
6. 确定 MVP 的验收方式：至少 8 个真实任务通过验收，失败任务能说明原因并恢复。
