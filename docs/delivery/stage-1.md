# Stage 1 · 持久内核与 MVP

<p class="lead">从原型走到每天可用的本地产品。顺序固定：真实短闭环 → 第一个 Codex 切片 → MVP 收口 → 副作用安全 → 第二任务族 → 恢复与发布。</p>

## 前置条件

- Stage 0 的 12 个任务、原型、协议、评测与安全基线可用。
- 已确定首个任务族；默认是“研究/文档整理”，若首位用户更依赖代码任务，可替换楔子但保留相同纵向结构。
- Web 是正式产品入口，不允许只靠 CLI、日志或脚本演示。

## 开发步骤

1. **交付走路骨架。** 启动 `hearthd`，接入 SQLite WAL、最小 Event Log、Task/Run 状态机、投影、fake executor、Web 任务列表/详情/创建和 SSE。
2. **接入第一个真实 Codex 切片。** 完成 Codex adapter、健康检查、一次性 workspace、Task Pack、结构化输出、Artifact、引用/文件验证、事件投影和 Token/延迟采集。
3. **收口 MVP-1。** 打通创建、查看、取消、重试、审批演练、产物取回、失败恢复和预算异常停止，形成真实窄任务闭环。
4. **补齐副作用安全骨架。** 实现 Effect Preview、Mandate、Approval、outbox、幂等键、Receipt、撤销/补偿演练和单写者 lease。
5. **加入第二任务族并加固内核。** 用第二个任务族验证路由、失败分类、预算、并发、重复投递、崩溃恢复和投影一致性。
6. **完成 Stage 1 发布。** 跑 10 个真实任务，对比全人工与直接 Codex，修复高频失败，补齐安装、备份、升级、导出、安全与评测报告。

## MVP 的位置

MVP-1 是 Stage 1 的早期出口，对应 D1.3，不是 Stage 6 的产物。它可以暂时不包含邮件、日历、GUI、主动性和多设备，但必须包含真实执行、持久状态、Web 任务卡、产物、审批演练和失败恢复。

## 退出验收

- [ ] MVP 能在浏览器中每天使用一个窄任务族。
- [ ] 服务崩溃、刷新或重启后，任务可恢复或明确转人工。
- [ ] 重复投递和重试不会产生重复外部副作用。
- [ ] 任务卡显示状态、产物、成本和下一步；失败原因用户可理解。
- [ ] 至少 10 个真实任务通过人工验收，Token 与人工分钟有基线。
- [ ] 权限边界、秘密保护、kill switch、备份和数据导出可用。

## 本模块不做

- 不做邮件、日历、桌面 GUI、主动循环或多设备。
- 不先扩展执行器数量而牺牲恢复、审批和界面完整性。
- 不用演示脚本替代真实 Codex 执行与验证。
