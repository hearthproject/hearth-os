# 第一阶段 · 最小完整 MVP

## 目标

第一阶段交付一个可以在真实浏览器里每天使用的最小完整产品。它只服务一个窄任务族，但必须走完“创建任务—执行—审批—查看产物—失败恢复”的完整路径。这个阶段不追求覆盖所有工作，只追求让第一条真实链路可靠可用。

本阶段分为四个小阶段：

| 小阶段 | 目标 |
|---|---|
| [1.1 明确首个场景与真实任务](/delivery/stage-1/1-1) | 确定首个用户、任务族、非目标和验收任务。 |
| [1.2 做出完整体验原型](/delivery/stage-1/1-2) | 用可点击原型走通任务、审批、产物和恢复。 |
| [1.3 打通最小任务闭环](/delivery/stage-1/1-3) | 让任务能真实执行、审批、产出结果并在失败后恢复。 |
| [1.4 用真实任务验收 MVP](/delivery/stage-1/1-4) | 让首位用户不依赖开发者也能独立使用。 |

## 怎么做

1. 先选定首个用户和首个任务族，并用真实任务确定验收标准。
2. 用可点击原型把完整路径和所有关键状态走一遍。
3. 打通真实任务闭环，包括执行、审批、产物和失败恢复。
4. 让首位用户连续使用一周，用真实任务验收 MVP。
