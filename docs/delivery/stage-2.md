# 第二阶段 · 日常内容工作

当前实现、已验证范围和明确留空项见[阶段二至六交付状态](/delivery/status)。

## 当前状态

- **已实现代码闭环：** 本地文件、知识库和公开网页来源，TXT、Markdown、CSV、JSON、HTML、PDF、DOCX、XLSX 提取，以及“草稿 → 审批 → 本地发件箱写入 → 回执”。
- **仍未完成：** 邮件和日历账户接入、真实发送或外部系统写入，以及 10–15 个真实日常任务验收。逐项证据见[阶段二至六交付状态](/delivery/status)。

## 目标

第二阶段把 Hearth 从第一阶段的首批跨行业任务扩展到大多数日常内容工作：读取邮件、日历、文件和知识库，处理文档、表格和网页资料，起草内容，并在审批后发送或写入。顺序必须是先只读、再起草、最后才执行外部写入。

本阶段分为四个小阶段：

| 小阶段 | 目标 |
|---|---|
| [2.1 接入只读信息源](/delivery/stage-2/2-1) | 让用户看到系统读取了什么，以及来源是否可靠。 |
| [2.2 处理文档、表格与网页资料](/delivery/stage-2/2-2) | 产出有来源、能核对、可继续使用的资料结果。 |
| [2.3 起草、审批与外部写入](/delivery/stage-2/2-3) | 先草稿、再审批、最后只执行一次外部写入。 |
| [2.4 验收日常内容工作](/delivery/stage-2/2-4) | 用真实日常任务证明更少时间、更高准确和可恢复。 |

## 怎么做

1. 先接入只读信息来源，让用户看到系统读到了什么。
2. 再加入文档、表格和网页资料的处理与引用。
3. 然后打通起草、审批和测试账户下的发送或写入。
4. 最后用真实日常任务验收时间节省、结果准确和失败恢复。
