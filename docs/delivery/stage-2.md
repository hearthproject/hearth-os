# Stage 2 · Personal Operator

<p class="lead">从“能完成文件任务”扩展到“能承担大多数日常内容工作”。顺序必须先只读、再确定性处理、再网页、最后测试账户下的真实写入，避免一开始就把高风险账户交给模型。</p>

## 前置条件

- Stage 1 的持久任务、审批、幂等、回执和恢复已经稳定。
- 已选定首批连接器与文档/数据任务，并准备测试账户。
- 所有外部来源都进入统一 Source 模型，保留权限、来源和审计信息。

## 开发步骤

1. **连接只读来源。** 先接邮件、日历、文件和知识库的只读同步，建立来源视图、去重、增量和权限校验。
2. **加入 Document/Data Executor。** 支持文档转换、表格处理、结构化提取、引用定位和可验证产物。
3. **加入 Browser Executor。** 先做公开网页研究、引用和页面 diff；隔离登录态，处理不可信页面和提示词注入。
4. **打通测试账户副作用。** 用测试账户完成“读—理解—起草—审批—发送/写入—回执”闭环，验证幂等、失败对账和撤销。
5. **编译上下文与预算。** 引入 Context Compiler、Token Governor v1 和 Memory v0；记录召回来源、Token 消耗和人工分钟。
6. **完成 Stage 2 发布。** 用代表性日常任务评估成功率、人工分钟、跨账户隔离、失败恢复和用户信任。

## 增量拆分

| 增量 | 用户可见结果 | 完成证据 |
|---|---|---|
| [D2.1](/delivery/stage-2/d2-1) 只读连接器与来源视图 | 用户能看到邮件、日历、文件和知识库来源 | 同步、去重、增量、权限与来源审计 |
| [D2.2](/delivery/stage-2/d2-2) Document/Data Executor | 文档与表格可转换、提取并验证 | 产物、引用、结构和失败样本 |
| [D2.3](/delivery/stage-2/d2-3) Browser Executor 与网页研究 | 网页研究有来源、引用和页面变化证据 | 隔离登录态、网页 diff、注入防护 |
| [D2.4](/delivery/stage-2/d2-4) 草稿、审批与测试账户副作用 | 用户能审批发送/写入并查看回执 | 测试账户闭环、幂等、对账、撤销 |
| [D2.5](/delivery/stage-2/d2-5) Context Compiler 与 Memory v0 | 任务使用更少上下文且能解释召回 | Token 基线、召回来源、预算与降级 |
| [D2.6](/delivery/stage-2/d2-6) Stage 2 发布 | 日常内容任务的人工分钟显著下降 | 真实任务评估、跨账户隔离、安全报告 |

## 退出验收

- [ ] 邮件“读—理解—起草—审批—发送—回执”闭环可用。
- [ ] 日历冲突检查与待审批写入可用。
- [ ] 文档转换、数据提取和网页研究结果可验证，来源可追溯。
- [ ] 常见任务的人工分钟显著下降，Token 有基线。
- [ ] 没有跨账户、跨项目数据串扰；失败时能恢复或明确转人工。

## 本模块不做

- 不直接接管无隔离的真实主账户。
- 不为了连接器数量牺牲权限、幂等和回执。
- 不让不可信网页内容直接改变系统权限或审批策略。
