## 这一增量解决什么

一个低打扰、可通过手机处理关键动作的主动个人 Agent。

Stage 4 的价值不是后台运行，而是在正确的时间以可接受的打扰做正确的事。主动性必须建立在既有恢复与审批之上。

## 开始前

- Stage 1–3 的恢复、审批、验证、接管和撤销已经稳定。
- 已明确允许触发主动任务的来源、时间窗口、预算和静默时段。
- 手机只作为查看、审批、接管和发起入口，不成为默认执行权威。
- D4.4 的交付物已经验收；未通过时不进入本增量。

## 实施步骤

1. 跑代表性 Trigger 场景和真实主动任务试跑。
2. 评估通知疲劳、审批安全、跨设备审计和预算控制。
3. 补齐隐私说明、紧急停止文档和主动模式已知限制。
4. 验证手机审批与接管在真实网络波动下仍然安全。
5. 完成 Stage 4 安全与评测报告，记录主动价值与打断成本。
6. 确认主动模式可暂停、回退，且没有后台预算透支或失控循环。

## 数据与接口契约

| 检查点 | 必须满足 |
| --- | --- |
| 触发幂等 | 同一来源事件经过去重与窗口聚合，不能生成重复主动任务。 |
| 审批安全 | 手机审批绑定参数、nonce、设备与过期时间；重新认证后才能确认。 |
| 通知隐私 | 推送只包含脱敏摘要，不泄露正文、附件、凭据或完整任务上下文。 |
| 注意力预算 | 用户可设定安静时段、打断上限和主动级别；预算耗尽立即停止。 |
| 可撤销性 | 任何主动模式、设备和通知权限都能暂停、降级或撤销，并留下审计。 |

## 交付物

- 代表性 Trigger 报告
- 主动任务价值/打断评估
- 隐私与紧急停止文档
- Stage 4 发布审计

## 验证清单

- [ ] Stage 4 退出条件全部满足；手机审批与接管稳定；主动模式可暂停和回退；无后台预算透支或失控循环。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 重复触发导致通知轰炸 | 聚合为一个候选卡并标注重复来源。 | 提高去重窗口、暂停触发或降低主动级别。 |
| 手机审批被重放 | 审批拒绝并显示设备/时间不匹配。 | 要求重新认证并重新生成审批请求。 |
| 后台预算耗尽 | 主动任务停在预算边界，显示已停止原因。 | 等待用户提高预算或手动继续，不自动透支。 |

## 本增量不包含

- 不在没有恢复、审批和验证的前提下开放主动循环。
- 不为了活跃度制造任务或通知。
- 不把手机变成长期持有主凭据的执行设备。
