## 这一步要交付什么

用户可以在手机上看到今日任务、需要你、产物，完成审批、接管、发起任务和接收高信号通知。

Stage 4 的价值不是后台运行，而是在正确的时间以可接受的打扰做正确的事。主动性必须建立在既有恢复与审批之上。

## 开始前

- Stage 1–3 的恢复、审批、验证、接管和撤销已经稳定。
- 已明确允许触发主动任务的来源、时间窗口、预算和静默时段。
- 手机只作为查看、审批、接管和发起入口，不成为默认执行权威。
- D4.1 的交付物已经验收；未通过时不进入本增量。

## 四个实施工作包

> 每个工作包都要产生可运行的代码、可复现的验证或明确的界面结果；只写接口或只做页面都不算完成。

### 01 · PWA 壳与离线只读缓存

移动端提供任务列表、详情、审批、接管和产物预览，离线时只允许读取最近缓存并明确标记数据时间。离线状态禁止确认外部副作用、修改预算或解除审批；恢复网络后从服务端重新校验权限和参数，不能直接补发离线动作。

### 02 · 移动审批与接管

审批页展示真实参数、影响和来源，使用短期会话或生物识别保护高价值动作。接管界面适配触屏和单手操作，明确暂停自动输入；手机不持有长期主凭据，撤销设备后立即退出所有敏感页面。

### 03 · 脱敏推送与深链

推送只包含任务类型、是否需要用户和最小上下文，不发送正文、收件人或秘密。深链打开后仍需重新鉴权并从服务端取真实状态；通知权限可分级关闭，过期或被撤销的审批不能通过旧推送重放。

### 04 · 移动可访问性与验收

检查 390px 宽度、键盘可达、屏幕阅读器标签、对比度、触控目标和横竖屏布局。关键路径在主设备、手机和断网恢复下都能完成或安全拒绝；验收必须证明手机上不能越权审批、离线不能产生副作用、旧深链不能重放。

## 工程落点

### 主要目录与模块

- `apps/hearthd/triggers` — Trigger 适配器、去重键、候选生成与降级
- `packages/control` — 自主级别、候选策略、风险门槛与 kill switch
- `packages/attention` — 注意力预算、静默时段、通知聚合与价值评分
- `apps/pwa` — 移动任务卡、审批、接管、离线只读与推送入口
- `packages/devices/pairing` — 公钥配对、短期会话与远程撤销
- `packages/relay` — 端到端加密推送、最小元数据与重放防护
- `apps/web` — 为什么现在、主动收件箱、强度设置与中断历史

### 关键接口

| 接口 | 必须保持的契约 |
| --- | --- |
| `TriggerEvent` | triggerId、source、dedupeKey、observedAt、payloadRef、scope、sensitivity；重复事件不能生成重复任务。 |
| `ProactiveCandidate` | candidateId、whyNow、proposedAction、autonomyLevel、risk、budget、expiresAt；候选不是授权。 |
| `AttentionBudget` | window、maxInterruptions、quietHours、valueThreshold、spent；预算耗尽必须停止主动打扰。 |
| `MobileApproval` | approvalId、nonce、parameterHash、expiresAt、deviceId、signature；离线状态不得确认外部副作用。 |

### 共享验证命令

```bash
pnpm test:triggers：重复事件、乱序、失效来源和预算耗尽
pnpm test:attention：静默时段、聚合、疲劳阈值和 kill switch
pnpm test:pwa：离线、断网、生物识别、重放和远程撤销
pnpm eval:proactive：主动与手动对照的成功率、打断和满意度
```

## 验收演练

1. 从干净的数据目录启动 hearthd，打开 [D4.2 页面](/delivery/stage-4/d4-2)，确认当前页面没有依赖浏览器缓存或手工种子数据。
2. 按顺序完成四个工作包：PWA 壳与离线只读缓存、移动审批与接管、脱敏推送与深链、移动可访问性与验收。每完成一个工作包，保存对应测试输出、截图或产物版本。
3. 复现失败案例“重复触发导致通知轰炸”。页面必须显示“聚合为一个候选卡并标注重复来源。”，然后按“提高去重窗口、暂停触发或降低主动级别。”恢复；不得出现重复副作用或未登记状态。
4. 重启服务并重新打开任务，确认运行状态、审批、产物和恢复入口都来自持久投影，而不是只存在于当前页面。
5. 运行上方的共享验证命令并导出证据。完成门槛是：关键动作在手机可完成；不持有长期主凭据；离线不产生外部副作用；审批需要重新认证；推送不泄露敏感正文。

## 完成判定

- [ ] 关键动作在手机可完成；不持有长期主凭据；离线不产生外部副作用；审批需要重新认证；推送不泄露敏感正文。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 重复触发导致通知轰炸 | 聚合为一个候选卡并标注重复来源。 | 提高去重窗口、暂停触发或降低主动级别。 |
| 手机审批被重放 | 审批拒绝并显示设备/时间不匹配。 | 要求重新认证并重新生成审批请求。 |
| 后台预算耗尽 | 主动任务停在预算边界，显示已停止原因。 | 等待用户提高预算或手动继续，不自动透支。 |

## 本增量不包含

- 不在没有恢复、审批和验证的前提下开放主动循环。
- 不为了活跃度制造任务或通知。
- 不把手机变成长期持有主凭据的执行设备。
