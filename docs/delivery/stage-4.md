# 第四阶段 · 主动服务与手机入口

当前实现、已验证范围和明确留空项见[阶段二至六交付状态](/delivery/status)。

## 当前状态

- **已实现代码闭环：** 六类触发条件、带来源与风险说明的主动建议、主动收件箱（接受、忽略、稍后提醒、转任务）、注意力预算、安静时段和暂停入口；Web 端提供可安装 PWA 壳、离线应用壳和移动底部导航。
- **仍未完成：** iOS/Android 真机安装验收、手机配对、系统推送、远程审批与接管，以及 5–10 个真实主动任务的打扰验收。逐项证据见[阶段二至六交付状态](/delivery/status)。

## 目标

第四阶段让 Hearth 在有限授权内主动工作，并把手机变成查看、审批和接管入口。重点不是“自动运行”，而是在正确的时间做正确的事，并且不制造打扰。

本阶段分为四个小阶段：

| 小阶段 | 目标 |
|---|---|
| [4.1 设置触发条件与主动建议](/delivery/stage-4/4-1) | 发现值得处理的事，并解释为什么现在重要。 |
| [4.2 建立主动收件箱](/delivery/stage-4/4-2) | 把建议集中到一个容易判断和处理的地方。 |
| [4.3 手机查看、审批与接管](/delivery/stage-4/4-3) | 手机只保留关键动作和短期权限，丢失后可立即撤销。 |
| [4.4 控制打扰与验收主动服务](/delivery/stage-4/4-4) | 主动模式要安静、有用、可控，并且可以随时关掉。 |

## 怎么做

1. 先建立触发条件和主动建议，不直接自动执行。
2. 再把建议集中到主动收件箱，让用户决定接受、忽略或转成任务。
3. 然后交付手机入口，支持查看、审批和接管。
4. 最后用注意力预算和真实任务验收，确保主动模式安静、可控、可撤销。
