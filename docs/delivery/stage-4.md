# Stage 4 · 主动个人 Agent

<p class="lead">让 Hearth 在有限授权内主动工作，同时保持低打扰。难点不是“能否自动运行”，而是能否在正确的时候、用正确的打扰程度做正确的事。</p>

## 前置条件

- Stage 1–3 的恢复、审批、验证、接管和撤销已经稳定。
- 用户已建立明确的注意力预算、静默时段和高风险动作边界。
- 主动模式默认可控、可暂停、可降级，并且有对照评估。

## 开发步骤

1. **接入 Trigger。** 从邮件、日历、文件和任务依赖产生事件，完成去重、冷却、优先级和“为什么现在”解释。
2. **建立主动收件箱。** 输出主动候选、建议动作、预算、影响和是否打扰；支持接受、忽略、暂停和转为普通任务。
3. **交付手机 PWA。** 支持查看今日、需要你、产物，完成审批、接管、发起任务和高信号通知。
4. **完成安全配对与撤销。** 使用短期二维码配对、公钥、nonce、参数绑定、过期时间、安全隧道或推送中继；手机丢失可立即撤销。
5. **实施注意力预算。** 控制打断次数、静默时段、聚合通知、后台预算和失控循环；先 shadow/对照运行。
6. **完成 Stage 4 发布。** 评估主动任务成功率、每任务打断次数、用户满意度、预算透支和安全回归。

## 增量拆分

每个增量现在按四层阅读：结果与门槛 → 四个实施工作包 → 工程落点与接口 → 验收演练。工作包可以拆给不同开发者并行，但必须按依赖顺序合并；只完成一个包不等于完成增量。

| 增量 | 用户可见结果 | 完成证据 |
|---|---|---|
| [D4.1](/delivery/stage-4/d4-1) Trigger 与主动收件箱 | Hearth 能解释“现在可以做什么” | 事件去重、候选生成、A1/A2 边界、暂停与忽略 |
| [D4.2](/delivery/stage-4/d4-2) 手机 PWA | 手机可查看、审批、接管、发起任务 | 响应式 PWA、关键动作、离线只读、推送脱敏 |
| [D4.3](/delivery/stage-4/d4-3) 安全配对、推送与设备撤销 | 手机配对简单，丢失后可立即撤销 | 公钥配对、nonce、过期、撤销、审计 |
| [D4.4](/delivery/stage-4/d4-4) 注意力预算与主动试跑 | 主动模式安静有用，不制造通知疲劳 | 打断指标、静默时段、shadow、kill switch |
| [D4.5](/delivery/stage-4/d4-5) Stage 4 发布 | 主动任务真实有用，关键动作手机可达 | 用户满意度、成功率、预算与安全评估 |

## 退出验收

- [ ] 主动任务真实有用，不制造通知疲劳。
- [ ] 每任务平均打断次数 ≤ 1。
- [ ] 高风险动作仍需审批，手机审批不可重放。
- [ ] 丢失设备可撤销，撤销后无法继续审批或接管。
- [ ] 用户能随时暂停、撤销和降级主动模式；无后台无限循环或预算透支。

## 本模块不做

- 不在没有预算、静默和撤销机制时开放主动循环。
- 不让手机持有长期主凭据。
- 不用推送正文泄露敏感信息。
