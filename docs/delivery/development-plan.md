# 从 0 到 100 开发计划

<p class="lead">产品路线图回答“做到哪里算完成”，开发计划回答“下一步具体做什么”。这里不是一条按周排期的甘特图，而是 7 个可独立验收的工程模块。</p>

## 本篇怎么读

- 计划单位是纵向增量 `D0.1 … D6.6`，不是周、月或固定迭代长度。
- 严格按依赖顺序推进；任何增量都不能只交付后端、日志或接口。
- 每个增量都必须让用户在浏览器中完成一件具体的事。
- 阶段验收不通过时，停留在当前 Stage 修补，不用“后面再补”换取推进。

## 先看总纲

[分阶段产品路线图](/delivery/roadmap)是范围和顺序的总纲：它定义 Stage 0–6 的目标、范围、退出条件和明确推迟项。开发计划把同一套阶段展开为工程步骤；两者冲突时，以产品路线图的阶段门槛为准。

## 七个开发模块

<DocCardGrid :items="modules" :columns="2" />

进入任一模块后，按同样的顺序阅读：

1. **前置条件**：确认依赖已经满足，不把未稳定的能力带入下一阶段。
2. **开发步骤**：按编号施工，每一步都说明要做什么、产出什么。
3. **增量拆分**：确认每个增量对应的用户可见结果和完成证据。
4. **退出验收**：全部通过才进入下一模块；不通过就留在当前模块修补。

## 计划边界

- **起点：** 有产品定义、首位用户和空仓库，但没有可运行系统。
- **终点：** 通过全部阶段出口，能在真实个人环境中长期使用、迁移、恢复和撤销的 Personal Agent OS。
- **单位：** 纵向增量，例如 D0.1、D1.1、D2.3；不是周、月或固定迭代长度。
- **顺序：** 严格按依赖推进；可以暂停、试用和回退，但不能用跳过恢复、界面或验证来换取速度。

## 六条执行规则

1. **纵向切片优先。** 每个增量都必须同时有用户结果、界面、持久状态、真实实现、验证和恢复。
2. **前端同步生长。** Stage 0 有可点击原型；Stage 1 的第一个可运行骨架就有真实 Web 任务卡；之后每个增量都要投影到界面。
3. **先窄后宽。** 先让一个任务族真正可依赖，再增加第二个任务族；先在一个连接器上证明权限、幂等和回执，再扩展渠道。
4. **持久性先于自主性。** 任务不能丢、副作用不能重复、失败必须可见；在这些完成前，不增加主动循环和高风险无人值守。
5. **安全先于真实副作用。** 发送、写入、分享、删除和桌面操作，必须先经过 Effect Preview、Mandate、Approval、幂等键和 Receipt 演练。
6. **评估先于扩展。** 新增执行器、连接器、模型、技能或自动化范围前，必须有代表性任务、基线、失败样本和回滚路径。

## MVP 的位置

MVP-1 位于 Stage 1 的早期出口，对应 D1.3，不是 Stage 6 的产物。它是一个真实可用的本地个人任务工作台，默认以“研究/文档整理”为第一个任务楔子；如果首位用户最高频的是代码任务，可以替换楔子，但纵向结构不变。

| 维度 | MVP 门槛 |
|---|---|
| 入口 | 本地 Web 可创建任务、选择工作区、引用文件或路径 |
| 任务 | 一个窄任务族的完整闭环：目标、范围、预算、状态和验收 |
| 执行 | Codex 在隔离工作区执行，返回结构化结果和产物 |
| 状态 | 排队、执行、审批、需要信息、完成、失败和可恢复状态真实持久化 |
| 界面 | 今日/任务卡、详情、审批、产物、失败与恢复，不要求 CLI 知识 |
| 证据 | 产物可预览/下载，带来源、哈希和验证结果 |
| 副作用 | 至少一种外部动作有预览、审批、幂等与练习回执 |
| 恢复 | 刷新或重启后任务不消失，能继续、取消、重试或转人工 |
| 成本 | 记录 Token、模型、执行器、延迟和人工分钟 |

## 每个增量的交付模板

| 项目 | 必须回答 |
|---|---|
| 用户可见结果 | 用户在浏览器里能多做哪一件具体的事？ |
| 主要工作 | 哪些后端、前端、协议、执行器和测试工作需要完成？ |
| 完成门槛 | 用什么可重复的证据证明它真的完成？ |
| 失败与恢复 | 失败时用户看到什么，如何取消、重试、接管或撤销？ |
| 成本与副作用 | Token、人工分钟、外部动作和回执是什么？ |
| 回归检查 | 上一个增量、上一阶段和关键安全边界是否仍然成立？ |

## 贯穿全部增量的五条工作线

| 工作线 | 每个增量必须更新 |
|---|---|
| 产品与界面 | 用户故事、状态、主动作、空状态、失败态、恢复入口、桌面/手机布局 |
| 协议与投影 | Event、schema、API、Task Pack、Result、投影字段、migration 和契约测试 |
| 评测与安全 | 代表性任务、成功/失败样本、权限检查、故障注入、安全回归和人工验收 |
| 可观测与成本 | trace、执行器/模型、Token、延迟、人工分钟、打断次数、失败分类 |
| 文档与迁移 | README、ADR、用户说明、安全、备份/升级、已知限制和数据导出 |

| 节点 | 对应模块 | 可演示的产品状态 |
|---|---|---|
| 原型 | S0 | 可点击的完整任务流程，不产生真实副作用 |
| 走路骨架 | S1 · D1.1 | Web + 持久任务 + fake executor |
| MVP-1 | S1 · D1.3 | 一个窄任务族的真实端到端产品 |
| Stage 1 完成 | S1 | 可恢复内核、两任务族、副作用安全骨架 |
| Personal Operator | S2 | 邮件/日历/文档/网页/数据日常任务 |
| Computer Operator | S3 | GUI 观察、接管、低/高风险桌面动作 |
| 主动个人 Agent | S4 | 主动循环、手机 PWA、注意力预算 |
| 记忆与进化 | S5 | 可纠正记忆、可回滚技能 |
| Personal Agent OS | S6 | 多设备、迁移、长期运行与完整审计 |

## 范围裁剪顺序

资源不足时先裁剪范围，不裁剪地基：减少连接器和渠道 → 减少主动性 → 减少原生形态 → 减少高级记忆 → 减少多设备 → 减少远程 Sandbox → 暂停技能晋升。

**永远不能裁掉：** Web 界面和任务卡、Event Log 和持久状态、审批/幂等/outbox/Receipt、验证器和失败样本、权限与秘密保护、导出/备份/撤销、用户可见的失败原因和下一步。

## 完成定义

“100%”不是所有软件和场景零人工，而是全部阶段出口同时成立：任务覆盖可验证；桌面与手机都能查看、发起、审批、接管和取回产物；崩溃与设备切换不丢任务；高风险动作可审批、可撤销；记忆可解释、可纠正、可遗忘；技能可评估、可回滚；系统可安装、可迁移、可长期运行。

## 阶段推进检查表

- [ ] 当前阶段退出条件都有证据，而不是口头宣布。
- [ ] 最后一个增量仍能在浏览器中完整演示。
- [ ] 从空数据库安装、启动、创建任务和恢复的路径可用。
- [ ] 没有未解决的高风险安全、重复副作用或秘密泄露问题。
- [ ] 新增能力都有失败态、恢复入口和用户可见说明。
- [ ] 评测集、真实任务结果、Token/人工分钟和失败分类已更新。
- [ ] 数据导出、备份、回滚和已知限制已更新。
- [ ] 下一阶段不依赖隐藏的人工操作或只在开发机可用的配置。
