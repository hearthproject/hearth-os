## 这一步要交付什么

一个候选技能可以经过评估、Canary 和小范围真实使用后晋升；出现问题时能回滚，并说明回滚原因。

Stage 5 先让记忆可纠正、可遗忘，再让技能可评估、可回滚；任何不能解释来源和权限的变化都不能进入生产。

## 开始前

- Stage 1–4 的任务、审批、验证、主动性和跨设备入口已经稳定。
- 已确定允许记忆的事实、偏好、经验和敏感信息边界。
- 每次技能变化都必须有对照评估、版本、权限交集和回滚路径。
- D5.3 的交付物已经验收；未通过时不进入本增量。

## 四个实施工作包

> 每个工作包都要产生可运行的代码、可复现的验证或明确的界面结果；只写接口或只做页面都不算完成。

### 01 · 晋升状态机与权限交集

实现 Draft → Evaluated → Shadow → Canary → Promoted → Rolled back 状态机，每次迁移需要可复查证据。有效权限等于父任务、用户 Mandate、技能声明和环境策略的交集；任何一项缩小都会立即生效，自进化不能成为提权路径。

### 02 · 版本、签名与运行时选择

技能版本不可变并签名，运行时按任务、能力和评估结果选择，不默认使用最新候选。回滚只切换指针并保留事件，旧版本仍可验证；签名无效、评估过期或 manifest 变化时拒绝加载。

### 03 · 技能界面与用户解释

技能页展示当前版本、候选差异、所需权限、评估集、Shadow/Canary 结果、晋升原因和回滚入口。用户能理解“为什么采用新方法”以及它多做了什么；没有评估证据或权限说明的候选不能展示为可晋升。

### 04 · 完整晋升、回滚与 Stage 5 发布

至少完成一个真实技能的晋升案例，经过 Shadow 和小范围 Canary 后提升，再主动演练回滚并记录影响范围。安全报告证明无权限扩大、无真实副作用泄漏、无评估污染；Stage 5 退出条件不全时不得进入多设备阶段。

## 工程落点

### 主要目录与模块

- `packages/memory/core` — 五类记忆模型、写入、检索与冲突
- `packages/memory/provenance` — 来源、置信度、敏感度、时效与召回解释
- `packages/memory/forget` — 索引、缓存、设备传播与遗忘审计
- `packages/memory/browser` — 记忆浏览、纠正、删除与导出页面
- `packages/evolution/trajectory` — 轨迹采集、重放、脱敏与样本分层
- `packages/evolution/skills` — manifest、权限、版本、签名与运行时选择
- `packages/evolution/evaluation` — 评估集、baseline、Shadow、Canary 与回滚

### 关键接口

| 接口 | 必须保持的契约 |
| --- | --- |
| `MemoryRecord` | memoryId、kind、value、provenance、confidence、sensitivity、observedAt、updatedAt、expiresAt；冲突不得静默覆盖。 |
| `ForgetRequest` | targetIds、scope、reason、requestedAt、propagationState、auditId；删除必须传播到索引、缓存和设备。 |
| `SkillManifest` | skillId、version、inputs、outputs、requiredCapabilities、evaluationRef、signature、status；权限只能取交集。 |
| `EvolutionDecision` | candidateId、stage、baseline、shadowResult、canaryResult、permissionDelta、rollbackRef；每次晋升可追溯。 |
| `TrajectoryRecord` | taskId、steps、toolCalls、inputsDigest、results、failureClass、consent、redactions；重放不得产生外部副作用。 |

### 共享验证命令

```bash
pnpm test:memory：写入、召回、冲突、纠正、遗忘和跨项目隔离
pnpm test:poison：提示注入、来源伪造、权限提升和记忆污染
pnpm test:evolution：权限交集、Shadow、Canary、晋升和回滚
pnpm eval:skills：候选与 baseline 的同任务对照和污染防护
```

## 验收演练

1. 从干净的数据目录启动 hearthd，打开 [D5.4 页面](/delivery/stage-5/d5-4)，确认当前页面没有依赖浏览器缓存或手工种子数据。
2. 按顺序完成四个工作包：晋升状态机与权限交集、版本、签名与运行时选择、技能界面与用户解释、完整晋升、回滚与 Stage 5 发布。每完成一个工作包，保存对应测试输出、截图或产物版本。
3. 复现失败案例“错误记忆被召回”。页面必须显示“召回卡显示来源与原因，用户可以纠正或删除。”，然后按“更新记忆、重建索引并记录纠正事件。”恢复；不得出现重复副作用或未登记状态。
4. 重启服务并重新打开任务，确认运行状态、审批、产物和恢复入口都来自持久投影，而不是只存在于当前页面。
5. 运行上方的共享验证命令并导出证据。完成门槛是：Stage 5 退出条件全部满足；至少一个技能有对照评估、晋升和回滚记录；无安全回归；用户能理解系统为什么采用新方法。

## 交付物

- 晋升状态机
- 技能 UI 与版本
- 一次完整晋升/回滚
- Stage 5 安全评估

## 完成判定

- [ ] Stage 5 退出条件全部满足；至少一个技能有对照评估、晋升和回滚记录；无安全回归；用户能理解系统为什么采用新方法。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 错误记忆被召回 | 召回卡显示来源与原因，用户可以纠正或删除。 | 更新记忆、重建索引并记录纠正事件。 |
| 遗忘没有传播 | 页面显示“遗忘未完成”并阻止继续依赖。 | 重试索引清理、设备同步和缓存失效，确认后再标记完成。 |
| 候选技能权限扩大 | 评估标记权限越界并直接拒绝晋升。 | 收窄 manifest 权限或重新设计技能，保持权限交集。 |

## 本增量不包含

- 不允许无来源、无评估、无回滚的技能自动上线。
- 不允许记忆投毒改变权限、审批策略或系统事实。
- 不用“模型觉得有用”替代可重复评估。
