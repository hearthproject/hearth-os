# D5.2 · 记忆冲突、遗忘与导出

<p class="lead">记忆变旧、冲突或需要删除时，系统必须能更新、传播遗忘并允许用户完整导出。</p>

## 这一增量解决什么

过期事实会被更新或遗忘；用户可以导出全部记忆，也可以确认遗忘已经传播到所有相关索引和设备。

Stage 5 先让记忆可纠正、可遗忘，再让技能可评估、可回滚；任何不能解释来源和权限的变化都不能进入生产。

## 开始前

- Stage 1–4 的任务、审批、验证、主动性和跨设备入口已经稳定。
- 已确定允许记忆的事实、偏好、经验和敏感信息边界。
- 每次技能变化都必须有对照评估、版本、权限交集和回滚路径。
- D5.1 的交付物已经验收；未通过时不进入本增量。

## 实施步骤

1. 实现冲突检测、更新时间与显式覆盖规则。
2. 实现删除/遗忘并行传播到索引、缓存和相关设备。
3. 提供完整记忆导出，包含来源、版本、时间与敏感标记。
4. 加入提示词注入与记忆投毒防护。
5. 建立遗忘审计和敏感记忆隔离。
6. 验证恶意内容不能通过记忆获得权限，用户能理解记忆为何变化。

## 数据与接口契约

| 检查点 | 必须满足 |
| --- | --- |
| 记忆来源 | 每条记忆记录来源、置信度、敏感度、时效、版本和召回原因。 |
| 遗忘传播 | 删除和遗忘必须产生 tombstone，并传播到索引、缓存和相关设备。 |
| 技能权限 | 候选技能只能继承或收窄现有权限，不能通过进化扩大授权。 |
| 评估可重复 | 评估集、基线、失败样本和运行配置可重复；优化不能只与旧版本比较。 |
| 晋升可回滚 | Shadow、Canary、Promote、Rollback 都有记录，出现回归可以恢复到上一版本。 |

## 交付物

- 冲突/覆盖规则
- 遗忘传播与审计
- 记忆导出包
- 投毒/注入测试

## 验证清单

- [ ] 遗忘可传播且可验证；导出包含来源和版本；冲突不会静默覆盖正确事实；恶意内容不能通过记忆获得权限；用户能理解记忆为何变化。
- [ ] 交付物已经和契约、任务卡投影保持一致，没有未登记的字段或状态。
- [ ] 至少一个失败路径有可操作恢复，关键动作留下审计事件。
- [ ] 演示不依赖手工修改数据库、只在终端拼接命令，或永久 mock。

## 失败与恢复

| 情况 | 用户看到 | 恢复动作 |
| --- | --- | --- |
| 错误记忆被召回 | 召回卡显示来源与原因，用户可以纠正或删除。 | 更新记忆、重建索引并记录纠正事件。 |
| 遗忘没有传播 | 页面显示“遗忘未完成”并阻止继续依赖。 | 重试索引清理、设备同步和缓存失效，确认后再标记完成。 |
| 候选技能权限扩大 | 评估标记权限越界并直接拒绝晋升。 | 收窄 manifest 权限或重新设计技能，保持权限交集。 |

## 本增量不包含

- 不允许无来源、无评估、无回滚的技能自动上线。
- 不允许记忆投毒改变权限、审批策略或系统事实。
- 不用“模型觉得有用”替代可重复评估。
