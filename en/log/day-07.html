Day07 · Goal evidence, delegation, and personal context

On this page

2026-11-10 moved Hearth from "tasks can run" toward "tasks have contracts, handoffs, context, and acceptance evidence". 56 commits touched 522 files (+20,709/−52,818): the first half added goal budgets, deadlines, stop conditions, command and Git validators, approval action binding, and reconciliation for uncertain effects; the second half added durable delegation, sandboxing, handoff evidence, channel idempotency, the personal ontology, Context Broker, standing intents, and connection runtime, then moved the evaluation corpus, apps, and scenario runner out of the main repository.

The large deletion count comes mainly from moving the evaluation stack and decoupling templates, not from removing product capability. The main repository keeps the evaluation bridge, task templates, product service, and operating evidence; evaluation cases, console, experiments, and scenario evidence now live in a standalone repository.

Goal and completion evidence ​

AreaResult
Budgets and stopGoal budgets cover turns, tool calls, tokens, duration, and human minutes; deadlines, stop conditions, and review policy enter scheduling, and exhaustion pauses, degrades, or hands work to a person
ValidatorsCompletion judgement adds command and Git validators alongside file, schema, human, and model review; commands run in a restricted environment and cannot expand authority
SchedulerThe scheduler injects custom validators when a task is ready to finish and persists the completion report; goal tasks cannot close without a verdict
Handoff evidenceTerminal evidence survives executor handoff, and late results from an old generation cannot overwrite new state
InterfaceTask detail shows criteria, completion verdict, evidence, and missing items instead of only an executor summary

Delegation, handoff, and sandboxing ​

AreaResult
Durable delegationA parent creates bounded child tasks with budget, workspace policy, parent-child relation, lease, heartbeat, and failure state; the scheduler advances them
Workspace policyRead-only, isolated-write, and shared-read policies bound what children can see and write
SandboxChecks working directory, read/write paths, network hosts, process allowlist, and credential boundaries; any violation fails closed with a reason
Handoff packetRecords goal, next action, acceptance criteria, evidence, permission subset, context watermark, generation, and redaction; work resumes only after verification
Channel idempotencyFeishu and other channel ingress events deduplicate by identity, so repeat delivery cannot create two tasks, approvals, or child tasks

Personal context and attention ​

AreaResult
Personal ontologyEntities, aliases, relations, states, decisions, and commitments become shared records; conflicting states are not silently overwritten but become attention items
Context BrokerAssembles context packs for chat, task, goal, handoff, and delegation scopes into must-know, relevant, recallable, and omitted lanes; references can expand only within parent authority
Memory governanceSource, confidence, taint, sensitivity, and validity affect recall; consolidation is auditable, and forgetting propagates to projections, versions, events, sync, and derived memory
Standing intentsLong-lived user rules become standing intents; a heartbeat turns intent and task state into candidates that explain why now, the next action, and the consequence of ignoring
Attention budgetDaily limit, quiet hours, per-kind cooldown, per-goal and high-priority limits, ignored penalty, and NO_REPLY feedback regulate interruption
Connection runtimeTransport, subscription, data freshness, and execution ownership are separate; reconnect advances generation, old-generation writes are rejected, offline actions enter an outbox, and cached projections never pretend to be live

Approvals, skills, and scheduling boundaries ​

AreaResult
Approval bindingNative patch, full-permission actions, GitHub writes, and SMTP sends bind the resolved real action; changed parameters, expiry, and reuse invalidate approval
Uncertain effectsExternal actions with uncertain delivery enter an explicit reconciliation queue where the user can confirm, retry, or abandon instead of blindly resending
Skill permissionsSkills are scoped by usage source, permission range, and risk; stale skills can be curated with rollback
Schedule catch-upScheduled tasks support bounded catch-up and failure cooldown so downtime or repeated failure cannot flood execution
TestsAdded regressions for goals, completion, delegation, handoff, sandbox, channels, connections, ontology, Context Broker, attention, and approval binding

Evaluation split and documentation ​

AreaResult
Standalone evaluationEvaluation web, service, core, cases, scenario runner, and docs moved to hearth-eval; the main repository keeps only task/judge bridge contracts and the managed artifact directory
Template decouplingProduct task templates no longer depend on the evaluation corpus; the product service owns its example inputs and output declarations
Artifact rootsTask artifacts land under the product artifact root, while evaluation inputs are authorized through an external root
Documentation factsREADME, delivery status, executor handoff, evaluation guide, and phase notes now describe the split; this page and Day06 are added

Boundaries and next step ​

  • Completion judgement covers commands, files, schema, Git, human, and model review, but subjective quality, real business impact, and real external receipts still need human acceptance.
  • Delegation is single-layer with no recursive agent team. The local sandbox checks paths, network, processes, and credentials; it is not a strong container or VM boundary.
  • The connection runtime has generations, an offline outbox, and cached projections, but no real remote node or phone, and no real offline-reconnect or cross-node reconciliation acceptance.
  • The personal ontology and Context Broker still rely mainly on local heuristic matching and ranking. Real long-term personal data, phone push, remote takeover, and cross-device context consistency remain unaccepted.
  • The evaluation stack is standalone, but this documentation update did not produce real experiments or pass rates in hearth-eval; main-repository tests do not replace independent evaluation.
  • npm test on the same day: 89 test files and 579 tests passed; npm run typecheck, npm run build, and npm run docs:build passed. Passing tests are not real-user, real-device, or long-running acceptance.
