EXECUTOR CATALOG

执行器目录 ​

Codex、Native、Connector、Browser、GUI 和 Document/Data 各自擅长什么、何时被选择、如何验证与接管。

Codex Executor ​

定位 ​

Codex 不局限于代码，可承担调研、长文档、报告、表格、代码和多文件工作区任务；但它是执行器，不是 Hearth 的权限中心、任务数据库、记忆中心或外部副作用网关。

适合：

  • 隔离 workspace 中的长链路推理；
  • 代码修改、测试、Issue 分流、PR 准备；
  • 调研、归纳和结构化研究；
  • 文档、报告、表格和数据文件生成/修改；
  • 多步骤 Shell、文件转换和验证。

不适合：

  • 直接管理邮箱、日历和通讯录；
  • 作为长期记忆；
  • 作为权限、审批或凭据中心；
  • 常驻监听事件；
  • 实时桌面和手机操作；
  • 直接发送和发布高风险副作用。

Task Pack 与输出契约 ​

不要给 Codex 一段无边界长提示词。输入应是 Task Pack：

  • 目标、验收标准和禁止事项；
  • 最小必要文件、引用和产物路径；
  • 工作区范围、可写目录和网络边界；
  • 可用工具、预算、截止时间和取消语义；
  • 需要的结构化输出 schema；
  • 已知失败样本和降级方式。

输出至少包括：标准化事件流、产物引用、结构化最终结果、验证结果、失败分类和可恢复性。自然语言“完成”不算完成。

隔离、取消与恢复 ​

  • 一个 Run 一个 workspace，任务结束回收；
  • 版本锁定 CLI/SDK，升级先跑契约测试；
  • 最小环境变量和网络出口；
  • 取消要终止整个进程树；
  • 超时、崩溃和恢复要保留检查点或可重建工作区；
  • 高风险账户和长期凭据不直接交给 Codex。

验收 ​

  • 任务包可复现；
  • 结构化结果可解析；
  • 产物有 diff、测试、引用或文件证据；
  • 取消、超时和失败分类可用；
  • Token 和成本可归因；
  • 不依赖自然语言“完成”。

Native Runtime ​

Native 是轻量、本地、可替换的通用推理层，适合短任务、低风险分类、上下文压缩和一些隐私敏感工作。它不追求替代 Codex 的长链路能力。

模型阶梯 ​

  • 规则/脚本：完全不用模型；
  • 小模型/本地模型：分类、抽取、短摘要；
  • 中型模型：一般推理、结构化整理；
  • Codex/大模型：长链路、多文件、高价值任务。

工具接口与升级 ​

Native 只通过受控工具接口读写文件、执行命令和调用 Connector。出现以下情况应升级到 Codex：

  • 任务需要大量文件协同；
  • 需要长链路规划和反复验证；
  • Native 多次失败或上下文超预算；
  • 产物质量或可靠性不达标；
  • 需要更强的代码/文档处理能力。

评估 ​

评估不要只看“回答是否像样”，还要看任务成功率、人工分钟、Token、工具调用正确率、失败分类和升级率。小模型“省钱但反复失败”通常更贵。

Connector Executor ​

Connector 把外部系统变成可审计的 Source 与 Effect，不是“把 API 钥匙交给模型”。

统一模型 ​

  • Source：读取、同步、归一化、来源、游标、限流；
  • Effect：类型化动作、预览、审批、outbox、幂等键、Receipt、对账；
  • 凭据：Credential Broker 发放短期权限，执行器看不到长期密钥；
  • 权限：按账户、资源、动作、时间和范围限定；
  • 失败：可重试、不可重试、不确定、需人工接管分开处理。

邮件、日历、文档、IM ​

  • 邮件：只读同步、线程、联系人、附件、草稿、待审批发送；
  • 日历：只读、时区、冲突检查、待审批写入；
  • 文档/云盘：读取、版本、导出、待审批分享；
  • IM/Issue/代码托管：消息、Issue、PR、评论等 Source/Effect，高风险动作审批。

Stage 2 先接一个真实只读 Connector，再逐步增加写入。不要在第一个 Connector 上同时打开所有高风险动作。

限流、重试与对账 ​

  • 每次投递有幂等键；
  • 限流和退避由系统控制，不交给模型自由重试；
  • 不确定结果先查询/对账；
  • 死信可查看、修复和人工重放；
  • 撤销和权限回收要有审计。

Browser Executor ​

Browser 用 Playwright 操作没有 API 或 API 不足的网页，但网页内容是不可信输入。

三种模式 ​

  1. 只读研究：打开、登录态受限、抓取、截图、来源；
  2. 草稿操作：填表、准备提交但不自动发送；
  3. 受控执行：在 Mandate 和审批下提交低/中风险动作。

执行流程 ​

  • 明确目标和允许域名；
  • 准备隔离 profile；
  • 观察页面和来源；
  • 非高风险步骤自动执行；
  • 遇到验证码、异常或高风险提交时接管；
  • 保存截图、DOM/状态证据和来源；
  • 验证最终状态，产生 Receipt（如有副作用）。

安全 ​

  • 页面文本不能当作系统指令；
  • 提示词注入不能扩大权限；
  • 登录态与长期凭据隔离；
  • 网络出口白名单；
  • 下载文件要验证类型和来源；
  • 不可信页面不能直接触发付款、发布、删除或权限变更。

失败与接管 ​

浏览器失败通常不是“再试一次”能解决。验证码、MFA、页面结构变化、登录过期和不可逆提交必须明确进入 needs_human，并展示用户需要做什么。

GUI Executor ​

GUI 操作没有 API 的桌面软件和跨应用流程。它比 Browser 更脆弱，因此更依赖白名单、验证和接管。

运行位置 ​

  • 设备 agentd 在目标桌面运行；
  • 使用可访问性树、截图、键鼠、窗口和文件选择；
  • 高风险任务在隔离虚拟桌面运行；
  • 手机只是查看/接管入口，不是默认执行权威。

执行流程 ​

  1. 识别目标应用和窗口；
  2. 确认能力和权限；
  3. 观察当前状态；
  4. 执行最小动作；
  5. 通过可访问性树、截图或目标状态验证；
  6. 失败则暂停、接管或回滚；
  7. 记录审计和证据。

边界 ​

  • 应用/窗口白名单；
  • 不读取密码库；
  • 不修改系统安全设置；
  • 高风险动作二次确认；
  • 不假设屏幕坐标永远稳定；
  • 每次操作后验证状态，不只看“点击成功”。

失败与接管 ​

GUI 必须假定会失败。用户要能暂停自动输入、接管、操作、交还或终止；系统要记录接管前后状态，避免自动流程和人工同时争抢键鼠。

Document/Data Executor ​

Document/Data 让确定性工作不经过模型：解析、OCR、格式转换、表格清洗、对账、统计、图表和导入导出。

管道 ​

text
输入文件 → 类型识别 → 解析/OCR → 结构化中间结果
→ 确定性转换/计算 → 验证 → Artifact + 来源

模型只处理真正需要语义判断的部分；重复计算、格式转换和数据校验不调用模型。

验证 ​

  • 文档结构、页码、引用和关键字段；
  • 表格 schema、行数、公式、抽样和对账；
  • 输出可复现、可 diff、可回溯原文件；
  • 大文件只提取所需片段和 artifact 引用；
  • 原文件不被破坏，失败可回退。

与 Codex 的分工 ​

  • 确定性处理：Document/Data；
  • 需要长文档理解、写作、复杂格式和多文件协调：Codex；
  • 判断哪个更便宜、更可靠由路由决定，不按工具偏好。
