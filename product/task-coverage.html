任务覆盖与完成定义 ​

Hearth 不追求“什么都能做”，而是用明确的八类任务、自主级别和验证器定义什么值得做、什么时候可以自动做、什么才算完成。

八类任务覆盖 ​

任务族典型工作首选执行方式
沟通与协作邮件、IM、会议纪要、跟进、日程协调Connector + Native/Codex + 审批
文档与内容docx、xlsx、pptx、PDF、Markdown、报告、翻译、改写Document/Data Engine、Native、Codex
研究与信息整理搜索、阅读、对比、引用、摘要、资料库Native + Browser + Codex
代码与研发仓库修改、测试、Issue、PR、代码审查Codex + 测试/CI 工具
数据与表格清洗、对账、统计、图表、导入导出Document/Data Engine + Python sidecar
网页与 SaaS登录、表单、下载、上传、后台操作Browser Executor
桌面应用没有 API 的软件、系统设置、跨应用流程GUI Executor
个人事务表单、预约、账单、提醒、设备操作Connector、Browser、GUI，高风险审批

一个任务可由多个执行器协作；“调研竞品并写进周报”可能同时使用 Browser、Native、Document Engine 和 Codex。

自主级别 ​

级别行为默认使用
A0 建议只生成建议、草稿或计划新场景、高风险、未验证能力
A1 受控执行自动完成低风险步骤，中风险首次审批Stage 1–2 默认
A2 授权执行在 Mandate 内自动完成已授权动作，高风险仍需审批Stage 4 以后
A3 受监督自主长周期运行，但保留审批、预算、kill switch 和回执长期目标

自主性必须按任务族、来源、时间段、设备、风险和金额独立配置，不能用一个“全自动开关”覆盖所有场景。

“完成”的定义 ​

自然语言“已完成”不是完成证据。不同任务需要不同验证器：

任务完成证据
代码/Issue/PR测试、类型检查、diff、CI 或人工审查
文档结构检查、引用检查、格式检查、用户验收
邮件草稿收件人、事实、语气检查；发送前审批
邮件发送Approval、Broker 执行记录、provider message id 或明确的不确定状态
网页操作DOM/可访问性状态、截图、最终状态和回执
桌面操作可访问性树、截图、目标状态和人工确认
研究来源可追溯，关键断言有引用
日程时间、时区、参与者、冲突检查和日历回执
数据schema、行数、抽样、对账和可复现脚本
