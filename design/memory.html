记忆与能力进化 ​

记忆不是聊天记录，也不是越多越好。它是一层受约束的判断缓存，帮助系统减少重复询问；能力进化则是在真实轨迹和评估之上形成可复用方法，而不是让 Agent 自己修改权限和安全边界。

设计目标 ​

系统要记住用户反复提供的背景、偏好、项目事实、过去任务的经验，以及已经验证过的工作方法。召回记忆时，要能说明它来自哪里、有多可信、适用于哪个范围、是否过期，以及为什么这次被使用。

记忆必须可纠正、可遗忘。用户可以查看系统记住了什么，修改错误内容，限制敏感信息的用途，并确认删除已经传播到索引、缓存、设备副本和派生摘要，而不是只删掉原页面。

能力进化要从成功、失败、人工纠偏、接管和成本数据中形成候选方法。候选方法可以是一段提示、一个固定流程、一条文档处理管道、一个连接器配方或一组验证步骤，但只有经过回放、无副作用试运行、小范围真实使用和用户审阅后，才能成为默认能力。

记忆和能力都不能成为事实源。任务状态、审批、产物和回执来自记录；记忆只提供背景和方法，技能只能申请原有任务已经拥有的权限，不能自行创建新凭据、后台任务或更大的授权范围。

设计取舍 ​

Hearth 把记忆分成五类，分别控制生命周期和用途。这样既能减少上下文重复，又不会把所有内容混成一团无法解释的长期状态。

记忆类型保存什么生命周期与用途
工作记忆当前目标、约束、临时观察和中间结果任务结束清理，只服务当前执行
经历记忆过去任务的经过、结果、失败和人工纠偏中期保存，可摘要，用于相似任务参考
事实记忆人物、项目、组织和稳定关系长期保存，必须有来源、有效期和敏感度
用户模型偏好、沟通风格、习惯和价值边界长期保存，高度可编辑，减少重复说明
方法记忆已验证的流程、工具配方和验证方式版本化保存，用于重复任务和能力进化

记忆写入先进入候选状态，检查来源、敏感度、重复、冲突和用户授权。网页、邮件、文档和工具输出都可能包含误导内容，不能因为出现一次就自动成为高可信事实；高敏感信息默认不自动写入。

检索按任务需要、适用范围、来源可信度、时效、敏感度和上下文预算筛选。系统不会把全部记忆塞进一次任务，也不会让不同账户或项目互相污染。新事实不能静默覆盖旧事实，冲突时保留来源并请求确认；低置信度记忆不能单独触发高风险动作。

遗忘要传播到缓存和派生摘要。缓存必须有版本、失效和删除规则，不能把已经遗忘的内容重新召回；多设备同步要携带版本和删除标记，防止旧设备把已删除记忆复活。

方法进化的流程是：收集轨迹、聚类重复和失败、生成候选说明、做权限审计、离线回放、无副作用试运行、小范围真实使用，最后决定晋升、拒绝或回退。晋升需要证明真实任务成功率不下降、没有越权、没有扩大权限，成本或人工时间有明确改善，并且失败可解释、可恢复。

系统可以提出新方法，但不能修改自己的授权规则、审批门槛、核心安全边界和事件格式。任何权限变化都必须由用户明确批准；核心代码变化走人工审查。一次演示成功、模型自称更好或只降低 Token 而没有降低人工时间，都不能作为晋升依据。
